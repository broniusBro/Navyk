# Регистрация, вход и личный кабинет: разбор Navyk и решения для brolingvo

2026-11-04 · основано на коде `web/js/ui/auth.js`, `web/js/ui/account.js`, `web/js/ui/profile.js`,
`server/src/auth/routes.ts`, `sessions.ts`, `password.ts`, `google.ts` и строках `web/i18n/ru.json → auth.*`.
Визуальный стиль экранов — `docs/design/direction.md`; макет регистрации — `docs/design/preview.html?s=auth`.

## 1. Что есть сейчас (наследие Navyk)

### Карта экранов

| Маршрут | Экран | Содержимое |
|---|---|---|
| (лист) | **Ворота** `openSignupSheet` | При тапе на урок вне `free_preview`: «Сохрани прогресс и открой весь курс», 3 преимущества, «Создать аккаунт» / «У меня уже есть аккаунт», «Бесплатно. Нужна только почта». Запоминает урок (`afterAuth`) |
| `#/register` | Регистрация | Google (если настроен) → «или» → почта, пароль (живой индикатор длины), согласие с условиями + раскрывашка «Что мы храним?», «Создать аккаунт» |
| `#/check-email` | Проверь почту | Адрес, 3 шага (открой / нажми / проверь «Спам»), «Отправить ещё раз», «Ошибка в адресе? Ввести другой», «Вернуться ко входу» |
| `#/confirm/<t>` | Подтверждение | «Секунду, проверяем ссылку…» → «Почта подтверждена!» + конфетти + «К пути» / «Ссылка не сработала» + форма повторной отправки |
| `#/login` | Вход | Google → почта (подставлена из прошлой попытки), пароль с «глазом», «Забыли пароль?», «Нет аккаунта? Зарегистрироваться» |
| `#/forgot` | Восстановление | Почта → «Письмо в пути» (одинаковый ответ, есть аккаунт или нет) |
| `#/reset/<t>` | Новый пароль | Пароль + повтор → «Сохранить и войти» (сразу вход, все старые сессии гасятся) |
| (лист) | **Аккаунт** из аватара | Почта, «Прогресс сохраняется…», «Выйти» |

### Серверные правила, которые влияют на UX

- Сессия — HttpOnly-cookie, скользящие 30 дней. Вход без подтверждения почты невозможен (403 `email_not_confirmed`).
- Пароль ≥ 8 символов, не из списка частых, не равен почте; без требований к цифрам/символам — это хорошо.
- 5 неудачных входов → блокировка 15 минут (и для несуществующих адресов — нет перебора аккаунтов).
- Письма: ≤ 3 в час на адрес; регистрация на уже существующий адрес молча шлёт письмо «вы уже зарегистрированы» со ссылкой сброса.
- Ссылка подтверждения живёт 24 ч, сброса — 1 ч.
- Google: вход создаёт аккаунт или привязывается к существующему по почте; неподтверждённый чужой пароль при этом обнуляется.
- Анонимный прогресс (localStorage) при первом входе сливается с аккаунтом; при выходе устройство очищается.
- В brolingvo backend уже добавляет `PATCH /api/auth/me {name}` и `DELETE /api/auth/me` (пароль или `confirm:"DELETE"` для Google-аккаунтов).

## 2. Что хорошо (оставляем)

1. **Нет перечисления аккаунтов** — одинаковые ответы на регистрацию/«забыл»/повтор. Безопасно и честно.
2. **Мягкие ворота вместо стены**: регистрация предлагается в момент ценности (хочу следующий урок), а не на входе.
   Урок запоминается и открывается сразу после входа (`afterAuth`) — нет «потерянного контекста».
3. **Пароль без мучений**: одно поле, «глаз», живая подсказка длины, никаких «заглавная+цифра+символ», нет повтора при регистрации.
4. **Понятные ошибки на человеческом языке**, у поля, с иконкой; `aria-invalid`, фокус на первое ошибочное поле.
5. **Письмо-инструкция** со «Спамом» и повторной отправкой; почта подставляется на всех экранах.
6. **Сброс пароля сразу входит** и подтверждает почту — меньше шагов.
7. **Слияние анонимного прогресса** — ничего не теряется.
8. Google-вход появляется только если настроен (нет мёртвых кнопок).

## 3. Что мешает (трение и риски)

| # | Проблема | Где | Почему плохо |
|---|---|---|---|
| P1 | **Подтверждение почты блокирует сразу всё.** Зарегистрировался → «проверь почту» → без клика по ссылке не войти, курс закрыт. | `login` 403, `register` → `#/check-email` | Самая большая утечка воронки: человек в метро, почта на другом устройстве, письмо в «Промоакциях». | P2 | Ворота открываются по тапу на **каждый** закрытый урок, а в brolingvo по правилу — «после первого модуля». Нет момента-праздника. | `openSignupSheet` | Ощущается как пейволл. Лучше предложить на пике: «Модуль 1 пройден! Сохрани прогресс». |
| P3 | Тексты завязаны на Navyk: «Открой письмо от Navyk», «Navyk — независимый проект, не связан с Anthropic», «К пути». | `ru.json → auth.*` | Неверный бренд, непонятные русскоязычному ученику польского отсылки. |
| P4 | «Создать аккаунт» — общая формулировка; ворота говорят «весь курс», но курс бесплатный — человек может решить, что дальше платно. | `gate_*`, `register_*` | Нужно явно: «бесплатно навсегда», «займёт 20 секунд». |
| P5 | Нет имени. Профиль показывает часть почты как имя. | `profile.js` | Обезличенно; ИИ-собеседнику и Pani Ani нечем обращаться. |

| P7 | Удаление аккаунта: нет в Navyk; в brolingvo — лист с паролем. Для Google-аккаунта без пароля — подсказка текстом. | `confirmDelete` | Нужен явный список «что удалится», кнопка-«опасность», задержка/подтверждение; после — понятный экран прощания. |
| P8 | Нет смены пароля и почты из кабинета (только через «Забыли пароль?»). | — | Обходной путь работает, но неочевиден. |
| P9 | Блокировка 15 мин после 5 ошибок показывает время, но не предлагает «Сбросить пароль» прямо в сообщении. | `login` 429 | Человек, забывший пароль, упирается в стену. |
| P10 | Гость в профиле видит пустые цифры и одну CTA; непонятно, что он теряет. | `profile.js` guest | Нет «твой прогресс только на этом устройстве». |
| P11 | Ошибка Google (`?e=google`) — общий текст, без причины и без кнопки «Войти по почте». | `renderLogin` | Тупик. |
| P12 | Экран «Проверь почту» не предлагает **«Открыть почту»** (Gmail/Mail/Outlook deep-link) и не показывает таймер повторной отправки. | `renderCheckEmail` | Лишние действия на телефоне; повторные нажатия упираются в лимит 3/ч молча (429 → «Что-то пошло не так»). |
| P13 | Лист «Аккаунт» из аватара дублирует профиль. | `openAccountSheet` | В brolingvo аватар → вкладка «Профиль». |
| P14 | Согласие «Нажимая… ты принимаешь…» — нормально юридически, но две ссылки + раскрывашка — визуальный шум. | `consent` | Свернуть до одной строки мелким текстом под кнопкой. |

## 4. Рекомендации для brolingvo — по экранам

Принцип: **регистрация — это «сохранить», а не «войти»**. Приложение полностью работает без аккаунта до конца
модуля 1; аккаунт бесплатный, нужен ради сохранения прогресса и открытия курса дальше. Личный кабинет = вкладка «Профиль».

### 4.1 Онбординг (`#/welcome`)
- 5 шагов: привет (Pani Ania) → цель → уровень → минут в день → «готово».
- Последний шаг: главная кнопка **«Начать первый урок»**, вторичная — «Создать аккаунт» (не навязывать).
  Ссылка «У меня уже есть аккаунт» только на первом шаге (сделано).
- Ответы онбординга хранить локально и отправлять в аккаунт при регистрации (цель и минуты → профиль).

### 4.2 Мягкие ворота (новый момент)
- Показывать лист **после завершения последнего урока модуля 1**, на экране «Урок пройден», а не по тапу.
  Заголовок: «Модуль пройден! Сохраним твой прогресс?» Тело: «Ты выучил(а) 24 слова и 3 дня подряд занимаешься.
  Аккаунт бесплатный — он сохранит всё и откроет следующие модули».
- Перки (галочки): «Бесплатно навсегда, без подписок», «Прогресс на телефоне и компьютере», «Pani Ania запомнит твои ошибки».
- Кнопки: **Google** (первой, если есть) → «Через почту» → текстовая «Позже».
- По тапу на закрытый урок — тот же лист, но с заголовком «Этот урок — после регистрации».
- «Позже» не наказывать: модуль 1 и вкладки «Словарь»/«Разговор» (в пределах лимита ИИ) остаются доступны.

### 4.3 Регистрация (`#/register`)
- Заголовок «Сохрани прогресс», лид «Бесплатно. 20 секунд».
- Поля: **Имя** (необязательное, «Как к тебе обращаться?» — для ИИ), почта, пароль. Без повтора пароля.
- Согласие — одной строкой мелким шрифтом под кнопкой; «Что мы храним?» оставить раскрывашкой.
- **Снять блокировку по подтверждению почты (P1)**: после регистрации сразу входить и сохранять прогресс;
  подтверждение почты требовать только для восстановления пароля и смены почты, а в профиле показывать
  мягкий баннер «Подтверди почту, чтобы не потерять доступ» с кнопкой «Отправить письмо». *Требует изменения
  сервера (сейчас `login` 403 и сессия выдаётся только в `confirm`) — задача backend-dev.* Если оставляем
  подтверждение обязательным — хотя бы не выбрасывать пользователя: прогресс продолжает копиться локально,
  а экран «Проверь почту» имеет кнопку «Продолжить учиться», и после клика по ссылке всё сольётся.

### 4.4 «Проверь почту» (`#/check-email`)
- Кнопка **«Открыть почту»**: по домену адреса — `googlemail://`/`https://mail.google.com`, `message://`, Outlook, mail.ru, yandex.
- Повторная отправка с таймером «Отправить ещё раз через 0:45»; при 429 — «Мы уже отправили 3 письма за час.
  Попробуй позже или войди через Google».
- Тексты: «Открой письмо от brolingvo», «Не пришло? Проверь «Спам» и «Промоакции»».
- Вторичная: «Продолжить урок» (см. 4.3).

### 4.5 Вход (`#/login`)
- Google первым, затем почта/пароль. Почта предзаполнена.
- При `locked`: «Слишком много попыток. Попробуй через 14 минут **или сбрось пароль**» — со ссылкой (P9).
- При `email_not_confirmed`: сразу кнопка «Отправить письмо ещё раз» (сделано) + «Открыть почту».
- Ошибка Google (P11): «Google не ответил. Попробуй ещё раз или войди по почте» + кнопка «Повторить с Google».

### 4.6 Восстановление и новый пароль (`#/forgot`, `#/reset/<t>`)
- Хорошо как есть. Добавить «Открыть почту» и таймер повторной отправки, как в 4.4.
- В письме и на экране указать срок ссылки: «действует 1 час».
- На `#/reset` убрать поле «Повтори пароль», если есть «глаз» (меньше ошибок на телефоне) — либо оставить, но показывать совпадение живой галочкой.

### 4.7 Профиль = личный кабинет (`#/me`)
Порядок секций (реализовано в `profile.js`, стили в `app.css`):
1. **Шапка**: аватар-инициал (градиент кармин→янтарь), имя (редактируется карандашом), почта.
   Гость: иконка, «Гость», «Прогресс хранится только на этом телефоне».
2. **Гостевой баннер** (`.save-banner--profile`): «Создать аккаунт» (primary) + «Войти».
3. **Статистика** (`.stat-grid`): серия, XP, уроки, слова — со счётчиком `countUp`.
4. **Неделя** (`.week-chart`): 7 столбиков, сегодня — кармином.
5. **Цель дня** (`.segmented`): 5/10/15/20 минут.
6. **Настройки** (`.settings-list`): скорость озвучки (обычно/🐢 медленно), автоозвучка ответов ИИ (`.switch`),
   **голос** (женский/мужской — когда появятся голоса), тема (авто/светлая/тёмная), **язык интерфейса**
   (русский/українська — когда будет uk), «Пройти онбординг заново».
7. **Аккаунт** (`.card--account`): «Прогресс сохранён в облаке» (+ дата последней синхронизации), «Сменить пароль»
   (ведёт на `#/forgot` с подставленной почтой — честно назвать «пришлём ссылку»), **«Выйти»**, «Удалить аккаунт».
8. Ссылки на политику, условия, cookies.

**Выход (P6)**: подтверждение в листе: «Выйти? Прогресс сохранён в аккаунте. На этом устройстве он будет
очищен — войди снова, и всё вернётся». Кнопки «Выйти» / «Отмена».

**Удаление аккаунта (P7)** — лист `.sheet--danger`:
- Заголовок «Удалить аккаунт навсегда?»; список «Удалится: прогресс, серия, слова, история разговоров с ИИ, почта».
- Пароль (или для Google — кнопка «Подтвердить через Google»/ввод слова «УДАЛИТЬ»).
- Кнопка `.btn--danger` «Удалить навсегда» активна только после ввода; после — экран «Аккаунт удалён. Do zobaczenia!»
  с кнопкой «Начать заново». При ошибке `last_owner` (админ) — понятный текст.
- Предложить альтернативу над кнопкой: «Хочешь просто передохнуть? Выключи напоминания».

### 4.8 Что видит гость
- Весь модуль 1 A1, словарь пройденных слов, вкладка «Разговор» (ИИ — в пределах `IP_AI_PER_DAY`).
- Закрытые уроки — с маленьким значком пользователя (`.node__badge`) и подписью «Нужен аккаунт», без замков-стен.
- Баннер на главной после первого урока (`.save-banner`): «Прогресс хранится только на этом телефоне» → «Сохранить».
- Профиль с реальной статистикой (из localStorage) — чтобы было что «терять» и ради чего регистрироваться.
