# ADR 0001. Сначала веб, затем мобильные приложения из одной кодовой базы

Статус: принято (платформа); стек — предложен, утвердить после исследования
Дата: 2026-10-13

## Контекст
Navyk нужно быстро показать первым пользователям и часто обновлять уроки.
Мобильные приложения нужны позже, и переписывать продукт с нуля мы не хотим.

## Решение
1. Первая версия — веб-приложение с мобильной вёрсткой и установкой как PWA (иконка на главном экране).
2. Мобильные приложения iOS и Android собираются из того же кода, а не пишутся заново.

## Варианты стека

| | A. Expo (React Native + web) | B. Next.js + Capacitor |
|---|---|---|
| Веб сейчас | Да, `expo export --platform web` | Да, лучший веб и SEO |
| Мобильное потом | Нативные экраны, один код | Веб внутри нативной оболочки |
| Ощущение в приложении | Ближе к нативному (анимации, жесты) | Как сайт, хуже анимации |
| SEO лендинга | Слабее → лендинг отдельно | Сильный |
| Сложность старта | Средняя | Низкая |

Предложение: **A. Expo + Expo Router + TypeScript** для приложения и отдельная статическая
посадочная страница для SEO. Механики Kodree/EWA (анимации, жесты, плавность) лучше
ощущаются в нативных экранах, а вариант A даёт их без переписывания.

## Последствия
- Оплата в вебе — Stripe/Paddle; в мобильных — встроенные покупки сторов (через RevenueCat), учёт подписки на бэкенде единый.
- Бэкенд и контент не зависят от клиента: один API для веба и мобильного.
- Код не должен опираться на браузерные API без абстракции (хранилище, уведомления, звук).
