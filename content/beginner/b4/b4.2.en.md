::: step hook
Olivia is a freelance designer in Lisbon. She created a “Clients” project and uploaded everything into it: her price list, her contract, 40 old mock-ups, draft emails and last year's price list.

```prompt
How much do I charge for a logo design?
```

```claude
According to the price list, €250. But another file says €200. Which one is current?
```

Where did Olivia go wrong?
:::

::: step explain
*Project knowledge* ({{data.ui_paths.project_knowledge}}) is the set of files Claude takes into account in every chat in the project. You add them with the “+” button on the right of the project page.

The rule for choosing is simple: add what's needed in almost every conversation. Like a student's backpack: you take the course textbook to every class, but leave last year's notes at home.
:::

::: exercise multi_choice
id: "b4.2.e1"
type: "multi_choice"
question: "Olivia is tidying up. Which files should stay in the project knowledge of her “Clients” project? Select all that apply."
options:
  - text: "The current price list for 2026"
    correct: true
    why: "Prices come up in almost every conversation with a client. This is the top candidate for the project knowledge."
  - text: "Contract template and payment terms"
    correct: true
    why: "Deadlines, deposits, revisions: clients ask about these all the time. Let Claude rely on her real terms, not generic advice."
  - text: "A short “About me” file: services, working style, turnaround times"
    correct: true
    why: "A file like this gives Claude context about her business. Replies will sound like Olivia, not some generic designer."
  - text: "Last year's price list"
    correct: false
    why: "That's exactly where the second price at the start of the lesson came from. Outdated versions confuse Claude: it can't tell which file is the main one. Better to delete the old one."
  - text: "40 old mock-ups for various clients"
    correct: false
    why: "They're not needed in every chat. Plus, Claude only extracts text from project files, and images have almost none. She can attach the right mock-up directly to a chat when she needs it."
hint: "For each file, ask yourself: will it be needed in almost every conversation with a client? And is there a newer version of it?"
:::

::: step explain
Why does it matter not to overload a project? Claude reads the knowledge through its *context window*: the amount of text it can keep in mind at once. Think of a desk: it holds a lot of paper, but not an unlimited amount.

For projects: up to {{data.limits.project_file_size_max}} per file and no limit on the number of files, but everything together has to fit in the context window.
:::

::: step explain
What if the knowledge grows really large? On paid plans ({{data.plans.rag_plans}}), Claude automatically switches on *RAG*: instead of keeping everything in mind, it searches the files for just the relevant pieces. Like a librarian who doesn't read the whole library but brings you the books you need.

The project's capacity grows up to {{data.limits.rag_capacity_multiplier}}. You don't need to switch anything on.
:::

::: step explain
To help Claude find what it needs faster, Claude's help centre recommends:

- giving files clear names: “Price_list_2026.pdf”, not “scan_17.pdf”;
- naming the document in your question: “according to the file Delivery_policy…”.

It's the same principle of *context*: the more clearly you show where to look, the more accurate the answer.
:::

::: step summary
**Only put what's needed in almost every chat into the project knowledge. Delete old versions, and attach one-off files to a message.**

Clear file names and naming the document in your question help Claude find what it needs.
