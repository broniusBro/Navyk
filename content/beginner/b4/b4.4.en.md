::: step hook
Module checkpoint! You already know the three parts of a project:

- *knowledge*: what Claude needs to know;
- *instructions*: how it should work;
- *chats*: specific tasks.

Today we'll put a whole project together using Diana as an example. She's a freelance copywriter in Vilnius with five regular clients, and every time she has to explain to Claude all over again who's who.
:::

::: exercise match_pairs
id: "b4.4.e1"
type: "match_pairs"
question: "Sort Diana's materials: where does each one go?"
pairs:
  - left: "A client table: what each client does, the tone they like, payment terms"
    right: "Into the project knowledge"
    why: "This is reference material needed in almost every chat. A file in the project knowledge saves Diana from explaining who's who."
  - left: "“Write in my name, casual with clients I'm on first-name terms with; emails under 120 words”"
    right: "Into the project instructions"
    why: "These are working rules: whose name, what tone, what length. They belong in the instructions."
  - left: "Today's email from a client asking to move a deadline"
    right: "As a message in a new project chat"
    why: "A one-off task. You write it in a chat, and Claude replies drawing on the project knowledge and instructions."
  - left: "The name “Clients 2026” and a description for herself"
    right: "When creating the project, for herself"
    why: "Claude can't see the project's name and description. It's a label so Diana can find the project in the list quickly."
hint: "Go through three questions: what Claude always needs to know, how it should work, and what needs doing right now. What's left is just for you."
:::

::: exercise order_steps
id: "b4.4.e2"
type: "order_steps"
question: "In what order is it easiest for Diana to set up the project?"
shuffle: true
items:
  - text: "Decide which recurring task the project is for"
    why: "Goal first. A project “for everything” quickly turns into a dumping ground, while a “Client emails” project is clear and useful."
  - text: "Create the project and give it a clear name"
    why: "Projects → + New Project. The name is for Diana so she doesn't get mixed up; Claude can't see it."
  - text: "Add the files needed in almost every chat to the project knowledge"
    why: "The client table, price list, rules for handling revisions. Old versions and one-off files don't go here."
  - text: "Write the instructions: role, context with a reason, tone, format"
    why: "Once the files are in place, it's easier to describe how to use them: for example, “take prices only from the price list”."
  - text: "Start a chat inside the project and check the answer on a real task"
    why: "The first real prompt will show what's missing. If the answer isn't right, fix the instructions or knowledge, not every chat."
hint: "From general to specific: first the why, then the box, then what goes in it, then the rules, and finally a real-world test."
:::

::: exercise single_choice
id: "b4.4.e3"
type: "single_choice"
question: "Diana has been using the project for a month. Claude keeps writing emails to clients that are too long. What's the best fix?"
options:
  - text: "Add the exact format and the reason to the project instructions, once: “under 120 words, clients read on their phones”"
    correct: true
    why: "Yes. Instructions apply in every chat in the project, so one edit fixes all future emails. And the reason helps Claude stay brief in new situations too."
  - text: "Write “shorter, please” in every new chat"
    correct: false
    why: "It'll work, but she'll have to repeat it forever. Saving you from that kind of repetition is exactly what a project is for."
  - text: "Delete the project and create a new one with the same content"
    correct: false
    why: "A new project with the same instructions will produce the same long emails. The problem isn't the project, it's the rules inside it."
  - text: "Upload an article called “How to write short emails” to the project knowledge"
    correct: false
    why: "Knowledge is “what to know”, while a length rule is “how to work”. One short, clear line in the instructions is more reliable than a whole article."
hint: "Which part of a project applies to every chat at once and covers “how to work”?"
:::

::: exercise find_error
id: "b4.4.e4"
type: "find_error"
question: "Here's Diana's draft instructions. Tap every spot that wouldn't pass the colleague test."
prompt: "You're my assistant for emailing clients. Write the usual way. Use the data from that table. Emails under 120 words, signed “Diana” at the end."
segments:
  - text: "You're my assistant for emailing clients. "
    weak: false
    why: "A clear role: Claude knows what it's doing in this project."
  - text: "Write the usual way. "
    weak: true
    why: "Only Diana knows what “the usual way” is. A new assistant would ask: “Meaning what?” Better to describe the tone: “friendly and to the point, no corporate jargon”."
  - text: "Use the data from that table. "
    weak: true
    why: "“That table” is unclear. Better to name the file and say what it's for: “take each client's tone and deadlines from the file Clients_2026”."
  - text: "Emails under 120 words, signed “Diana” at the end."
    weak: false
    why: "A specific format: length and sign-off. Claude won't have to guess."
hint: "Read each sentence as someone meeting Diana for the first time. At which words would they ask “Which one? What kind?”"
:::

::: step explain
The final task of the module. Pick a real recurring task of your own: studying, work, a hobby, family matters.

Describe the project in three parts: **name**, **files for the knowledge** (2–4 of them) and **instructions**. For now, just list the files in words.

Navyk will send your plan to Claude for feedback.
:::

::: exercise write_prompt
id: "b4.4.e5"
type: "write_prompt"
question: "Plan a project for your own task. Write: 1) a name; 2) which files you'll put in the project knowledge and why; 3) project instructions with a role, context and reason, tone and format. Don't include other people's personal data."
placeholder: "Name: …\nFiles: …\nInstructions: You're…"
ideas:
  - "Revising for an exam from your notes"
  - "Replying to freelance clients"
  - "Family budget and shopping"
  - "Learning a language for work"
  - "Posts for your hobby page"
min_chars: 120
hint: "First ask yourself: what do I keep explaining to Claude over and over? That's your material for the knowledge and the instructions. For the instructions, go through the four parts from lesson b4.3."
review:
  task: "Checkpoint for the “Projects” module. The learner is planning a project for their own task: a name, a list of files for the project knowledge (described in words; no files are attached) and the text of the project instructions. Assess the instructions first and foremost against R1–R4. Take the plan's coherence into account: files are things needed in almost every chat (no one-off or outdated ones); the instructions are working rules (role, context with a reason, tone, format), not a one-off prompt. If the learner has put a one-off task into the instructions, or reference data into the instructions instead of files, point this out gently. Claude can't see the name, so don't mark down for it."
  criteria: ["R1", "R2", "R3", "R4"]
  reference_prompt: |
    Name: Exams — Microeconomics

    Files for the project knowledge:
    - Microeconomics_course_syllabus.pdf — the list of topics and exam questions, so Claude knows what the exam will cover.
    - Lecture_notes_1-12.docx — my notes, so the explanations match how the lecturer taught each topic.
    - My_mistakes.txt — topics I get confused about; I'll add to it after every practice session.

    Instructions:
    You're a microeconomics tutor for a second-year economics student in Vienna. The exam is on 20 January and it's written: problems plus short theory answers. I remember things best through real-life examples, so explain every concept with an everyday example (a market, a café, a taxi). Draw on the syllabus and my notes; if a topic isn't covered there, say so. Friendly, calm tone. Keep answers under 200 words: a short explanation, one example and, at the end, one problem for me to check myself. If I get something wrong, show me exactly where and give me a similar problem.
  show_reference: true
  fallback_feedback:
    - "Is there a name that will help you spot the project in the list right away?"
    - "Is every file needed in almost every chat? Are there any one-off or outdated files?"
    - "Does it explain why each file is needed?"
    - "Do the instructions include a role: what Claude's job is in this project?"
    - "Is there context and a reason for the rules: what the task is and why it's done this way?"
    - "Are the tone and answer format set as “what to do”?"
    - "Colleague test: could a new assistant work from these instructions without asking questions?"
    - "Is the plan free of other people's personal data, passwords and ID numbers?"
:::
