::: step hook
Marco in Warsaw is uploading his apartment complex's house rules to Claude. It's a scanned handbook running to hundreds of pages, with appendices. An error pops up on screen: **Uploaded file is too large**.

The file didn't go through. Why does this happen, and what now?
:::

::: step explain
Uploads have *limits*, like the baggage allowance on a flight. These currently apply in a single chat:

- files per chat: {{data.limits.chat_files_per_chat}};
- size of one file: {{data.limits.chat_file_size}};
- pages in a PDF: {{data.limits.pdf_pages_max}};
- image size: {{data.limits.image_max_px}}.

Limits change. Navyk checks them against Claude's help centre.
:::

::: step explain
Here's an important detail. In a short PDF (up to {{data.limits.pdf_visual_pages}}) Claude sees both text and visuals: charts, scanned tables, diagrams. In a longer PDF it reads *text only*.

With DOCX, TXT and other non-PDF files it's always like that: Claude takes only the text and can't see any embedded images.
:::

::: exercise single_choice
id: "b3.2.e1"
type: "single_choice"
question: "Marco only needs an answer about parking and noise after 22:00. What's the best thing to do with the huge rulebook?"
options:
  - text: "Save the relevant sections as a separate small PDF and upload that"
    correct: true
    why: "Claude's help centre recommends splitting large documents into sections. Bonus: in a small file Claude finds what's needed faster and gets less distracted by hundreds of irrelevant pages."
  - text: "Keep uploading the same file until it goes through"
    correct: false
    why: "The limit isn't a random glitch. The file is over the limit, and retrying won't make it any smaller."
  - text: "Conclude that Claude doesn't work with documents"
    correct: false
    why: "It does, uploads just have limits. Make the document smaller rather than giving up on the help."
  - text: "Ask Claude about the complex's rules without attaching the file"
    correct: false
    why: "Claude doesn't know the rules of this particular complex. Without the document it'll answer in general terms or get it wrong."
hint: "Claude's help centre recommends one simple step for documents that are too large."
:::

::: exercise single_choice
id: "b3.2.e2"

question: "Olivia uploaded her school's annual report, a very long PDF. Claude summarised the text but said it couldn't see the attendance chart on the last pages. What's going on?"
options:
  - text: "In long PDFs Claude reads only the text, and the chart is an image"
    correct: true
    why: "Exactly. The fix: extract the pages with the chart into a separate short PDF, or take a screenshot of the chart and attach it as an image."
  - text: "Claude can't read charts at all"
    correct: false
    why: "It can, if the chart is an image or in a short PDF. The problem is the length of the file, not charts."
  - text: "Olivia asked the question the wrong way"
    correct: false
    why: "The question has nothing to do with it. Even a perfect question won't help if Claude never received the image from the long PDF."
  - text: "The chart is too colourful"
    correct: false
    why: "Colours aren't a problem. The issue is that from a long PDF Claude takes only the text."
hint: "Remember how a short PDF differs from a long one for Claude."
:::

::: exercise single_choice
id: "b3.2.e3"
type: "single_choice"
question: "Tom sent a DOCX with his boiler manual, which contains a photo of the wiring diagram. Claude answers only from the text and says nothing about the diagram. How can he fix this?"
options:
  - text: "Attach the diagram as a separate image or save the document as a PDF"
    correct: true
    why: "From a DOCX Claude takes only the text. It will see the image if it's uploaded separately or as part of a short PDF."
  - text: "Write “look at the picture more carefully” in the question"
    correct: false
    why: "Asking won't help: the image in the DOCX simply never reached Claude. It can't look at something it didn't receive."
  - text: "Rename the file so it has the word “diagram” in it"
    correct: false
    why: "A file's name doesn't change its contents. The image still won't be read."
  - text: "Upload the same DOCX again in a new chat"
    correct: false
    why: "A new chat won't help: again, only the text will be extracted from the DOCX."
hint: "Think about which format Claude reads in full, images included."
:::

::: step summary
**Uploads have limits, and Claude reads long PDFs without the images.**

Split a large file and upload the parts you need. Need the visuals? Give Claude a short PDF or a screenshot. Navyk shows the current limits from Claude's help centre.
