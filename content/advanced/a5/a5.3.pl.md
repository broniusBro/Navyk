::: step hook
Kasia postanowiła: dość kopiowania zasad piątkowego raportu do każdego czatu. Zrobi własny skill.

Kasia nie jest programistką. Czy będzie potrzebować kodu? Nie: najprostszy skill to jeden plik tekstowy.
:::

::: step explain
Minimalny skill to folder z plikiem *SKILL.md*. Na górze krótki nagłówek z dwoma polami, niżej zwykły tekst:

```markdown
---
name: weekly-client-report
description: Przygotowuje piątkowy raport dla klienta o postępach projektu. Używać, gdy ktoś prosi o raport dla klienta, podsumowanie tygodnia lub status dla zleceniodawcy.
---
# Raport dla klienta
1. Pierwsze zdanie: najważniejsza rzecz z tygodnia.
2. Trzy sekcje: „Zrobione”, „W toku”, „Czego potrzebujemy od Państwa”.
3. Per Państwo, bez żargonu: klienci nie są techniczni.
4. Do 200 słów.
```
:::

::: step explain
*name* to nazwa skilla, do {{data.limits.a5_skill_name_max}}. Najbezpieczniej pisać małymi literami bez polskich znaków, z łącznikami.

*description* ma do {{data.limits.a5_skill_description_max}} i to jest najważniejsze. Pamiętasz grzbiety na półce? Claude widzi tylko je i na podstawie opisu decyduje, czy wyjąć segregator.

Dobry opis mówi dwie rzeczy: co robi skill i kiedy go używać.
:::

::: step explain
Pod nagłówkiem napisz, jak wykonać pracę. Trzy rady z centrum pomocy Claude:

- *zacznij prosto*: tekst instrukcji, bez skryptów;
- *dodaj przykład* dobrego wyniku: przekazuje styl lepiej niż opisy;
- *jeden skill, jedno zadanie*: kilka małych skilli działa lepiej niż jeden ogromny.

Nigdy nie wpisuj do skilla haseł ani kluczy dostępu.
:::

    role: "noise"

::: step explain
Jak zainstalować skill:

1. Włóż SKILL.md do folderu. Nazwa folderu = name.
2. Spakuj folder do ZIP tak, żeby w katalogu głównym archiwum leżał sam folder.
3. Otwórz {{data.ui_paths.a5_customize_skills}} i kliknij {{data.ui_paths.a5_upload_skill}}.

Twój własny skill widzisz tylko ty. Tekst możesz poprawić od razu na miejscu: zaznacz fragment i kliknij {{data.ui_paths.a5_edit_with_claude}}.
:::

  - text: "Wypróbować kilka promptów i zajrzeć do rozumowania Claude, czy skill się wczytał"
    why: "Sprawdzenie w praktyce. Wypróbuj różne sformułowania: „raport dla klienta”, „podsumowanie tygodnia”. Jeśli skill nie działa, popraw description i spróbuj ponownie."
hint: "Najpierw tekst, potem folder, potem archiwum, potem wgrywanie, a na samym końcu sprawdzenie."

::: step explain
Teraz zrób własny skill. Weź zadanie, które opisałeś w pierwszej lekcji modułu, albo dowolne powtarzalne: protokół ze spotkania, odpowiedź na typową reklamację, post do mediów społecznościowych.

Napisz pełny SKILL.md. Navyk wyśle go do Claude do oceny.
:::

Oczekiwany jest nagłówek YAML z name i description oraz tekst instrukcji poniżej. Najważniejsze: description mówi, co robi skill i kiedy go używać, z konkretnymi słowami-sygnałami, do 200 znaków (oceń w R1 i R4: jeśli opis jest ogólnikowy, np. „pomaga z tekstami” albo „używać zawsze”, to główny obszar do poprawy). Instrukcje: jasne zadanie i wynik (R1), kontekst — dla kogo i dlaczego tak (R2), format — struktura, ton, długość (R3), kryterium dobrego wyniku i przykład (R4, R6). Kroki to plus. Nie wymagaj skryptów ani kodu. Jeśli w skillu są hasła, klucze dostępu albo prawdziwe dane osobowe — zadziałało R10: delikatnie ostrzeż, że skill to plik, który można pobrać lub przesłać dalej, i nie powtarzaj tych danych."
  criteria: ["R1", "R2", "R3", "R4", "R6"]
  reference_prompt: |
    ---
    name: meeting-protocol
    description: Zamienia notatki ze spotkania w protokół — decyzje, zadania, osoby odpowiedzialne, terminy. Używać, gdy ktoś prosi o protokół, podsumowanie spotkania lub omówienie calla.
    ---
    # Protokół ze spotkania

    Protokół czytają współpracownicy, których nie było na spotkaniu, więc musi być zrozumiały bez kontekstu.

    1. Pierwsza linijka: temat, data, uczestnicy.

::: step summary
**Skill bez kodu to folder z plikiem SKILL.md: nagłówek z name i description, niżej instrukcje i przykład.**

Opis decyduje o wszystkim: co robi skill i kiedy go używać. Nie działa? Popraw opis i sprawdź ponownie.

Dalej: gdzie trzymać zasadę — w ustawieniach, w projekcie czy w skillu.
:::
