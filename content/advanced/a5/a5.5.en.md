::: step hook
Megan is a lawyer at a small firm. She needs a skill for reviewing contracts, access to the firm's document storage and a couple of quick commands like “summarise this case”.

Find and install everything one piece at a time, then explain to colleagues what to click where? That sounds like half a day's work.
:::

::: step explain
That's what a *plugin* is for: a ready-made bundle of skills, connectors and helpers for specific subtasks, all in one set. Think of it as a starter toolkit for a new employee: open the box, and everything's at hand.

Plugins are put together for a role, a team or a company. They're available {{data.plans.a5_plugins_plans}}.
:::

::: step explain
Everything lives in one directory. In the left sidebar, open {{data.ui_paths.a5_customize}}. There are three tabs: {{data.ui_paths.a5_directory_tabs}}. Each has a {{data.ui_paths.a5_discover}} section.

To install a plugin: go to {{data.ui_paths.a5_customize_plugins_discover}}, pick a plugin and click {{data.ui_paths.a5_add}}. Then type {{data.ui_paths.a5_slash_menu}} in the chat to see its skills and commands.
:::

::: step explain
A plugin is someone else's code and someone else's instructions. Be careful:

- Some plugins run programs (*local MCP servers*) right on your computer. They have the same permissions as any other program.
- Only install from sources you trust.
- If a colleague sends you a plugin, look through it first, then turn it on.

Skills from the directory can't be edited. To change one, download a copy and upload it as your own.
:::

::: exercise multi_choice
id: "a5.5.e4"
type: "multi_choice"
question: "Megan found a “Super Lawyer” plugin from an unknown repository. What's sensible to do before installing it? Select all that apply."
options:
  - text: "Check who made the plugin and where it comes from"
    correct: true
    why: "The source is the first filter. Claude's help centre advises installing plugins only from trusted sources."
  - text: "Check whether it includes programs that run on the computer"
    correct: true
    why: "Local MCP servers run with the permissions of a regular program. If the plugin doesn't need that for its stated task, that's a red flag."
  - text: "If the firm is on a work plan, ask the admin whether plugins like this are allowed"
    correct: true
    why: "In organisations, the admin can restrict plugins, and on some plans can turn on automatic checks for them. Better to ask in advance."
  - text: "Install it straight away: if the plugin turned up, it must be safe"
    correct: false
    why: "No. Being able to find and add a plugin doesn't guarantee it's safe, especially if the repository is unknown."
  - text: "Put the storage password into the plugin's skill so everything runs faster"
    correct: false
    why: "Passwords never go into skills or plugins. Connectors, with a proper sign-in, exist for accessing services."
hint: "Think about three things: where the plugin comes from, what it runs, and who at the firm is responsible for security."
:::

::: step explain
Where a plugin works: in chat on the website and in the app, and also in Claude Code if you're signed in with the same account.

In an ordinary chat, skills and commands work. More complex parts, such as helpers for subtasks and local programs, are shown greyed out there: they're meant for long-running tasks and Claude Code.
:::

::: step summary
**A plugin is a ready-made bundle of skills, connectors and commands for a role or team. It all lives in one directory: {{data.ui_paths.a5_customize}}.**

Before installing, check the source and what the plugin runs on your computer.

Module complete: you can now use skills, write your own and put together ready-made sets.
