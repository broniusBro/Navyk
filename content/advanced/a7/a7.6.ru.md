::: step hook
Максим из Киева организует выездной день для команды из 15 человек:

```prompt
Составь план выездного тимбилдинга для команды.
```

```claude
План: 9:00 — сбор и трансфер, 10:00 — квест на сплочение, 13:00 — обед, 15:00 — верёвочный парк, 18:00 — ужин у костра…
```

Но у Максима половина команды на удалёнке в других городах, бюджет скромный, а один коллега на костылях. Claude этого не знал. И о половине этого Максим сам не подумал заранее.
:::

::: step explain
В большой задаче ты часто не знаешь, какой контекст важен. Тест коллеги не помогает: ты не видишь собственных пробелов.

Выход — *интервью*. Дай короткую задачу и попроси Claude сначала расспросить тебя. Официальный гайд по Claude Code советует так начинать большие задачи: Claude спросит о том, о чём ты ещё не подумал. Мы переносим этот приём в обычный чат.
:::

::: step explain
Образец по мотивам гайда:

```prompt
Хочу организовать выездной день для команды из 15 человек. Расспроси меня подробно, прежде чем что-то предлагать. Не задавай очевидных вопросов — копай в трудные места, о которых я мог не подумать. Продолжай, пока не выяснишь всё важное, а потом собери итоговое задание одним сообщением.
```

Три ключевые части: *не очевидное*, *до конца*, *итоговое задание*.
:::

    correct: false
    why: "Задачу можно описать одной фразой. Гайд Claude Code говорит прямо: если задача описывается одной фразой, планирование можно пропустить. Интервью тут — лишняя трата времени."
  - text: "Узнать, сколько миллилитров в стакане"
    correct: false
    why: "Простой справочный вопрос. Расспрашивать тут не о чем."
  - text: "Исправить опечатку в заголовке поста"
    correct: false
    why: "Всё уже ясно: что, где и как исправить. Сделай напрямую."

::: exercise order_steps
id: "a7.6.e2"

shuffle: true
items:
  - text: "Коротко описать задачу и попросить Claude расспросить тебя"
    why: "Старт минимальный: не надо заранее угадывать, что важно. Это и выяснит интервью."
  - text: "Отвечать на вопросы, пока Claude не скажет, что всё выяснил"
    why: "В образце из гайда: продолжать, пока не обсудили всё. Если на вопрос нет ответа, так и скажи — это тоже информация."
  - text: "Попросить итоговое задание одним сообщением и проверить его"
    why: "Ответы, разбросанные по десяти сообщениям, легко потерять. Задание собирает их в одном месте, и ты сразу видишь, всё ли понято верно."
  - text: "Открыть новый чат, вставить туда задание и попросить выполнить"
    why: "Гайд советует выполнять в новой сессии: чистый контекст занят только работой, а не историей расспросов. В чате это работает так же."
hint: "Сначала спрашивают, потом записывают, потом делают. Делать удобнее с чистого листа."
:::

:::

::: step explain
Какое задание считать хорошим? Гайд описывает это для программистов, но правило общее. Хорошее задание *самодостаточно*: его поймёт человек, который не видел интервью. В нём сказано, что *не входит* в задачу, и *как проверить*, что результат удался.
:::

::: step explain
Теперь сам. Возьми большую задачу из своей жизни или работы: переезд, запуск проекта, ремонт, свадьба, подготовка к экзамену, новый процесс в команде.

Напиши *стартовое* сообщение для интервью. Navyk отправит его на разбор Claude.
:::

::: step summary
**Большая задача? Сначала пусть Claude тебя расспросит.**

Короткий старт, трудные вопросы до конца, итоговое задание одним сообщением, выполнение в новом чате. Для задачи, которая описывается одной фразой, интервью не нужно.

Модуль «Продвинутый промптинг» пройден!
:::
