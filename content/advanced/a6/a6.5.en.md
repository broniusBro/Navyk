::: step hook
Every morning Natalie, a project manager in Dublin, spends 20 minutes on email, calendar and the team chat: what's on fire today?

What if a briefing were waiting for her at 8:30 am, ready to go, every weekday, without her asking?
:::

::: step explain
A *scheduled task* is a job Claude does on its own, on a schedule. You set it up once, and after that each *run* is a separate session.

Frequency: {{data.limits.a6_schedule_frequency}}. Available on: {{data.plans.a6_scheduled_plans}}.

The task runs in the cloud, even while your computer is asleep. The exception is tasks that use local files and programs.
:::

::: step explain
New interface: describe the task and how often in a conversation, answer Claude's questions, check the name, schedule and instructions, then click {{data.ui_paths.a6_schedule_button}}.

Old interface: {{data.ui_paths.a6_scheduled}} → {{data.ui_paths.a6_new_task}} → {{data.ui_paths.a6_create_with_claude}} or {{data.ui_paths.a6_set_up_manually}}.
:::

::: step explain
Each run is a separate session, and Natalie won't be there to clarify anything. So the instructions need to be *self-contained*: what to collect, from where, in what form, and what counts as important.

And boundaries. Write the briefing, but don't send, delete or buy anything: nobody's watching a run in real time.
:::

    weak: false

  - text: "Do it like yesterday. "
    weak: true
    why: "Each run is a separate session. Better not to rely on “yesterday”: describe the format right in the instructions."
  - text: "If a client asks to move a meeting, reply to them straight away and move it. "
    weak: true
    why: "Sending emails and changing meetings are actions other people see, and nobody's watching the run. Better: “flag those emails in the briefing and I'll reply myself”."
  - text: "Output: a list of up to 10 points, urgent items first."
    weak: false
    why: "A specific format and order. The briefing can be read in a minute."
hint: "What will a fresh session with no memory of the past understand? What happens if Claude makes a mistake while nobody's looking?"
:::

::: step explain
The task is created, but the job isn't done. Check the first runs: the results are on the {{data.ui_paths.a6_scheduled}} page, along with past and upcoming runs.

Not happy with the result? Fix the instructions. Task no longer needed? Pause or delete it. Want to test it now? Run it manually without waiting for the schedule.
:::

::: exercise write_prompt
id: "a6.5.e5"
type: "write_prompt"
question: "Write instructions for a scheduled task: how often, where to get the data, what counts as important, what form the result takes and what not to do without you."
placeholder: "Every Monday at 9 am…"
ideas:
  - "How often and at what time should it run?"
  - "Which sources should the data come from?"
  - "What matters, and what should be skipped?"
  - "What form and length should the result have?"
  - "What must Claude not do until you've had a look?"
min_chars: 120
hint: "Imagine each run reads the instructions for the first time with nobody to ask. Is the text enough?"
review:
  task: "The learner writes instructions for a scheduled (recurring) task that Claude carries out on its own on a schedule, each time in a separate session and unsupervised. Strong instructions are self-contained: frequency, data sources, what counts as important and what to skip, the output format; boundaries: don't send, delete or buy anything, flag such cases for a person instead; what to do if data is missing. Don't require names of buttons or interface settings. Don't mark down for missing XML tags. References like “same as last time” count against clarity."
  criteria: ["R1", "R2", "R3", "R4", "R5"]
  reference_prompt: |
    Every Monday at 9 am, put together an overview of competitors' prices for my online tea shop.

    Why: I decide whether to change my prices for the week, and I need to see what's changed, not the whole price list.

    What to do:
    1. Open the green and black tea pages of the three shops listed in the “Competitors” file in the connected folder.
    2. Compare their prices per 100 g with mine from the “My prices” file.
    3. Flag items where a competitor is more than 10% cheaper than me.

    Format: a table (product, my price, competitor's price, difference in %), with 2–3 sentences of conclusions underneath. Only show changes over 10%; leave out the rest.

    If a page doesn't open or there's no price, write “no data” and the link. Don't buy anything, don't contact anyone and don't change my files: save the result as a new file with the date in the name.
  show_reference: true
  fallback_feedback:
    - "Does it say how often and when to run the task?"
    - "Is it clear where to get the data?"
    - "Does it say what matters and what to skip?"
    - "Is the form and length of the result specified?"
    - "Would the instructions be enough for a fresh session, without “same as last time”?"
    - "Does it say what not to do without you: send, delete, buy?"
    - "Is there a rule for when data is missing?"
:::

::: step summary
**Scheduled task = self-contained instructions + a schedule + regular checks on the runs.**

Each run is a new, unsupervised session, so spell everything out and don't allow irreversible actions. Check the results on the scheduled tasks page; edit, pause or delete as needed.

:::
