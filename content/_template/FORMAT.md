# Формат файла урока Navyk

Версия формата: 0.2.0 (2026-10-13). Шаблон: `content/_template/lesson.ru.md`.

Файл урока: `content/{level}/{module}/{lesson_id}.{ru|uk|en}.md`, например `content/beginner/b2/b2.1.ru.md`.
Файл состоит из шапки YAML и последовательности блоков `:::`. Один блок равен одному экрану в приложении.

## 1. Шапка (front matter)

Шапка стоит между строками `---` в начале файла и пишется на строгом YAML.

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `id` | string | да | Совпадает с `id` урока в `content/course.json`. |
| `lang` | `ru` \| `uk` \| `en` | да | Язык файла. |
| `level` | `beginner` \| `advanced` \| `pro` | да | Уровень. |
| `module` | string | да | Id модуля из `course.json` (`b1`, `b2`...). |
| `title` | string | да | Название урока на языке файла. |
| `goal` | string | да | Одна измеримая цель: «После урока ты сможешь…». |
| `duration_min` | int 3..5 | да | Оценка времени прохождения. |
| `prerequisites` | list of lesson ids | да | Может быть `[]`. |
| `principles` | list | да | Id принципов из `course.json` (`P1`...). |
| `free_preview` | bool | нет | `true`: урок доступен до регистрации. |
| `volatile` | bool | да | `true`: урок зависит от быстро меняющихся фактов. |
| `data_refs` | list | нет | Разделы данных, на которые ссылается текст (`ui_paths`, `models`...). |
| `verified_at` | date | да | Дата проверки фактов по официальным источникам. |
| `sources` | list of {url, supports} | да | Источник и факт, который он подтверждает. |
| `repeat` | list | да | План интервального повторения (раздел 5). |

## 2. Экраны-объяснения: `::: step <kind>`

```
::: step explain
Текст в Markdown.
:::
```

`kind`: `hook` (крючок в начале), `explain` (одна мысль), `summary` (правило, которое человек унесёт с собой).

- Лимит повествовательного текста на экран: 60 слов.
- Реплики чата оформляются как огороженный код с типом `prompt` (сообщение человека) или `claude` (ответ Claude).
  Приложение рисует их как пузыри чата. Пузыри не входят в лимит 60 слов, но каждый из них занимает не больше 80 слов.
- Новый термин выделяется курсивом при первом появлении, и сразу за ним идёт пример из жизни.

## 3. Подстановки данных

Названия моделей, тарифы, лимиты и пути в интерфейсе в тексте не пишутся. Вместо них ставится ссылка на данные:
`{{data.<раздел>.<ключ>}}`, например `{{data.ui_paths.chat_input}}`.

Для `ui_paths` движок выводит английское название элемента интерфейса и пояснение на языке урока, например
«**Reply to Claude…** (поле ввода сообщения)». Разделы, которые используются в уроке, перечисляются в `data_refs`.
Ключи берутся из `content/data/*.json`. Если ключа нет, валидатор помечает это ошибкой.

## 4. Упражнения: `::: exercise <type>`

Тело блока пишется на строгом YAML. Поле `type` повторяет тип из заголовка, валидатор проверяет, что они совпадают.
Строки берутся в двойные кавычки. Внутри текста используются кавычки-ёлочки «», а не `"`. Многострочный текст записывается через `|`.

### Общие поля

| Поле | Обяз. | Описание |
|---|---|---|
| `id` | да | `<lesson_id>.e<N>`, уникален в пределах курса. Используется для повторения. |
| `type` | да | Один из `exercise_types` в `course.json`. |
| `question` | да | Формулировка задания. |
| `hint` | да | Подсказка. Показывается по кнопке, ответ не раскрывает. |

Правило автономности: у каждого варианта, фрагмента, блока и пары есть `why`, то есть объяснение,
которое показывается после ответа. Объяснение есть и у верных, и у неверных вариантов, поэтому человек
понимает свою ошибку без учителя.

### single_choice / multi_choice

```yaml
options:
  - text: "..."
    correct: true        # в single_choice ровно один true; в multi_choice хотя бы один
    why: "..."
```
Порядок вариантов перемешивается движком.

### compare_answers

```yaml
variant: "why_better"    # why_better | which_better | which_prompt
cards:                   # 1–3 карточки «запрос → ответ Claude»
  - id: "A"
    label: "..."
    prompt: "..."        # может отсутствовать при variant: which_prompt
    answer: |
      ...
options: [...]           # как в single_choice
```

### find_error

```yaml
prompt: "Полный текст промпта"
segments:                # склейка segments[*].text без разделителей равна prompt
  - text: "Фрагмент "
    weak: true           # хотя бы один фрагмент weak: true
    why: "..."
```
Человек нажимает на слабые фрагменты. Если `weak: true` у нескольких фрагментов, нужно найти все.

### build_prompt

```yaml
blocks:
  - id: "b1"
    text: "..."
    role: "goal"         # goal | context | format | role | noise
    why: "..."
target_order: ["b1", "b2"]   # блоки noise сюда не входят
```

### order_steps

```yaml
shuffle: true
items:                   # в верном порядке; строка или {text, why}
  - text: "..."
    why: "..."
```

### match_pairs

```yaml
pairs:
  - left: "..."
    right: "..."
    why: "..."
```

### fill_gap

```yaml
text: "Текст с пропусками ___ и ___."   # каждый ___ соответствует элементу gaps по порядку
gaps:
  - options:
      - text: "..."
        correct: true
        why: "..."
```

### write_prompt / improve_prompt (с разбором Claude)

```yaml
weak_prompt: "..."       # только для improve_prompt; подставляется в поле ввода для правки
placeholder: "..."       # подсказка в пустом поле
ideas: ["...", "..."]    # чипсы-идеи (необязательно)
min_chars: 15
review:
  task: "..."            # уходит проверяющему в <lesson_context>
  criteria: [R1, R2]     # id из content/reviewer/rubric.json
  reference_prompt: |    # сильный пример; калибровка, а не единственно верный ответ
    ...
  show_reference: true   # показать эталон ученику после разбора
  fallback_feedback:     # чек-лист самопроверки, если ИИ-проверка недоступна или лимит исчерпан
    - "..."
```
Бэкенд берёт `review.*` и рубрику, отправляет запрос проверяющему (`content/reviewer/system-prompt.md`)
и считает балл сам. Если сервис недоступен, приложение показывает `fallback_feedback` как чек-лист
и `reference_prompt` для сравнения. Упражнение засчитывается и в этом случае.

## 5. Повторение (`repeat` в шапке)

```yaml
repeat:
  - concept: "P1"                 # id принципа или понятия
    exercises: ["b2.1.e3"]        # упражнения урока, которые можно вернуть
    schedule:
      - { day: 1, type: single_choice }
      - { day: 3, type: find_error }
      - { day: 7, type: fill_gap }
      - { day: 21, type: write_prompt }
```
`day` считается от дня прохождения урока. Ошибка в повторении переносит понятие на ближайший день повторения.

## 6. Источники: `::: sources`

Список ссылок Markdown. Должен совпадать с `sources` в шапке.
