::: step hook
Ben's team in Cork has five developers and one team lead. Every pull request waits two days for review: the team lead simply can't keep up.

Half the comments are the same every time: "no tests", "key in the code", "forgot to handle the error". An automated check could catch that before the PR ever reaches a human.
:::

::: step explain
That's what *Claude Code GitHub Actions* is for: the `anthropics/claude-code-action` action, which runs Claude Code in your repository's workflow.

Two modes:

- *interactive*: the workflow has no `prompt`; Claude waits for an `@claude` mention in a comment and replies right there;
- *automation mode*: the workflow has a `prompt`; Claude runs by itself on an event, such as a new PR.
:::

::: step explain
The quickest route is the `/install-github-app` command in Claude Code inside the repository. It installs the Claude GitHub App, saves the secret and prepares a pull request with the workflow. You need admin rights on the repository and `gh` installed.

Done by hand, it's three steps: install the app, add the secret, put the workflow file in `.github/workflows/`.
:::

::: step explain
Here's the review workflow example from the docs: the `code-review` plugin runs on every opened or updated PR and leaves comments.

```yaml
on:
  pull_request:
    types: [opened, synchronize, ready_for_review, reopened]
jobs:
  review:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: read
      issues: read
      id-token: write
    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 1
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          plugin_marketplaces: "https://github.com/anthropics/claude-code.git"
          plugins: "code-review@claude-code-plugins"
          prompt: "/code-review:code-review --comment ${{ github.repository }}/pull/${{ github.event.pull_request.number }}"
          claude_args: '--allowedTools "mcp__github_inline_comment__create_inline_comment"'
```

Without `--comment`, the findings only end up in the run log.
:::

::: step explain
Every run uses two resources: GitHub Actions minutes and Claude tokens (billed to your API key, or to your subscription if you sign in with a subscription token).

Two more details. In a public repository, GitHub doesn't pass secrets to runs from forks, so reviews only work for branches in that same repository. And your team's review criteria are best described in `CLAUDE.md`: Claude reads it on every run.
:::

::: step explain
The ready-made plugin looks for common mistakes. But Ben's team has its own rules: "money is stored in cents as integers", "every new endpoint comes with a test". Rules like these belong in your own `prompt` for automation mode.

A good review prompt is like a briefing for a new senior developer: what to check, what matters, what to ignore and how to format the response.
:::

::: step summary
**Claude Code GitHub Actions: `@claude` on request, or an automatic review of every PR.**

- Quick setup: `/install-github-app`.
- The key lives only in GitHub Secrets.
- Workflow permissions: minimal.
- Costs are capped with `--max-turns`, timeouts and concurrency.
- Review criteria go in the `prompt` and `CLAUDE.md`.
