::: step hook
Скрипт із `claude -p` в Андрія працює, але тільки доки ввімкнений ноутбук. У п'ятницю ввечері він закрив кришку й поїхав на дачу. У суботу вранці звіту не було.

Потрібен «співробітник», який працює сам, без його комп'ютера.
:::

::: step explain
Це *routine*: збережене завдання Claude Code — промпт, репозиторії та конектори, — яке саме запускається в хмарі. Ноутбук може бути вимкнений.

Routines доступні на планах {{data.plans.pthree_routines_plans}}. Статус: {{data.plans.pthree_routines_status}}.

Створити routine можна на сторінці {{data.ui_paths.pthree_routines_page}} кнопкою {{data.ui_paths.pthree_new_routine}}, у застосунку Desktop або командою `/schedule` у CLI.
:::

::: step explain
Routine стартує за *тригером*. Є три види тригерів, і їх можна поєднувати:

- {{data.ui_paths.pthree_trigger_schedule}}: щогодини, щодня, у будні, щотижня або один раз у заданий час. Мінімальний інтервал — {{data.limits.pthree_cloud_min_interval}};
- {{data.ui_paths.pthree_trigger_api}}: запит HTTP POST на адресу routine з токеном;
- {{data.ui_paths.pthree_trigger_github}}: новий pull request або реліз у репозиторії.
:::

::: step explain
Головне в routine — промпт. Routine працює сама й *не питає дозволів* під час роботи. Перепитати нікого.

Тому промпт має бути *самодостатнім*: прочитавши тільки його, Claude розуміє, що робити, де, у якому порядку і як виглядає успіх. Це «тест колеги» на максимум: колега отримав записку й пішов працювати в нічну зміну.
:::

::: step explain
API-тригер має важливу деталь. Адреса й токен з'являться після збереження routine: відкрий її для редагування, додай тригер {{data.ui_paths.pthree_trigger_api}} і натисни {{data.ui_paths.pthree_generate_token}}. Токен показують лише один раз — одразу збережи його в сховищі секретів.

```bash
curl -X POST "$ROUTINE_URL" \
  -H "Authorization: Bearer $ROUTINE_TOKEN" \
  -H "anthropic-beta: experimental-cc-routine-2026-04-01" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{"text": "Алерт: помилки 500 на /checkout"}'
```
:::

::: step explain
Кожен запуск створює нову сесію: ти бачиш, що зробив Claude, можеш відкрити зміни й продовжити розмову. Кнопка {{data.ui_paths.pthree_run_now}} запускає routine одразу — зручно для першої перевірки.

Обережно із зеленим статусом. Він означає лише «сесія стартувала й завершилася без збою інфраструктури». Чи виконане завдання, видно тільки в самій сесії.
:::

::: step explain
Тепер сам. Хороший промпт для routine відповідає на п'ять запитань:

1. Що зробити і навіщо?
2. Де брати дані: які файли, PR, період?
3. У якому порядку діяти?
4. Як виглядає результат і куди його покласти?
5. Що робити, якщо щось пішло не так?
:::

::: step summary
**Routine — завдання Claude Code, яке саме запускається в хмарі.**

- Тригери: розклад, API, подія GitHub; їх можна поєднувати.
- Дозволів під час роботи не питає — промпт має бути самодостатнім.
- Текст з API надходить як недовірені дані.
- Зелений статус ≠ завдання виконане: читай сесію.

Далі: коли routine, а коли завдання на власному комп'ютері чи `/loop`.
:::
