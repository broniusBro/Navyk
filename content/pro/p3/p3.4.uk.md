::: step hook
У команді Богдана з Вінниці п'ятеро розробників і один тімлід. Кожен pull request чекає на рев'ю по два дні: тімлід фізично не встигає.

Половина зауважень однакові: «немає тестів», «ключ у коді», «забув обробити помилку». Таке міг би ловити автомат ще до того, як PR дійде до людини.
:::

::: step explain
Для цього є *Claude Code GitHub Actions* — дія `anthropics/claude-code-action`, яка запускає Claude Code у workflow твого репозиторію.

Два режими:

- *інтерактивний*: у workflow немає `prompt`, Claude чекає на згадку `@claude` у коментарі й відповідає там само;
- *режим автоматизації*: у workflow є `prompt`, Claude запускається сам на подію, наприклад на новий PR.
:::

::: step explain
Найшвидший шлях — команда `/install-github-app` у Claude Code всередині репозиторію. Вона встановлює Claude GitHub App, зберігає секрет і готує pull request із workflow. Потрібні права адміністратора репозиторію і встановлений `gh`.

Вручну це три кроки: встановити застосунок, додати секрет, покласти файл workflow у `.github/workflows/`.
:::

::: step explain
Приклад workflow рев'ю з документації: плагін `code-review` запускається на кожен відкритий або оновлений PR і залишає коментарі.

```yaml
on:
  pull_request:
    types: [opened, synchronize, ready_for_review, reopened]
jobs:
  review:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: read
      issues: read
      id-token: write
    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 1
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          plugin_marketplaces: "https://github.com/anthropics/claude-code.git"
          plugins: "code-review@claude-code-plugins"
          prompt: "/code-review:code-review --comment ${{ github.repository }}/pull/${{ github.event.pull_request.number }}"
          claude_args: '--allowedTools "mcp__github_inline_comment__create_inline_comment"'
```

Без `--comment` зауваження залишаться лише в лозі запуску.
:::

::: step explain
Кожен запуск витрачає два ресурси: хвилини GitHub Actions і токени Claude (за ключем API або з підписки, якщо вхід через токен підписки).

Ще дві деталі. У публічному репозиторії GitHub не передає секрети в запуски з форків, тому рев'ю працює лише для гілок цього самого репозиторію. А критерії рев'ю команди зручно описати в `CLAUDE.md`: Claude читає його під час кожного запуску.
:::

::: step explain
Готовий плагін шукає загальні помилки. Але в команди Богдана свої правила: «гроші рахуємо в копійках цілими числами», «кожен новий ендпоінт — із тестом». Такі правила варто вписати у власний `prompt` для режиму автоматизації.

Хороший промпт рев'ю — як інструкція новому старшому розробникові: що перевіряти, що важливо, на що не зважати і як оформити відповідь.
:::

::: step summary
**Claude Code GitHub Actions: `@claude` на запит або автоматичне рев'ю кожного PR.**

- Швидке налаштування — `/install-github-app`.
- Ключ — тільки в GitHub Secrets.
- Права workflow — мінімальні.
- Витрати обмежують `--max-turns`, тайм-аути й concurrency.
- Критерії рев'ю — у `prompt` і `CLAUDE.md`.

Далі: як не дати автоматизації зробити зайве від твого імені.
:::
