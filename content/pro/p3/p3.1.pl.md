::: step hook
Paweł z Krakowa co rano otwiera Claude Code i pisze to samo: „Przejrzyj wczorajszy log builda i powiedz, co się zepsuło”.

Pięć minut dziennie, dwadzieścia pięć tygodniowo. Chce, żeby robił to skrypt, a on rano tylko czytał gotowe podsumowanie. Ale przecież Claude Code jest interaktywny: czy nie zakłada, że ktoś przy nim siedzi?
:::

::: step explain
Niekoniecznie. Claude Code ma *tryb nieinteraktywny*: flagę `-p` (pełna nazwa `--print`). Claude wykonuje prompt, wypisuje odpowiedź i kończy działanie. Jak zwykłe polecenie w terminalu: uruchomiłeś, dostałeś wynik, idziesz dalej.

```bash
claude -p "Co robi moduł auth?"
```

Przy sukcesie polecenie zwraca kod wyjścia 0, przy błędzie — niezerowy. Skrypt może się na tym opierać.
:::

:::

::: step explain
Dane możesz podać na wejście potokiem `|`, a odpowiedź zapisać do pliku:

```bash
cat build-error.txt | claude -p "krótko wyjaśnij przyczynę błędu builda" > output.txt
```

Przez stdin możesz przekazać do {{data.limits.pthree_stdin_max}}. Jeśli masz więcej, zapisz dane do pliku i podaj ścieżkę w prompcie.

Dla skryptu wygodniejszy jest JSON. Flaga `--output-format` przyjmuje `text` (domyślnie), `json` i `stream-json`.
:::

::: exercise match_pairs
id: "p3.1.e2"
type: "match_pairs"
question: "Połącz zadanie skryptu z odpowiednim formatem wyjścia."
pairs:
  - left: "Zapisać odpowiedź czytelną dla człowieka do pliku z raportem"
    right: "`--output-format text`"
    why: "To format domyślny: sam tekst odpowiedzi. Wygodnie go czytać albo zapisać bez zmian."
  - left: "Wyciągnąć odpowiedź i id sesji, żeby później kontynuować rozmowę"
    right: "`--output-format json`"
    why: "Jeden obiekt JSON: tekst odpowiedzi w polu `result`, a do tego `session_id`, koszt `total_cost_usd` i inne metadane."
  - left: "Pokazywać odpowiedź we własnym interfejsie w trakcie generowania"
    right: "`--output-format stream-json`"
    why: "Każda linia to osobne zdarzenie w JSON. Ostatnia linia to końcowy komunikat `result`. Do strumienia token po tokenie dodaje się `--verbose` i `--include-partial-messages`."
  - left: "Dostać listę funkcji ściśle jako tablicę stringów"
    right: "`--output-format json` razem z `--json-schema`"
    why: "Ze schematem JSON Schema odpowiedź trafia do pola `structured_output` i jest z nim zgodna. Skrypt nie musi parsować swobodnego tekstu."
hint: "Text jest dla ludzi, json to jeden obiekt dla skryptu, stream-json to strumień zdarzeń. Gdy potrzebna ścisła struktura, dodaje się schemat."
:::

::: step explain
Tak Paweł wyciąga z JSON-a sam tekst odpowiedzi. Narzędzie `jq` parsuje JSON prosto w terminalu:

```bash
claude -p "Przeanalizuj log build.log i wypisz błędy" \
  --output-format json | jq -r '.result'
```

A pole `total_cost_usd` to szacunek kosztu po stronie klienta, faktyczny rachunek może się różnić.
:::

::: step explain
Bez człowieka nie ma kto kliknąć „zezwól”. Dlatego uprawnienia ustawia się z góry:

- `--allowedTools "Read,Edit"` — te narzędzia działają bez pytania;
- `Bash(git diff *)` — zezwól tylko na polecenia zaczynające się od `git diff`. Spacja przed `*` ma znaczenie;
- `--permission-mode dontAsk` — wszystko, co wymagałoby potwierdzenia, jest odrzucane.

Zasada: zezwalaj dokładnie na to, czego potrzebuje zadanie.
:::

::: step explain
Czasem potrzebny jest drugi krok w tej samej rozmowie. Flaga `--continue` kontynuuje ostatnią rozmowę. Jeśli skryptów jest kilka, pewniej jest zapisać `session_id` i przekazać go do `--resume`:

```bash
session_id=$(claude -p "Zacznij code review" --output-format json | jq -r '.session_id')
claude -p "Kontynuuj to review" --resume "$session_id"
```
:::

::: step explain
Jeszcze jedna flaga do skryptów — `--bare`. Nie wczytuje hooków, skilli, pluginów, serwerów MCP, automatycznej pamięci ani CLAUDE.md. Wynik jest taki sam na każdej maszynie: cudze ustawienia z `~/.claude` się nie wtrącą.

W trybie `--bare` logowanie przez subskrypcję nie działa, potrzebny jest klucz API w zmiennej `ANTHROPIC_API_KEY`. Dokumentacja zaleca `--bare` do skryptów i CI.
:::

::: step summary
**`claude -p` to Claude Code jako zwykłe polecenie terminala.**

- `--output-format json` i `jq`: odpowiedź w `result`, id w `session_id`.
- Uprawnienia ustawiasz z góry i wąsko: `--allowedTools`, `--permission-mode dontAsk`.
- `--resume "$id"` kontynuuje właściwą rozmowę.
- Do CI — `--bare` i klucz API.

Dalej: jak uruchamiać takie zadania według harmonogramu, nawet gdy laptop jest zamknięty.
:::
