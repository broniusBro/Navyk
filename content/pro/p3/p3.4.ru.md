::: step hook
В команде Богдана из Винницы пятеро разработчиков и один тимлид. Каждый pull request ждёт ревью по два дня: тимлид физически не успевает.

Половина замечаний одни и те же: «нет тестов», «ключ в коде», «забыл обработать ошибку». Такое мог бы ловить автомат ещё до того, как PR дойдёт до человека.
:::

::: step explain
Для этого есть *Claude Code GitHub Actions* — действие `anthropics/claude-code-action`, которое запускает Claude Code в workflow твоего репозитория.

Два режима:

- *интерактивный*: в workflow нет `prompt`, Claude ждёт упоминания `@claude` в комментарии и отвечает там же;
- *режим автоматизации*: в workflow есть `prompt`, Claude запускается сам на событие, например на новый PR.
:::

::: step explain
Самый быстрый путь — команда `/install-github-app` в Claude Code внутри репозитория. Она ставит Claude GitHub App, сохраняет секрет и готовит pull request с workflow. Нужны права администратора репозитория и установленный `gh`.

Вручную это три шага: установить приложение, добавить секрет, положить файл workflow в `.github/workflows/`.
:::

::: step explain
Пример workflow ревью из документации: плагин `code-review` запускается на каждый открытый или обновлённый PR и оставляет комментарии.

```yaml
on:
  pull_request:
    types: [opened, synchronize, ready_for_review, reopened]
jobs:
  review:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: read
      issues: read
      id-token: write
    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 1
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          plugin_marketplaces: "https://github.com/anthropics/claude-code.git"
          plugins: "code-review@claude-code-plugins"
          prompt: "/code-review:code-review --comment ${{ github.repository }}/pull/${{ github.event.pull_request.number }}"
          claude_args: '--allowedTools "mcp__github_inline_comment__create_inline_comment"'
```

Без `--comment` замечания останутся только в логе запуска.
:::

::: step explain
Каждый запуск тратит два ресурса: минуты GitHub Actions и токены Claude (по ключу API или из подписки, если вход через токен подписки).

Ещё две детали. В публичном репозитории GitHub не передаёт секреты в запуски из форков, поэтому ревью работает только для веток этого же репозитория. А критерии ревью команды удобно описать в `CLAUDE.md`: Claude читает его на каждом запуске.
:::

::: step explain
Готовый плагин ищет общие ошибки. Но у команды Богдана свои правила: «деньги считаем в копейках целыми числами», «каждый новый эндпоинт — с тестом». Такие правила стоит вписать в собственный `prompt` для режима автоматизации.

Хороший промпт ревью — как инструкция новому старшему разработчику: что проверять, что важно, что не замечать и как оформить ответ.
:::

::: step summary
**Claude Code GitHub Actions: `@claude` по запросу или автоматический ревью на каждый PR.**

- Быстрая настройка — `/install-github-app`.
- Ключ — только в GitHub Secrets.
- Права workflow — минимальные.
- Расходы ограничивают `--max-turns`, таймауты и concurrency.
- Критерии ревью — в `prompt` и `CLAUDE.md`.

Дальше: как не дать автоматизации сделать лишнее от твоего имени.
:::
