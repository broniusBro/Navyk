::: step hook
W zespole Bartka z Wrocławia jest pięciu programistów i jeden team lead. Każdy pull request czeka na review po dwa dni: team lead fizycznie nie nadąża.

Połowa uwag powtarza się w kółko: „brak testów”, „klucz w kodzie”, „nie obsłużyłeś błędu”. Coś takiego mógłby wyłapać automat, zanim PR w ogóle trafi do człowieka.
:::

::: step explain
Do tego służy *Claude Code GitHub Actions* — akcja `anthropics/claude-code-action`, która uruchamia Claude Code w workflow twojego repozytorium.

Dwa tryby:

- *interaktywny*: w workflow nie ma `prompt`, Claude czeka na wzmiankę `@claude` w komentarzu i odpowiada w tym samym miejscu;
- *tryb automatyzacji*: w workflow jest `prompt`, Claude uruchamia się sam po zdarzeniu, np. po nowym PR.
:::

::: step explain
Najszybsza droga to polecenie `/install-github-app` w Claude Code wewnątrz repozytorium. Instaluje Claude GitHub App, zapisuje sekret i przygotowuje pull request z workflow. Potrzebujesz uprawnień administratora repozytorium i zainstalowanego `gh`.

Ręcznie to trzy kroki: zainstalować aplikację, dodać sekret, umieścić plik workflow w `.github/workflows/`.
:::

::: step explain
Przykładowy workflow review z dokumentacji: plugin `code-review` uruchamia się przy każdym otwartym lub zaktualizowanym PR i zostawia komentarze.

```yaml
on:
  pull_request:
    types: [opened, synchronize, ready_for_review, reopened]
jobs:
  review:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: read
      issues: read
      id-token: write
    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 1
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          plugin_marketplaces: "https://github.com/anthropics/claude-code.git"
          plugins: "code-review@claude-code-plugins"
          prompt: "/code-review:code-review --comment ${{ github.repository }}/pull/${{ github.event.pull_request.number }}"
          claude_args: '--allowedTools "mcp__github_inline_comment__create_inline_comment"'
```

Bez `--comment` uwagi zostaną tylko w logu uruchomienia.
:::

::: step explain
Każde uruchomienie zużywa dwa zasoby: minuty GitHub Actions i tokeny Claude (z klucza API albo z subskrypcji, jeśli logujesz się tokenem subskrypcji).

Jeszcze dwa szczegóły. W publicznym repozytorium GitHub nie przekazuje sekretów do uruchomień z forków, więc review działa tylko dla gałęzi z tego samego repozytorium. A kryteria review zespołu wygodnie opisać w `CLAUDE.md`: Claude czyta go przy każdym uruchomieniu.
:::

::: step explain
Gotowy plugin szuka typowych błędów. Ale zespół Bartka ma własne zasady: „kwoty liczymy w groszach jako liczby całkowite”, „każdy nowy endpoint — z testem”. Takie zasady warto wpisać do własnego `prompt` w trybie automatyzacji.

Dobry prompt review jest jak instrukcja dla nowego starszego programisty: co sprawdzać, co jest ważne, czego nie zauważać i jak sformułować odpowiedź.
:::

::: step summary
**Claude Code GitHub Actions: `@claude` na życzenie albo automatyczne review każdego PR.**

- Szybka konfiguracja — `/install-github-app`.
- Klucz — tylko w GitHub Secrets.
- Uprawnienia workflow — minimalne.
- Koszty ograniczają `--max-turns`, timeouty i concurrency.
- Kryteria review — w `prompt` i `CLAUDE.md`.

Dalej: jak nie pozwolić automatyzacji zrobić czegoś zbędnego w twoim imieniu.
:::
