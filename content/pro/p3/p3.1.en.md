::: step hook
Every morning, Liam in Dublin opens Claude Code and types the same thing: "Go through yesterday's build log and tell me what broke."

Five minutes a day, twenty-five a week. He wants a script to do it so all he has to do in the morning is read the summary. But Claude Code is interactive, isn't it? Doesn't it expect someone sitting there?
:::

::: step explain
Not necessarily. Claude Code has a *non-interactive mode*: the `-p` flag (full name `--print`). Claude runs the prompt, prints the response and exits. Just like any other terminal command: run it, get the output, move on.

```bash
claude -p "What does the auth module do?"
```

On success the command returns exit code 0; on failure, a non-zero code. Your script can rely on that.
:::

::: step explain
You can pipe data in with `|` and save the response to a file:

```bash
cat build-error.txt | claude -p "briefly explain what caused the build error" > output.txt
```

You can pass up to {{data.limits.pthree_stdin_max}} through stdin. For anything bigger, save it to a file and put the path in the prompt.

For scripts, JSON is handier. The `--output-format` flag can be `text` (the default), `json` or `stream-json`.
:::

::: step explain
Here's how Liam pulls just the response text out of the JSON. The `jq` utility parses JSON right in the terminal:

```bash
claude -p "Analyse build.log and list the errors" \
  --output-format json | jq -r '.result'
```

As for the `total_cost_usd` field: it's a client-side cost estimate, and your actual bill may differ.
:::

::: step explain
With nobody around, there's no one to click "allow". So you set permissions in advance:

- `--allowedTools "Read,Edit"`: these tools run without asking;
- `Bash(git diff *)`: allow only commands that start with `git diff`. The space before `*` matters;
- `--permission-mode dontAsk`: anything that would need approval is denied.

The rule: allow exactly what the task needs.
:::

::: step explain
Sometimes you need a second step in the same conversation. The `--continue` flag continues the most recent conversation. If you have several scripts, it's safer to save the `session_id` and pass it to `--resume`:

```bash
session_id=$(claude -p "Start a review" --output-format json | jq -r '.session_id')
claude -p "Continue that review" --resume "$session_id"
```
:::

::: step explain
One more flag for scripts: `--bare`. It doesn't load hooks, skills, plugins, MCP servers, auto memory or CLAUDE.md. You get the same result on any machine: other people's settings in `~/.claude` can't interfere.

In `--bare` mode, subscription login isn't used; you need an API key in the `ANTHROPIC_API_KEY` variable. The docs recommend `--bare` for scripts and CI.
:::

::: step summary
**`claude -p` turns Claude Code into an ordinary terminal command.**

- `--output-format json` plus `jq`: the answer is in `result`, the ID in `session_id`.
- Set permissions up front and keep them narrow: `--allowedTools`, `--permission-mode dontAsk`.
- `--resume "$id"` continues the right conversation.
- For CI: `--bare` and an API key.
