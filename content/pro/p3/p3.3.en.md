::: step hook
Emma in Galway runs a photo studio's website. She needs three things:

1. Check the site's repository for broken links every night.
2. Sort new photos in a folder on her Mac every hour.
3. Keep an eye on whether a deployment has finished for the next half hour.

All of these are "scheduled", but each needs a different tool. Why?
:::

::: step explain
There are three ways to run Claude on a schedule:

- *A cloud routine* works without your computer, but only sees a fresh copy of the repository.
- *A local task in Desktop* runs on your computer and sees your files, but only while the app is open and the computer is awake.
- *`/loop`* repeats a prompt inside an open Claude Code session. Close the session and the repeats stop.
:::

::: step explain
Three more differences:

| | Cloud | Desktop | `/loop` |
|---|---|---|---|
| Asks for permission | no | as you configure it | as in the session |
| Minimum interval | {{data.limits.pthree_cloud_min_interval}} | {{data.limits.pthree_local_min_interval}} | {{data.limits.pthree_local_min_interval}} |
| Survives a restart | yes | yes | partly, via `--resume` |

Rule of thumb: reliable and without your computer, use the cloud; need local files, use Desktop; quick check-in during a session, use `/loop`.
:::

::: step explain
`/loop` is the quickest option. An interval and a prompt:

```text
/loop 5m check whether the deployment has finished and tell me what happened
```

Units: `s`, `m`, `h`, `d`. Without an interval, Claude picks the delay between repeats itself, anywhere from a minute to an hour.

Recurring tasks are deleted after {{data.limits.pthree_loop_expiry}}, and a single session can have up to {{data.limits.pthree_loop_max_tasks}}. For a one-off reminder, it's easier to just ask in words: "in 45 minutes, check the integration tests".
:::

::: step explain
You create a local task in Desktop: {{data.ui_paths.pthree_desktop_new_routine}}, then {{data.ui_paths.pthree_desktop_local}}. Choosing {{data.ui_paths.pthree_desktop_cloud}} creates a cloud routine instead.

If the computer was asleep, Desktop does *one* catch-up run for the most recent missed time when it wakes (within {{data.limits.pthree_desktop_catchup_window}}). A "9 am" task might run at 11 pm. Plan for that in the prompt.
:::

::: step summary
**The choice comes down to two questions: does the computer need to be on, and do you need local files?**

- No computer, reliable: a cloud routine (no more than once an hour).
- Local files: a Desktop task (the computer stays awake).
- Quick check-in: `/loop` in an open session.
