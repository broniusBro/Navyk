::: step hook
Андрій із Харкова щоранку відкриває Claude Code і пише те саме: «Розбери вчорашній лог збірки й скажи, що зламалося».

П'ять хвилин на день, двадцять п'ять на тиждень. Він хоче, щоб це робив скрипт, а він уранці тільки читав готовий підсумок. Але ж Claude Code інтерактивний: хіба він не чекає, що поруч сидітиме людина?
:::

::: step explain
Не обов'язково. Claude Code має *неінтерактивний режим*: прапорець `-p` (повна назва `--print`). Claude виконує запит, друкує відповідь і завершує роботу. Як звичайна команда терміналу: запустив, отримав вивід, пішов далі.

```bash
claude -p "Що робить модуль auth?"
```

У разі успіху команда повертає код виходу 0, у разі збою — ненульовий. Скрипт може на це спиратися.
:::

::: step explain
Дані можна подати на вхід через конвеєр `|`, а відповідь зберегти у файл:

```bash
cat build-error.txt | claude -p "коротко поясни причину помилки збірки" > output.txt
```

Через stdin можна подати до {{data.limits.pthree_stdin_max}}. Якщо більше — збережи у файл і вкажи шлях у запиті.

Для скрипта зручніший JSON. Прапорець `--output-format` буває `text` (за замовчуванням), `json` і `stream-json`.
:::

  - left: "Отримати список функцій суворо у вигляді масиву рядків"

hint: "Text — для людей, json — один об'єкт для скрипта, stream-json — потік подій. Де потрібна сувора структура, додають схему."
:::

::: step explain
Ось як Андрій дістає з JSON лише текст відповіді. Утиліта `jq` розбирає JSON просто в терміналі:

```bash
claude -p "Розбери лог build.log і перелічи помилки" \
  --output-format json | jq -r '.result'
```

А ось поле `total_cost_usd`: це оцінка вартості на боці клієнта, реальний рахунок може відрізнятися.
:::

::: step explain
Без людини нікому натиснути «дозволити». Тому права задають заздалегідь:

- `--allowedTools "Read,Edit"` — ці інструменти працюють без запитань;
- `Bash(git diff *)` — дозволити тільки команди, які починаються з `git diff`. Пробіл перед `*` важливий;
- `--permission-mode dontAsk` — усе, що потребувало б підтвердження, відхиляється.

Правило: дозволяй рівно те, що потрібно завданню.
:::

::: step explain
Іноді потрібен другий крок у тій самій розмові. Прапорець `--continue` продовжує останню розмову. Якщо скриптів кілька, надійніше зберегти `session_id` і передати його в `--resume`:

```bash
session_id=$(claude -p "Почни рев'ю" --output-format json | jq -r '.session_id')
claude -p "Продовж це рев'ю" --resume "$session_id"
```
:::

::: step explain
Ще один прапорець для скриптів — `--bare`. Він не завантажує хуки, навички, плагіни, MCP-сервери, автопам'ять і CLAUDE.md. Результат однаковий на будь-якій машині: чужі налаштування з `~/.claude` не втрутяться.

У режимі `--bare` вхід за підпискою не використовується, потрібен ключ API у змінній `ANTHROPIC_API_KEY`. Документація рекомендує `--bare` для скриптів і CI.
:::

::: step summary
**`claude -p` — Claude Code як звичайна команда терміналу.**

- `--output-format json` і `jq`: відповідь у `result`, id у `session_id`.
- Права задають заздалегідь і вузько: `--allowedTools`, `--permission-mode dontAsk`.
- `--resume "$id"` продовжує потрібну розмову.
- Для CI — `--bare` і ключ API.

Далі: як запускати такі завдання за розкладом, навіть коли ноутбук закритий.
:::
