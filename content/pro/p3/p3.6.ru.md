::: step hook
Дмитрий из Запорожья в одном терминале попросил Claude сделать новую форму входа, а во втором — починить баг в корзине. Через десять минут обе сессии правили один и тот же `package.json`, а тесты падали от чужих изменений.

Две сессии — хорошая идея. Одна папка на двоих — плохая.
:::

::: step explain
Решение — *git worktree*: отдельная рабочая папка со своими файлами и своей веткой, но с общей историей репозитория. Как два стола в одной мастерской: инструменты общие, а заготовки друг другу не мешают.

```bash
claude --worktree feature-auth
```

Claude создаст папку `.claude/worktrees/feature-auth/` на новой ветке `worktree-feature-auth`. Вторая сессия — та же команда с другим именем в другом терминале.
:::

::: step explain
Три практические мелочи:

- добавь `.claude/worktrees/` в `.gitignore`, чтобы папки не мешались в основной копии;
- worktree — свежая копия, поэтому зависимости ставят заново, а файлы вроде `.env` переносит `.worktreeinclude`;
- при выходе пустой безымянный worktree удаляется сам. Если в нём есть изменения, Claude спросит, оставить его или удалить.
:::

::: step explain
Если сессий много, их удобно держать на одном экране. Это *agent view*, статус: {{data.plans.pthree_agent_view_status}}.

```bash
claude agents
claude --bg "разберись, почему падает тест SettingsChangeDetector"
```

Каждый запрос запускает фоновую сессию. Перед правкой файлов она переходит в свой worktree. Статусы: Working, Needs input, Completed и другие — сразу видно, кто ждёт тебя.
:::

::: step explain
Параллельность нужна не только для скорости. Сессия, которая только что написала код, склонна считать его хорошим. Свежий контекст смотрит честнее.

Это паттерн *«автор/ревьюер»*: сессия A пишет, сессия B без истории A делает ревью, A исправляет по замечаниям. Похожий вариант: один Claude пишет тесты, другой — код, который их проходит.
:::

  - text: "Замечания B передаются в сессию A"

  - text: "Сессия A исправляет код по замечаниям и снова запускает тесты"

hint: "Кто пишет, кто смотрит, как замечания возвращаются и чем всё заканчивается?"
:::

::: step explain
Важная тонкость: ревьюер, которого просят «найти проблемы», почти всегда что-нибудь найдёт, даже в хорошем коде. Если гоняться за каждым замечанием, код обрастёт лишними слоями и проверками.

Поэтому в промпте ревьюера называют, *что* проверять и по какому плану, и просят отмечать только то, что влияет на корректность и требования.
:::

::: step summary
**Параллельно — значит изолированно.**

- `claude --worktree <имя>`: своя папка и ветка на каждую сессию.
- `claude agents`: фоновые сессии на одном экране, каждая в своём worktree.
- Лимиты расходуются за каждую сессию.
- «Автор/ревьюер»: свежий контекст проверяет честнее; проси только существенные замечания.

Модуль пройден: теперь Claude работает на тебя и по расписанию, и параллельно.
:::
