::: step hook
Ольга з Одеси веде сайт фотостудії. Їй потрібні три речі:

1. Щоночі перевіряти репозиторій сайту на биті посилання.
2. Щогодини розбирати нові фото в теці на її Mac.
3. Найближчі пів години стежити, чи завершився деплой.

Усе це «за розкладом», але інструменти потрібні різні. Чому?
:::

::: step explain
Є три способи запускати Claude за розкладом:

- *Routine у хмарі* — працює без твого комп'ютера, але бачить лише свіжу копію репозиторію.
- *Локальне завдання в Desktop* — працює на твоєму комп'ютері й бачить твої файли, але тільки доки застосунок відкритий і комп'ютер не спить.
- *`/loop`* — повторює запит усередині відкритої сесії Claude Code. Закрив сесію — повтори припинилися.
:::

::: step explain
Ще три відмінності:

| | Хмара | Desktop | `/loop` |
|---|---|---|---|
| Питає дозволу | ні | як налаштуєш | як у сесії |
| Мінімальний інтервал | {{data.limits.pthree_cloud_min_interval}} | {{data.limits.pthree_local_min_interval}} | {{data.limits.pthree_local_min_interval}} |
| Переживає перезапуск | так | так | частково, через `--resume` |

Коротке правило: надійно й без комп'ютера — хмара; потрібні локальні файли — Desktop; швидко простежити в сесії — `/loop`.
:::

::: step explain
`/loop` — найшвидший спосіб. Інтервал і запит:

```text
/loop 5m перевір, чи завершився деплой, і скажи, що сталося
```

Одиниці: `s`, `m`, `h`, `d`. Без інтервалу Claude сам обирає паузу між повторами, від хвилини до години.

Повторювані завдання видаляються через {{data.limits.pthree_loop_expiry}}, в одній сесії їх може бути до {{data.limits.pthree_loop_max_tasks}}. Разове нагадування простіше попросити словами: «за 45 хвилин перевір інтеграційні тести».
:::

::: step explain
Локальне завдання створюють у Desktop: {{data.ui_paths.pthree_desktop_new_routine}}, потім {{data.ui_paths.pthree_desktop_local}}. Вибір {{data.ui_paths.pthree_desktop_cloud}} створює хмарну routine.

Якщо комп'ютер спав, після пробудження Desktop робить *один* надолужувальний запуск за останній пропущений строк (у межах {{data.limits.pthree_desktop_catchup_window}}). Завдання «на 9 ранку» може виконатися об 11 вечора. Враховуй це в промпті.
:::

::: step summary
**Вибір залежить від двох запитань: чи потрібен увімкнений комп'ютер і чи потрібні локальні файли.**

- Без комп'ютера, надійно — routine у хмарі (не частіше ніж раз на годину).
- Локальні файли — завдання в Desktop (комп'ютер не спить).
- Швидко простежити — `/loop` у відкритій сесії.

Далі: автоматичне рев'ю pull request у GitHub Actions.
