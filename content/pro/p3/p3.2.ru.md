::: step hook
Скрипт с `claude -p` у Андрея работает, но только пока включён ноутбук. В пятницу вечером он закрыл крышку и уехал на дачу. В субботу утром отчёта не было.

Нужен «сотрудник», который работает сам, без его компьютера.
:::

::: step explain
Это *routine*: сохранённая задача Claude Code — промпт, репозитории и коннекторы, — которая запускается сама в облаке. Ноутбук может быть выключен.

Routines доступны на планах {{data.plans.pthree_routines_plans}}. Статус: {{data.plans.pthree_routines_status}}.

Создать routine можно на странице {{data.ui_paths.pthree_routines_page}} кнопкой {{data.ui_paths.pthree_new_routine}}, в приложении Desktop или командой `/schedule` в CLI.
:::

::: step explain
Routine стартует по *триггеру*. Их три вида, и их можно совмещать:

- {{data.ui_paths.pthree_trigger_schedule}}: каждый час, день, будни, неделю или один раз в заданное время. Минимальный интервал — {{data.limits.pthree_cloud_min_interval}};
- {{data.ui_paths.pthree_trigger_api}}: запрос HTTP POST на адрес routine с токеном;
- {{data.ui_paths.pthree_trigger_github}}: новый pull request или релиз в репозитории.
:::

::: step explain
Главное в routine — промпт. Routine работает сама и *не спрашивает разрешений* по ходу. Переспросить некого.

Поэтому промпт должен быть *самодостаточным*: прочитав только его, Claude понимает, что делать, где, в каком порядке и как выглядит успех. Это «тест коллеги» на максималках: коллега получил записку и ушёл работать в ночную смену.
:::

::: step explain
У API-триггера есть важная деталь. Адрес и токен появятся после сохранения routine: открой её на редактирование, добавь триггер {{data.ui_paths.pthree_trigger_api}} и нажми {{data.ui_paths.pthree_generate_token}}. Токен показывается один раз — сразу сохрани его в хранилище секретов.

```bash
curl -X POST "$ROUTINE_URL" \
  -H "Authorization: Bearer $ROUTINE_TOKEN" \
  -H "anthropic-beta: experimental-cc-routine-2026-04-01" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{"text": "Алерт: 500-е ошибки на /checkout"}'
```
:::

::: step explain
Каждый запуск создаёт новую сессию: ты видишь, что Claude сделал, можешь открыть изменения и продолжить разговор. Кнопка {{data.ui_paths.pthree_run_now}} запускает routine сразу — удобно для первой проверки.

Осторожно с зелёным статусом. Он значит только «сессия стартовала и завершилась без сбоя инфраструктуры». Сделана ли задача, видно лишь в самой сессии.
:::

::: step explain
Теперь сам. Хороший промпт для routine отвечает на пять вопросов:

1. Что сделать и зачем?
2. Где брать данные: какие файлы, PR, период?
3. В каком порядке действовать?
4. Как выглядит результат и куда его положить?
5. Что делать, если что-то пошло не так?
:::

::: step summary
**Routine — задача Claude Code, которая сама запускается в облаке.**

- Триггеры: расписание, API, событие GitHub; их можно совмещать.
- Разрешений по ходу не спрашивает — промпт должен быть самодостаточным.
- Текст из API приходит как недоверенные данные.
- Зелёный статус ≠ задача выполнена: читай сессию.

Дальше: когда routine, а когда задача на своём компьютере или `/loop`.
:::
