::: step hook
Sarah has built a research agent: it reads eight long review papers and writes a comparison.

Everything fits in the context window, but towards the end the agent mixes up figures from the first review and gets slower and slower. Nothing has been deleted, so why is this happening?
:::

::: step explain
Context is a limited resource. The more tokens in the window, the worse the model is at recalling specific details, even before the limit. This is called *context rot*. Think of a desk buried in paperwork: the page you need is there, but it gets harder and harder to find.

On top of that, every step reprocesses the whole context, so latency and cost go up.
:::

  - text: "The reviews are written in a different language"
    correct: false
    why: "Language has nothing to do with it. The same problem happens with any long material."
hint: "Think back to the desk buried in paperwork."
:::

::: step explain
*Context engineering* means keeping the minimum in the window, but the most useful minimum. Four techniques:

- *Compaction*: near the window limit, the conversation is replaced with a summary, and the agent carries on from there.
- *Tool result clearing*: old results are replaced with a placeholder, but the record of the call stays.
- *Notes* (memory): the agent writes its conclusions to a file outside the window and reads them in a new session.
- *Subagents*: work happens in a separate context, and only the result comes back.
:::

id: "p6.5.e2"

question: "Match each agent problem with the technique that solves it."
pairs:
  - left: "The window is clogged with the contents of files the agent read and summarised long ago"
    right: "Tool result clearing"
    why: "These results can be fetched again just by reading the file once more. So they can be removed with no loss, keeping the record of the call."
  - left: "A long conversation full of reasoning and decisions is nearing the window limit"
    right: "Compaction"
    why: "Reasoning and decisions can't be “reread”, only retold. A summary keeps the substance and frees up space."
  - left: "Tomorrow the agent will start a new session and needs to pick up where it left off"
    right: "Notes in an external file"
    why: "Compaction and clearing work within a single session. A new session starts with an empty window, and only saved notes can help."
  - left: "A hundred pages of documentation need digging through, but the main agent only needs the bottom line"
    right: "Subagent"
    why: "A subagent works in its own clean context and returns a short result. The hundred pages never enter the main agent's window."
hint: "Ask yourself: can this data be fetched again? Is it needed after the session ends? Does the main agent need all of it, or just the bottom line?"
:::

::: step explain
In the API, compaction is configured as a context edit. You pass your own instructions in the `instructions` field:

```python
context_management={
    "edits": [{
        "type": "compact_20260112",
        "trigger": {"type": "input_tokens", "value": 150_000},
        "instructions": "Summarize this research agent transcript...",
    }]
}
```

Important: your own instructions completely *replace* the default ones rather than adding to them. So they need to describe everything that has to be kept.
:::

placeholder: "Summarise the conversation so that…"

  - "What the summary is for"
  - "What's been read, what's left"
  - "Figures with their source"
  - "Decisions and open questions"
  - "What can be dropped"
  - "What format to return the summary in"
min_chars: 80
hint: "Start with the summary's purpose: carrying on after compaction. List what must be kept (what's been read, figures with sources, decisions, next steps), what can be thrown away and what format to return it in."
review:
  task: "The learner writes custom compaction instructions for a research agent that compares eight reviews on three criteria and then writes a final comparison. Custom instructions fully replace the default ones, so they must be self-contained. Strong instructions: it's clear that a summary is needed to carry on working (R1); the purpose and task context are explained (R2); the summary format is specified: sections or a list, wrapped in tags such as <summary> (R3); criteria: what must be kept (which documents have been read and which remain, figures with their source, decisions made, open questions, next steps) and what can be dropped (full texts that can be reread) (R4)."
  criteria: ["R1", "R2", "R3", "R4"]
  reference_prompt: |
    Summarise this conversation so that work can continue after the history has been replaced with the summary. The agent's task: compare eight reviews on three criteria (lifespan, ease of experimentation, relevance to humans) and write a final comparison.
    Make sure you keep:
    1. Which reviews have already been read and which remain.
    2. Every figure for each criterion, noting which review it comes from.
    3. Decisions made about the structure of the comparison.
    4. Open questions and the next step.
    Don't copy out the full texts of the reviews or intermediate reasoning: the reviews can be read again. If you're unsure about a figure, flag it. Wrap the summary in <summary></summary> tags.
  show_reference: true
  fallback_feedback:
    - "Is it clear that the summary is for carrying on after compaction?"
    - "Is the state preserved: what's been read, what's left?"
    - "Do you ask for figures to be kept together with their source?"
    - "Are decisions, open questions and the next step included?"
    - "Does it say what can be dropped, such as full texts?"
    - "Is the summary format specified, for example <summary> tags?"
:::

::: step summary
**Keep the minimum in the window, but the most useful minimum.**

Clear what can be fetched again. Compact long conversations. Write knowledge that has to outlast the session to notes. Hand bulky work to a subagent.
