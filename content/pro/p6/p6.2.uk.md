::: step hook
Ольга будує систему для служби підтримки: листи надходять про оплату, доставку й повернення. Вона думає, чи не зробити «агента на всі випадки».

Але більшість систем на Claude збирають із п'яти простих схем. Їх називають *патернами* — перевіреними рішеннями типових завдань, як рецепти в кулінарії. Упізнати їх швидше, ніж винаходити заново.
:::

::: step explain
Перші три — найпростіші:

- *Ланцюжок* (prompt chaining): кроки по черзі, вихід одного — вхід наступного. Написати план → за планом текст → перекласти.
- *Маршрутизація* (routing): спершу визначити тип входу, потім надіслати до потрібного спеціалізованого промпту. Лист про повернення — до «повернень».
- *Паралельні виклики* (parallelization): незалежні підзадачі виконуються одночасно, результати збирають разом.
:::

::: step explain
Ланцюжок у коді — це просто цикл. Відповідь одного кроку стає входом наступного:

```python
def chain(text: str, prompts: list[str]) -> str:
    result = text
    for prompt in prompts:
        result = llm_call(f"{prompt}\nInput: {result}")
    return result
```

Тут `llm_call` — твоя функція, яка надсилає один запит до Claude і повертає текст.
:::

::: step explain
Ще два патерни складніші:

- *Оркестратор і виконавці* (orchestrator-workers): головний виклик сам розбирає завдання, вирішує, які потрібні підзадачі, і роздає їх виконавцям. Підзадачі наперед невідомі.
- *Генератор і оцінювач* (evaluator-optimizer): один виклик пише, інший перевіряє за критеріями й дає зауваження. Цикл повторюється, доки оцінювач не прийме результат.
:::

::: exercise match_pairs
id: "p6.2.e1"
type: "match_pairs"
question: "З'єднай завдання з патерном, який підходить найкраще."
pairs:
  - left: "Написати план статті, за планом — текст, потім скоротити до 300 слів"
    right: "Ланцюжок"
    why: "Кроки йдуть суворо по черзі, і кожен спирається на результат попереднього. Кожен крок простіший, його легше перевірити."
  - left: "Листи клієнтів: про оплату — в один промпт, про повернення — в інший"
    right: "Маршрутизація"
    why: "Спершу визначається тип входу, потім працює спеціалізований промпт. Кожен можна налаштувати під свою тему, не заважаючи іншим."
  - left: "Оцінити новий тариф очима трьох груп клієнтів, кожну окремо"
    right: "Паралельні виклики"
    why: "Три оцінки не залежать одна від одної, тож їх можна зробити одночасно й скласти результати. Це швидше, ніж по черзі."
  - left: "За описом товару вирішити, які тексти потрібні (сайт, соцмережі, розсилка), і написати кожен"
    right: "Оркестратор і виконавці"
    why: "Набір підзадач залежить від товару, і його обирає головний виклик. У цьому відмінність від паралельних викликів, де підзадачі відомі наперед."
  - left: "Писати код, перевіряти тестами й зауваженнями, виправляти, доки все не пройде"
    right: "Генератор і оцінювач"
    why: "Є чіткі критерії (тести), і зворотний зв'язок справді покращує результат. Класичний випадок для циклу «написав → перевірив → виправив»."
hint: "Шукай ключові ознаки: суворий порядок, вибір за типом, незалежні частини, підзадачі невідомі наперед, цикл із перевіркою."
:::

::: step summary
**П'ять патернів: ланцюжок, маршрутизація, паралельні виклики, оркестратор і виконавці, генератор і оцінювач.**

Їх можна поєднувати. Але кожен додає виклики, тож бери патерн, лише коли він помітно покращує результат.
