::: step hook
Megan is building a service for accountants: you upload a sales spreadsheet, and an agent crunches the numbers, draws charts and writes a report.

She has already built the agent on the Agent SDK, and it all works on her laptop. But now hundreds of clients will be using the service. Where will the agent run? Who's responsible for the servers, isolation and storing sessions?
:::

::: step explain
The key question is *who runs the agent loop*: “ask the model → run a tool → return the result”.

- **Client SDK** (the `anthropic` package): you write the loop yourself. Every model call and every tool is your code.
- **Agent SDK**: the loop and tools are ready-made, but they run in your process, on your servers.
- **Managed Agents**: Anthropic runs the loop and the sandbox, and you control them through the API.
:::

::: step explain
*Managed Agents* has three building blocks:

- **Agent**: the agent's settings: model, system prompt, tools.
- **Environment**: a container template: packages, network access.
- **Session**: a single run: it links the agent with the environment, attaches files and streams events.

You create the agent and the environment once, and start as many sessions as you need. It's currently in beta: in the API, it lives under `client.beta`.
:::

::: step summary
**The choice comes down to one question: “who runs the agent loop?”**

Client SDK: you do. Agent SDK: a ready-made library in your process. Managed Agents: Anthropic's platform.

Managed Agents is currently in beta, so check the details in the documentation before you launch.
