::: step hook
Dan is building review processing for an online shop: translate each review into English, tag the topic (delivery, quality, price) and add it to a spreadsheet.

He went straight for a “smart agent” with a dozen tools. The agent sometimes wanders off track, it's slow and it's expensive. Yet the steps are exactly the same every time.

Where did Dan go wrong?
:::

::: step explain
There are two ways to build a system on Claude.

A *workflow* has its path written in code up front: step 1, step 2, step 3. Claude does each step, but you decide the order. Think of an assembly line: every part travels along the same belt.

An *agent* lets Claude decide what to do next: which tool to call, what to check, when to stop. The path emerges as it works. Think of a mechanic tracking down the cause of a fault.
:::

::: exercise single_choice
id: "p6.1.e1"
type: "single_choice"
question: "What makes an agent different from a workflow?"
options:
  - text: "The model picks the next step based on what it has found, not the code"
    correct: true
    why: "Exactly. In a workflow, the order of steps is written in code in advance. An agent changes its own plan: it spots a database error in the logs, so it goes to look at the database instead of what was planned."
  - text: "An agent uses tools and a workflow doesn't"
    correct: false
    why: "A workflow step can call a tool too, for example a database lookup in step two. The difference isn't the tools, it's who picks the next step."
  - text: "An agent always produces better results"
    correct: false
    why: "Not always. On a task with repetitive steps, an agent can wander off, while a workflow follows a proven path. Quality depends on whether the setup fits the task."
  - text: "A workflow is one prompt to Claude and an agent is many"
    correct: false
    why: "A workflow almost always involves several calls: translate, then classify, then format. It's just that the order is set in code."
hint: "Ask yourself: who decides what the next step will be, the developer in advance or the model as it works?"
:::

::: exercise match_pairs
id: "p6.1.e2"
type: "match_pairs"
question: "Match each task with the simplest solution that can handle it."
pairs:
  - left: "Come up with 5 headlines for an article from the finished text"
    right: "One good prompt"
    why: "Everything needed is already in the text, and there's only one step. A chain or an agent would just add latency and cost."
  - left: "For each review: translate, tag the topic, add a row to the spreadsheet"
    right: "Workflow: steps set in code"
    why: "The steps are always the same and in the same order. This is Dan's case: an assembly line is more reliable and cheaper than an agent."
  - left: "Work out why a service went down overnight: logs, metrics, recent changes"
    right: "Agent"
    why: "You don't know in advance where to look: the next step depends on what turns up in the logs. The path emerges along the way, so it's a job for an agent."
hint: "For each task, ask: can you write out all the steps in advance? Do you even need more than one step?"
:::

::: step explain
How do you choose? Start simple and add complexity only if the simple option isn't good enough.

1. One good prompt.
2. Workflow: several calls, order set in code.
3. Agent: the model chooses the path.

Every extra call costs money and waiting time. It's only worth paying if quality noticeably improves.
:::

::: exercise multi_choice
id: "p6.1.e3"
type: "multi_choice"
question: "Which signs show that a task genuinely needs an agent? Select all that apply."
options:
  - text: "The answer isn't in the input: you have to search external systems"
    correct: true
    why: "Search, databases, APIs and so on. The agent decides where to look and when it has enough information."
  - text: "The next step depends on what was found in the previous one"
    correct: true
    why: "This is the key sign. A path like this can't be written in code in advance: it emerges during the investigation."
  - text: "The steps are always the same and in the same order"
    correct: false
    why: "That's a sign of a workflow. If you know the path, write it in code: it's more predictable, cheaper and easier to debug."
  - text: "You want the system to sound cutting-edge"
    correct: false
    why: "Hype isn't a reason. An agent adds cost, latency and the risk of going off track. You need a real reason."
  - text: "One prompt with good context solves the task"
    correct: false
    why: "Then one prompt is enough. You need neither a workflow nor an agent."
hint: "You need an agent where the path can't be written out in advance. Look for the options about an unknown path."
:::

::: exercise order_steps
id: "p6.1.e4"
type: "order_steps"
question: "Put these in order: how to add complexity to a system sensibly."
shuffle: true
items:
  - text: "Try one good prompt with context and format"
    why: "The cheapest and fastest option. It's often enough, and then you've lost nothing."
  - text: "Test the result on a few real examples"
    why: "Without testing, you can't tell whether you need more complexity. Decide on facts, not gut feeling."
  - text: "If it falls short, split the work into steps in code (workflow)"
    why: "Each step is simpler and easier to check. You're still in control of the order."
  - text: "If the path can't be set in advance, let the model choose the steps (agent)"
    why: "The last rung: flexible, but more expensive and less predictable. Take it deliberately."
hint: "Simplest first, then testing, and only then each next rung of complexity."
:::

::: step summary
**Workflow: the path is set in code. Agent: the model chooses the path.**

Start with one prompt, then a workflow, and only if the path can't be written out in advance, an agent. Complexity has to pay for itself in quality.

Next: five ready-made workflow patterns that most systems are built from.
:::
