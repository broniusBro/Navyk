::: step hook
Sam built an integration between his team's task tracker and Claude Desktop. A month later the team switched to Claude Code, and a month after that they asked for the same thing in their code editor.

Each time he rewrote the integration from scratch.

How do you build a connection once so it works everywhere?
:::

::: step explain
*MCP* (Model Context Protocol) is an open standard that lets AI applications connect to external systems: files, databases, APIs, workflows.

Its creators compare it to a USB-C port. Any USB-C cable fits any laptop. In the same way, an MCP server written once connects to Claude, ChatGPT, Visual Studio Code, Cursor and other applications.
:::

::: step explain
Every MCP setup has three roles:

- *Host* — the AI application a person works in: Claude Code, Claude Desktop, a code editor.
- *Client* — a component inside the host. For each server, the host creates a separate client with a dedicated connection.
- *Server* — a program that provides context and tools. It runs locally on your computer or remotely on the internet.
:::

::: step example
Here's an example from the MCP docs. Visual Studio Code is the host. A developer has connected two servers to it:

- a remote Sentry server with the app's errors;
- a local filesystem server.

Two clients appear inside VS Code: one keeps the connection to Sentry, the other to the filesystem. The clients don't mix with each other.
:::

::: step explain
An important security principle: a server only receives what it needs for the request.

The full conversation history stays with the host. A server can't read the whole chat and can't “see into” other servers. The host controls any interaction between servers.

So a weather server will never find out what you discussed with your bank's server.
:::

::: step summary
**MCP is an open standard for connecting AI applications to external systems: “USB-C for AI”.**

The host is the application a person works in. The client is a host component, one per server. The server is a program with data and tools, local or remote.

This lesson is based on MCP specification version {{data.versions.pfive_mcp_spec}}. Next: what exactly a server can offer the host.
:::
