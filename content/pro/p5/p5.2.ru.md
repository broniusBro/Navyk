::: step hook
Ирина делает MCP-сервер для базы данных интернет-магазина. Ей нужно, чтобы:

- Claude сам находил заказы по запросу;
- схема таблиц всегда была под рукой;
- менеджер одним выбором запускал готовый сценарий «Отчёт за неделю».

Это три разные вещи. В MCP для них есть три разных *примитива*.
:::

::: step explain
Сервер может дать хосту три примитива. Различаются они тем, кто решает, когда их использовать:

- *Tools* (инструменты) — решает модель. Функции, которые Claude вызывает сам: найти заказ, создать задачу.
- *Resources* (ресурсы) — решает приложение. Данные для контекста: содержимое файла, схема базы.
- *Prompts* (шаблоны) — решает пользователь. Готовые сценарии, которые человек выбирает сам, например как slash-команду.
:::

::: step example
Сервер Ирины в терминах MCP:

- инструмент `find_orders` — Claude вызывает его, когда спрашивают про заказы (метод `tools/call`);
- ресурс со схемой таблиц — хост подкладывает его в контекст (метод `resources/read`);
- шаблон «Отчёт за неделю» — менеджер выбирает его из меню (метод `prompts/get`).

Хост узнаёт, что есть на сервере, через методы `tools/list`, `resources/list` и `prompts/list`.
:::

::: step explain
У клиента тоже есть возможности для сервера. Главная — *elicitation* (запрос данных у пользователя).

Сервер посреди работы понимает, что ему не хватает данных, например места в самолёте. Хост показывает человеку форму. Человек может ответить, отказаться или отменить всю операцию.

Есть два режима: *form* (форма в хосте) и *URL* (человек переходит по ссылке).
:::

::: step explain
Правило спецификации: в режиме form нельзя запрашивать пароли, API-ключи, токены и платёжные данные.

Для них есть режим URL: человек сам вводит данные на странице сервиса. Они не проходят через хост и не попадают в контекст модели.

Claude Code показывает такие запросы автоматически, настраивать ничего не нужно.
:::

::: step explain
⚠️ В спецификации {{data.versions.pfive_mcp_spec}} три возможности объявлены устаревшими (*deprecated*):

- *sampling* — сервер просит хост сгенерировать ответ модели;
- *roots* — хост сообщает серверу, с какими папками работать;
- *logging* — сервер шлёт логи клиенту по протоколу.

Пока они работают, но новые реализации не должны их добавлять. По политике протокола окно устаревания — минимум 12 месяцев.
:::

::: step summary
**Tools вызывает модель, resources подкладывает приложение, prompts выбирает пользователь.**

Elicitation — способ сервера спросить человека. Секреты запрашивай только через URL-режим.

В спецификации {{data.versions.pfive_mcp_spec}} устарели sampling, roots и logging. Новые серверы на них не строй.
:::
