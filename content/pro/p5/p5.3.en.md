::: step hook
Emma wrote an MCP server, and it works perfectly in Claude Desktop on her laptop.

Her colleagues added the same server to claude.ai, and it won't connect. Same code, no bugs in it.

The problem isn't the code, it's the *transport*: the way the client and server pass messages to each other.
:::

::: step explain
MCP messages mean the same thing everywhere. The transport only handles delivery. There are two standard transports:

- *stdio*. The client itself launches the server as a process on the same computer and talks to it over standard input and output. No network needed.
- *Streamable HTTP*. The server runs separately, for example in the cloud, and accepts HTTP requests at a single address such as `https://example.com/mcp`. Many clients share one server.
:::

::: step example
Why didn't it work for Emma's colleagues? Claude.ai connects to servers from Anthropic's cloud, not from your laptop. So a server for claude.ai has to be remote and reachable from the internet.

Emma's server ran over stdio: Claude Desktop started it as a process on her computer. The cloud has no way to start a process on someone else's laptop.
:::

::: step explain
Each transport has its own traps.

**Stdio.** The stdout channel is reserved for protocol messages. Any stray `print()` to stdout breaks the connection. Write logs to stderr.

**Streamable HTTP.** The server must validate the `Origin` header; otherwise a website in the browser could reach a local server (a DNS rebinding attack). A local HTTP server listens only on `127.0.0.1`, not `0.0.0.0`. And authentication is always required.
:::

::: step explain
⚠️ In the {{data.versions.pfive_mcp_spec}} specification, the protocol became *stateless*:

- no sessions and no `Mcp-Session-Id` header;
- no `initialize` handshake: each request carries the protocol version and client capabilities itself;
- the server must respond to `server/discover`, describing its versions and capabilities.

The old HTTP+SSE transport (version 2024-11-05) is deprecated and has been replaced by Streamable HTTP.
:::

::: step summary
**Local and for one person: stdio. Remote and for many: Streamable HTTP with authentication (OAuth recommended).**

With stdio, don't write to stdout. With HTTP, validate Origin and don't expose a local server to the whole network.

The {{data.versions.pfive_mcp_spec}} specification has no sessions or initialize, and HTTP+SSE is deprecated.
:::
