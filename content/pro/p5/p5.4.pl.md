::: step hook
Bartek pyta Claude, ile dni zostało do deadline'u. Czasem odpowiedź jest niedokładna: model może nie znać dzisiejszej daty albo pomylić się w liczeniu.

Liczenie dat to zadanie dla zwykłego kodu. Można więc dać Claude narzędzie, które zrobi to dokładnie.

Zbudujmy taki serwer MCP w Pythonie: jedno narzędzie, około 20 linii.
:::

::: step explain
Robimy według oficjalnego przewodnika MCP dla wersji {{data.versions.pfive_mcp_spec}}. Potrzebne będą Python 3.10+ i menedżer pakietów `uv`. Python SDK MCP — w wersji {{data.versions.pfive_python_sdk_min}} lub nowszej.

```bash
uv init deadlines
cd deadlines
uv venv
source .venv/bin/activate
uv add "mcp[cli]"
```

⚠️ W tutorialach sprzed 2026 roku import jest inny (`FastMCP`). Porównuj kod z wersją SDK.
:::

::: step example
Plik `server.py`:

```python
from datetime import date

from mcp.server import MCPServer

mcp = MCPServer("deadlines")


@mcp.tool()
def days_until(deadline: str) -> str:
    """Count days from today to a deadline.

    Args:
        deadline: Date in YYYY-MM-DD format, e.g. 2026-12-31
    """
    try:
        target = date.fromisoformat(deadline)
    except ValueError:
        return "Invalid date. Use YYYY-MM-DD, e.g. 2026-12-31."
    return f"{(target - date.today()).days} days left until {deadline}."


if __name__ == "__main__":
    mcp.run(transport="stdio")
```
:::

::: step explain
Co jest tu ważne:

- `@mcp.tool()` zamienia funkcję w narzędzie MCP;
- nazwa funkcji staje się nazwą narzędzia, a podpowiedzi typów — schematem parametrów;
- docstring staje się opisem. To właśnie go czyta Claude, kiedy decyduje, czy wywołać narzędzie;
- `transport="stdio"` — serwer do uruchamiania lokalnie.

I zasada z poprzedniej lekcji: żadnych `print()`. Do logów jest moduł `logging`, który pisze do stderr.
:::

::: step explain
Podłączamy do Claude Code. Wszystko po `--` to polecenie, którym Claude Code uruchomi serwer:

```bash
claude mcp add --transport stdio deadlines -- uv --directory /ABSOLUTE/PATH/deadlines run server.py
```

Status sprawdzisz poleceniem `/mcp` w Claude Code. W Claude Desktop to samo wpisuje się do `claude_desktop_config.json`, w sekcji `mcpServers`.

Bez hosta serwer można przetestować w MCP Inspector: `npx @modelcontextprotocol/inspector`.
:::

question: "To pierwsza wersja narzędzia Marty. Kliknij linie, przez które serwer się zepsuje albo Claude nie zrozumie, kiedy wywołać narzędzie."
prompt: "@mcp.tool()\ndef calc(d):\n    print(\"called\", d)\n    \"\"\"Does stuff.\"\"\"\n    return (date.fromisoformat(d) - date.today()).days\n"
segments:
  - text: "@mcp.tool()\n"
    weak: false
    why: "Dekorator jest na miejscu: funkcja stanie się narzędziem MCP."
  - text: "def calc(d):\n"
    weak: true
    why: "Nazwa calc i parametr d nic Claude nie mówią, a bez podpowiedzi typu schemat parametru będzie pusty. Lepiej: days_until(deadline: str) -> str."
  - text: "    print(\"called\", d)\n"
    weak: true
    why: "print() pisze do stdout, a w serwerze stdio ten kanał jest zajęty przez protokół. To wywołanie zepsuje JSON-RPC. Logi — przez logging, który pisze do stderr."
  - text: "    \"\"\"Does stuff.\"\"\"\n"
    weak: true
    why: "Dwa problemy. Taki docstring nie mówi, co robi narzędzie ani w jakim formacie jest data. Do tego stoi po print(), a Python uznaje za docstring tylko pierwszą instrukcję w ciele funkcji, więc opisu nie będzie wcale."
  - text: "    return (date.fromisoformat(d) - date.today()).days\n"
    weak: false
    why: "Sama logika jest poprawna. Można dodać zrozumiały komunikat dla złego formatu daty, jak w przykładzie z lekcji."
hint: "Sprawdź każdą linię: czy nazwa jest zrozumiała, czy kod nie pisze do stdout i czy Claude dostaje porządny opis."
:::

::: step summary
**Serwer MCP w Pythonie to funkcja z `@mcp.tool()`, podpowiedziami typów i dobrym docstringiem plus `mcp.run(transport="stdio")`.**

Podłączaj poleceniem `claude mcp add ... -- <polecenie uruchomienia>`, podawaj ścieżkę bezwzględną i nie pisz do stdout.
