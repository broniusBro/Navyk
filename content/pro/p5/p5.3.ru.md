::: step hook
Ирина написала MCP-сервер, и в Claude Desktop на её ноутбуке он работает отлично.

Коллеги добавили тот же сервер в claude.ai, и он не подключается. Код одинаковый, ошибок в нём нет.

Дело не в коде, а в *транспорте*: в способе, которым клиент и сервер передают друг другу сообщения.
:::

::: step explain
Смысл сообщений MCP одинаков везде. Транспорт задаёт только доставку. Стандартных транспортов два:

- *stdio*. Клиент сам запускает сервер как процесс на том же компьютере и общается через стандартный ввод и вывод. Сеть не нужна.
- *Streamable HTTP*. Сервер работает отдельно, например в облаке, и принимает HTTP-запросы на один адрес вида `https://example.com/mcp`. Одним сервером пользуются многие клиенты.
:::

::: step example
Почему у коллег Ирины не заработало? Claude.ai подключается к серверам из облака Anthropic, а не с твоего ноутбука. Поэтому сервер для claude.ai должен быть удалённым и доступным из интернета.

Сервер Ирины запускался через stdio: Claude Desktop стартовал его как процесс у неё на компьютере. Облаку запустить процесс на чужом ноутбуке нечем.
:::

::: step explain
У каждого транспорта свои ловушки.

**Stdio.** Канал stdout занят сообщениями протокола. Любой лишний `print()` в stdout ломает связь. Логи пиши в stderr.

**Streamable HTTP.** Сервер должен проверять заголовок `Origin`, иначе сайт в браузере сможет обратиться к локальному серверу (атака DNS rebinding). Локальный HTTP-сервер слушает только `127.0.0.1`, а не `0.0.0.0`. И всегда нужна аутентификация.
:::

::: step explain
⚠️ В спецификации {{data.versions.pfive_mcp_spec}} протокол стал *без состояния* (stateless):

- нет сессий и заголовка `Mcp-Session-Id`;
- нет рукопожатия `initialize`: каждый запрос сам несёт версию протокола и возможности клиента;
- сервер обязан отвечать на `server/discover`, рассказывая о своих версиях и возможностях.

Старый транспорт HTTP+SSE (версия 2024-11-05) устарел, на смену ему пришёл Streamable HTTP.
:::

    why: "Правильно: stderr — разрешённый канал для логов stdio-сервера, протоколу он не мешает."

::: step summary
**Локально и для одного человека — stdio. Удалённо и для многих — Streamable HTTP с аутентификацией (рекомендуется OAuth).**

В stdio не пиши в stdout. В HTTP проверяй Origin и не открывай локальный сервер всей сети.

В спецификации {{data.versions.pfive_mcp_spec}} нет сессий и initialize, а HTTP+SSE устарел.
:::
