::: step hook
Martha has a remote MCP server for her company's knowledge base: `https://kb.example.com/mcp`.

It's needed in three places at once: in Claude Code for the developers, in claude.ai for the support team, and in the backend of a chatbot that runs on the Claude API.

One server, four ways to connect it. Let's go through each.
:::

::: step explain
**Claude Code.** A remote server is added with one command; status and OAuth sign-in are in `/mcp` (details in lesson p2.5):

```bash
claude mcp add --transport http kb https://kb.example.com/mcp
```

A local server is added with `--` and its launch command, as in the previous lesson.

If you're signed in to Claude Code with your claude.ai account, your claude.ai connectors show up in Claude Code automatically.
:::

::: step explain
**Claude Desktop, local servers.** These go in `claude_desktop_config.json`, under `mcpServers`: the launch command and its arguments. After editing, fully quit the app and open it again.

Important: local servers like these only work in Claude Desktop on that computer. They're not available in claude.ai or Cowork.
:::

::: step explain
**Claude.ai: custom connector.** You need a remote server. The path is {{data.ui_paths.pfive_customize_connectors}}, then {{data.ui_paths.pfive_add_custom}}, and paste the URL. OAuth details, if needed, go in {{data.ui_paths.pfive_advanced_settings}}.

Plans: {{data.plans.pfive_custom_plans}}. On Free you can add {{data.plans.pfive_free_custom_max}} custom connector. In Team and Enterprise, {{data.plans.pfive_team_custom_who}} can add them.

Claude connects from Anthropic's cloud, so the server has to be reachable from the internet.
:::

::: step example
**Claude API: MCP connector.** You don't need to write your own MCP client: the server is specified right in the Messages API request. The feature is in beta and needs the `anthropic-beta` header.

```bash
curl https://api.anthropic.com/v1/messages \
  -H "Content-Type: application/json" \
  -H "X-API-Key: $ANTHROPIC_API_KEY" \
  -H "anthropic-version: 2023-06-01" \
  -H "anthropic-beta: {{data.versions.pfive_api_beta}}" \
  -d '{
    "model": "{{data.models.pfive_example_model_id}}",
    "max_tokens": 1000,
    "messages": [{"role": "user", "content": "How do I return an item?"}],
    "mcp_servers": [{
      "type": "url",
      "url": "https://kb.example.com/mcp",
      "name": "kb",
      "authorization_token": "YOUR_TOKEN"
    }],
    "tools": [{"type": "mcp_toolset", "mcp_server_name": "kb"}]
  }'
```
:::

::: step explain
What to know about the MCP connector:

- of all MCP features, only tool calls are supported;
- the server must be reachable from the internet over HTTP, with an address starting with `https://`. A local stdio server can't be connected directly;
- you obtain and refresh the OAuth token yourself and pass it in `authorization_token`;
- the response contains `mcp_tool_use` and `mcp_tool_result` blocks.
:::

  - text: "He forgot to specify a model that supports MCP"

    why: "The model isn't the problem. The API reaches the server over the network, and a stdio server on a laptop has no network address."
  - text: "In the API you first have to call server/discover manually"
    correct: false
    why: "The MCP connector handles the exchange with the server. Here the server simply can't be reached over the network."
  - text: "He also needs to add the server to claude_desktop_config.json"
    correct: false
    why: "That file configures Claude Desktop on a specific computer. It has nothing to do with API requests."

::: step summary
**Claude Code: `claude mcp add`. Claude Desktop: local servers in `claude_desktop_config.json`. Claude.ai: a custom connector using the remote server's URL. API: the MCP connector, `mcp_servers` plus `mcp_toolset`.**

For claude.ai and the API, the server must be reachable from the internet. Only connect servers you trust.
:::
