::: step hook
Ірина робить MCP-сервер для бази даних інтернет-крамниці. Їй потрібно, щоб:

- Claude сам знаходив замовлення за запитом;
- схема таблиць завжди була під рукою;
- менеджер одним вибором запускав готовий сценарій «Звіт за тиждень».

Це три різні речі. У MCP для них є три різні *примітиви*.
:::

::: step explain
Сервер може дати хосту три примітиви. Різняться вони тим, хто вирішує, коли їх використовувати:

- *Tools* (інструменти) — вирішує модель. Функції, які Claude викликає сам: знайти замовлення, створити задачу.
- *Resources* (ресурси) — вирішує застосунок. Дані для контексту: вміст файлу, схема бази.
- *Prompts* (шаблони) — вирішує користувач. Готові сценарії, які людина вибирає сама, наприклад як slash-команду.
:::

::: step example
Сервер Ірини в термінах MCP:

- інструмент `find_orders` — Claude викликає його, коли питають про замовлення (метод `tools/call`);
- ресурс зі схемою таблиць — хост додає його в контекст (метод `resources/read`);
- шаблон «Звіт за тиждень» — менеджер вибирає його з меню (метод `prompts/get`).

Хост дізнається, що є на сервері, через методи `tools/list`, `resources/list` і `prompts/list`.
:::

::: step explain
Клієнт теж має можливості для сервера. Головна — *elicitation* (запит даних у користувача).

Сервер посеред роботи розуміє, що йому бракує даних, наприклад місця в літаку. Хост показує людині форму. Людина може відповісти, відмовитися або скасувати всю операцію.

Є два режими: *form* (форма в хості) і *URL* (людина переходить за посиланням).
:::

::: step explain
Правило специфікації: у режимі form не можна запитувати паролі, API-ключі, токени й платіжні дані.

Для них є режим URL: людина сама вводить дані на сторінці сервісу. Вони не проходять через хост і не потрапляють у контекст моделі.

Claude Code показує такі запити автоматично, нічого налаштовувати не треба.
:::

::: step explain
⚠️ У специфікації {{data.versions.pfive_mcp_spec}} три можливості оголошено застарілими (*deprecated*):

- *sampling* — сервер просить хост згенерувати відповідь моделі;
- *roots* — хост повідомляє серверу, з якими теками працювати;
- *logging* — сервер надсилає логи клієнту через протокол.

Поки що вони працюють, але нові реалізації не повинні їх додавати. За політикою протоколу вікно застарівання — щонайменше 12 місяців.
:::

::: step summary
**Tools викликає модель, resources додає застосунок, prompts вибирає користувач.**

Elicitation — спосіб сервера запитати людину. Секрети запитуй тільки через URL-режим.

У специфікації {{data.versions.pfive_mcp_spec}} застаріли sampling, roots і logging. Нових серверів на них не будуй.
:::
