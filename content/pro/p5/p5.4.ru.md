::: step hook
Богдан спрашивает Claude, сколько дней осталось до дедлайна. Иногда ответ неточный: модель может не знать сегодняшнюю дату или ошибиться в подсчёте.

Посчитать даты может обычный код. Значит, можно дать Claude инструмент, который делает это точно.

Соберём такой MCP-сервер на Python: один инструмент, около 20 строк.
:::

::: step explain
Делаем по официальному гайду MCP для версии {{data.versions.pfive_mcp_spec}}. Понадобятся Python 3.10+ и менеджер пакетов `uv`. Python SDK MCP — версии {{data.versions.pfive_python_sdk_min}} или новее.

```bash
uv init deadlines
cd deadlines
uv venv
source .venv/bin/activate
uv add "mcp[cli]"
```

⚠️ В туториалах до 2026 года импорт другой (`FastMCP`). Сверяй код с версией SDK.
:::

::: step example
Файл `server.py`:

```python
from datetime import date

from mcp.server import MCPServer

mcp = MCPServer("deadlines")


@mcp.tool()
def days_until(deadline: str) -> str:
    """Count days from today to a deadline.

    Args:
        deadline: Date in YYYY-MM-DD format, e.g. 2026-12-31
    """
    try:
        target = date.fromisoformat(deadline)
    except ValueError:
        return "Invalid date. Use YYYY-MM-DD, e.g. 2026-12-31."
    return f"{(target - date.today()).days} days left until {deadline}."


if __name__ == "__main__":
    mcp.run(transport="stdio")
```
:::

::: step explain
Что здесь важно:

- `@mcp.tool()` превращает функцию в инструмент MCP;
- имя функции становится именем инструмента, а подсказки типов — схемой параметров;
- docstring становится описанием. Именно его читает Claude, когда решает, вызывать ли инструмент;
- `transport="stdio"` — сервер для локального запуска.

И правило из прошлого урока: никаких `print()`. Для логов есть модуль `logging`, он пишет в stderr.
:::

::: step explain
Подключаем к Claude Code. Всё после `--` — команда, которой Claude Code запустит сервер:

```bash
claude mcp add --transport stdio deadlines -- uv --directory /ABSOLUTE/PATH/deadlines run server.py
```

Проверить статус можно командой `/mcp` внутри Claude Code. Для Claude Desktop то же самое пишется в `claude_desktop_config.json`, в раздел `mcpServers`.

Без хоста сервер можно погонять в MCP Inspector: `npx @modelcontextprotocol/inspector`.
:::

prompt: "@mcp.tool()\ndef calc(d):\n    print(\"called\", d)\n    \"\"\"Does stuff.\"\"\"\n    return (date.fromisoformat(d) - date.today()).days\n"
segments:
  - text: "@mcp.tool()\n"
    weak: false
    why: "Декоратор на месте: функция станет инструментом MCP."
  - text: "def calc(d):\n"
    weak: true
    why: "Имя calc и параметр d ничего не говорят Claude, а без подсказки типа схема параметра получится пустой. Лучше days_until(deadline: str) -> str."
  - text: "    print(\"called\", d)\n"
    weak: true
    why: "print() пишет в stdout, а в stdio-сервере этот канал занят протоколом. Вызов сломает JSON-RPC. Логи — через logging, он пишет в stderr."
  - text: "    \"\"\"Does stuff.\"\"\"\n"
    weak: true
    why: "Две беды. Такой docstring не говорит, что делает инструмент и в каком формате дата. К тому же он стоит после print(), а Python считает docstring только первую строку тела функции, так что описания не будет вовсе."
  - text: "    return (date.fromisoformat(d) - date.today()).days\n"
    weak: false
    why: "Сама логика верная. Можно добавить понятное сообщение для неверного формата даты, как в примере урока."
hint: "Проверь каждую строку: понятно ли имя, не пишет ли код в stdout и есть ли у Claude нормальное описание."

::: step summary
**MCP-сервер на Python — это функция с `@mcp.tool()`, подсказками типов и хорошим docstring плюс `mcp.run(transport="stdio")`.**

Подключай командой `claude mcp add ... -- <команда запуска>`, указывай абсолютный путь и не пиши в stdout.
