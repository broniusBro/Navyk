::: step hook
Тарас написал интеграцию своего таск-трекера с Claude Desktop. Через месяц команда пересела на Claude Code, а ещё через месяц попросила то же самое в редакторе кода.

Каждый раз он переписывал интеграцию заново.

Как сделать подключение один раз, чтобы оно работало везде?
:::

::: step explain
*MCP* (Model Context Protocol) — открытый стандарт, по которому ИИ-приложения подключаются к внешним системам: файлам, базам данных, API, рабочим процессам.

Создатели протокола сравнивают его с портом USB-C. Любой USB-C-кабель подходит к любому ноутбуку. Так и MCP-сервер, написанный один раз, подключается к Claude, ChatGPT, Visual Studio Code, Cursor и другим приложениям.
:::

::: step explain
В любой MCP-схеме три роли:

- *Хост* (host) — ИИ-приложение, с которым работает человек: Claude Code, Claude Desktop, редактор кода.
- *Клиент* (client) — компонент внутри хоста. На каждый сервер хост создаёт отдельного клиента с выделенным подключением.
- *Сервер* (server) — программа, которая даёт контекст и инструменты. Работает локально на твоём компьютере или удалённо в интернете.
:::

::: step example
Пример из документации MCP. Visual Studio Code — хост. Разработчик подключил к нему два сервера:

- удалённый сервер Sentry с ошибками приложения;
- локальный сервер файловой системы.

Внутри VS Code появляются два клиента: один держит связь с Sentry, второй — с файловой системой. Клиенты друг с другом не смешиваются.
:::

::: step explain
Важный принцип безопасности: сервер получает только то, что ему нужно для запроса.

Полная история разговора остаётся у хоста. Сервер не может прочитать весь чат и не может «заглянуть» в другие серверы. Взаимодействие между серверами контролирует хост.

Поэтому сервер погоды не узнает, о чём ты переписывался с сервером банка.
:::

::: step summary
**MCP — открытый стандарт подключения ИИ-приложений к внешним системам, «USB-C для ИИ».**

Хост — приложение, с которым работает человек. Клиент — компонент хоста, по одному на сервер. Сервер — программа с данными и инструментами, локальная или удалённая.

Урок опирается на спецификацию MCP версии {{data.versions.pfive_mcp_spec}}. Дальше: что именно сервер может дать хосту.
:::
