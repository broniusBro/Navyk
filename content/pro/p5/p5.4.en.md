::: step hook
Ben asks Claude how many days are left until a deadline. Sometimes the answer is off: the model may not know today's date, or may miscount.

Counting dates is something ordinary code can do. So you can give Claude a tool that does it precisely.

Let's build that MCP server in Python: one tool, about 20 lines.
:::

::: step explain
We'll follow the official MCP guide for version {{data.versions.pfive_mcp_spec}}. You'll need Python 3.10+ and the `uv` package manager. The MCP Python SDK must be version {{data.versions.pfive_python_sdk_min}} or newer.

```bash
uv init deadlines
cd deadlines
uv venv
source .venv/bin/activate
uv add "mcp[cli]"
```

⚠️ Tutorials from before 2026 use a different import (`FastMCP`). Check the code against your SDK version.
:::

::: step example
The `server.py` file:

```python
from datetime import date

from mcp.server import MCPServer

mcp = MCPServer("deadlines")


@mcp.tool()
def days_until(deadline: str) -> str:
    """Count days from today to a deadline.

    Args:
        deadline: Date in YYYY-MM-DD format, e.g. 2026-12-31
    """
    try:
        target = date.fromisoformat(deadline)
    except ValueError:
        return "Invalid date. Use YYYY-MM-DD, e.g. 2026-12-31."
    return f"{(target - date.today()).days} days left until {deadline}."


if __name__ == "__main__":
    mcp.run(transport="stdio")
```
:::

::: step explain
What matters here:

- `@mcp.tool()` turns the function into an MCP tool;
- the function name becomes the tool name, and the type hints become the parameter schema;
- the docstring becomes the description. That's exactly what Claude reads when deciding whether to call the tool;
- `transport="stdio"` makes it a server for running locally.

And the rule from the last lesson: no `print()`. For logs there's the `logging` module, which writes to stderr.
:::

::: step explain
Now connect it to Claude Code. Everything after `--` is the command Claude Code will use to launch the server:

```bash
claude mcp add --transport stdio deadlines -- uv --directory /ABSOLUTE/PATH/deadlines run server.py
```

You can check the status with the `/mcp` command inside Claude Code. For Claude Desktop, the same thing goes into `claude_desktop_config.json`, under `mcpServers`.

To try the server out without a host, use MCP Inspector: `npx @modelcontextprotocol/inspector`.
:::

::: exercise find_error
id: "p5.4.e2"
type: "find_error"
question: "This is Martha's first version of the tool. Tap the lines that will break the server or leave Claude unsure when to call the tool."
prompt: "@mcp.tool()\ndef calc(d):\n    print(\"called\", d)\n    \"\"\"Does stuff.\"\"\"\n    return (date.fromisoformat(d) - date.today()).days\n"
segments:
  - text: "@mcp.tool()\n"
    weak: false
    why: "The decorator is in place: the function will become an MCP tool."
  - text: "def calc(d):\n"
    weak: true
    why: "The name calc and the parameter d tell Claude nothing, and without a type hint the parameter schema will be empty. Better: days_until(deadline: str) -> str."
  - text: "    print(\"called\", d)\n"
    weak: true
    why: "print() writes to stdout, and in a stdio server that channel is reserved for the protocol. This call will break JSON-RPC. Log with logging, which writes to stderr."
  - text: "    \"\"\"Does stuff.\"\"\"\n"
    weak: true
    why: "Two problems. This docstring doesn't say what the tool does or what format the date is in. On top of that, it comes after print(), and Python only treats the first statement in the function body as the docstring, so there will be no description at all."
  - text: "    return (date.fromisoformat(d) - date.today()).days\n"
    weak: false
    why: "The logic itself is fine. You could add a clear message for an invalid date format, as in the lesson's example."
hint: "Check each line: is the name clear, does the code write to stdout, and does Claude get a proper description?"
:::

::: step summary
**A Python MCP server is a function with `@mcp.tool()`, type hints and a good docstring, plus `mcp.run(transport="stdio")`.**

Connect it with `claude mcp add ... -- <launch command>`, use an absolute path, and don't write to stdout.
