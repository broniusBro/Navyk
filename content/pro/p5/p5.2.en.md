::: step hook
Emma is building an MCP server for an online shop's database. She wants:

- Claude to find orders on request by itself;
- the table schema to always be at hand;
- a manager to launch a ready-made “Weekly report” workflow with one click.

These are three different things. MCP has three different *primitives* for them.
:::

::: step explain
A server can offer the host three primitives. They differ in who decides when to use them:

- *Tools* — the model decides. Functions Claude calls by itself: find an order, create a task.
- *Resources* — the application decides. Data for context: a file's contents, a database schema.
- *Prompts* (templates) — the user decides. Ready-made workflows a person picks themselves, for example as a slash command.
:::

::: step example
Emma's server in MCP terms:

- the `find_orders` tool — Claude calls it when someone asks about orders (method `tools/call`);
- a resource with the table schema — the host adds it to the context (method `resources/read`);
- the “Weekly report” template — the manager picks it from a menu (method `prompts/get`).

The host finds out what the server offers through the `tools/list`, `resources/list` and `prompts/list` methods.
:::

::: step explain
The client has features for the server too. The main one is *elicitation* (requesting data from the user).

Partway through a task, the server realises it's missing some data, such as a seat on a plane. The host shows the person a form. The person can respond, decline, or cancel the whole operation.

There are two modes: *form* (a form in the host) and *URL* (the person follows a link).
:::

::: step explain
A rule from the specification: in form mode you must not ask for passwords, API keys, tokens or payment details.

URL mode exists for those: the person enters the data on the service's own page. It never passes through the host or reaches the model's context.

Claude Code shows these requests automatically; there's nothing to configure.
:::

    correct: false

:::

::: step explain
⚠️ The {{data.versions.pfive_mcp_spec}} specification marks three features as *deprecated*:

- *sampling* — the server asks the host to generate a model response;
- *roots* — the host tells the server which folders to work with;
- *logging* — the server sends logs to the client over the protocol.

They still work for now, but new implementations should not add them. Under the protocol's policy, the deprecation window is at least 12 months.
:::

::: step summary
**The model calls tools, the application attaches resources, the user picks prompts.**

Elicitation is how a server asks the person something. Only ever request secrets through URL mode.

The {{data.versions.pfive_mcp_spec}} specification deprecates sampling, roots and logging. Don't build new servers on them.
:::
