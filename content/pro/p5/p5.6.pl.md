::: step hook
Tomek opakował API swojego CRM w serwer MCP: 30 narzędzi, po jednym na każdy endpoint.

Claude się gubi. Żeby znaleźć klienta, wywołuje `list_contacts`, dostaje wszystkie 5000 kontaktów i kontekst się zapycha. Potem wywołuje `get` z parametrem `user` i przekazuje imię zamiast ID.

Serwer działa, ale agentowi pracuje się z nim źle. Zobaczmy, jak to naprawić.
:::

::: step explain
Narzędzie to nie nakładka na endpoint API, tylko działanie dopasowane do zadania agenta.

- Zamiast `list_contacts`, które zwraca wszystkich, zrób `search_contacts`: agent potrzebuje jednego klienta, a nie tysięcy.
- Zamiast trzech wywołań „znajdź wolny termin, sprawdź uczestników, utwórz spotkanie” — jedno `schedule_event`, które zrobi wszystko samo.

Więcej narzędzi nie znaczy lepiej.
:::

::: step explain
Nazwa i parametry:

- Grupuj narzędzia prefiksem usługi: `asana_search`, `jira_search`. Wtedy ich nie pomylisz, jeśli dwa serwery mają własne `search`.
- Nazywaj parametry jednoznacznie: `user_id`, a nie `user`.

Opis pisz tak, jakbyś tłumaczył zadanie nowemu pracownikowi: co robi narzędzie, kiedy po nie sięgać, co znaczą parametry, co zwróci i czego nie potrafi. To taki sam prompt jak każdy inny.
:::

::: step example
Według danych Anthropic precyzyjne poprawki *opisów narzędzi* pomogły Claude Sonnet 3.5 osiągnąć najlepszy wynik w benchmarku SWE-bench Verified: błędów było wyraźnie mniej.

Model był ten sam. Zmieniły się tylko teksty, na podstawie których wybiera i wywołuje narzędzia.
:::

::: exercise find_error
id: "p5.6.e2"
type: "find_error"
question: "To opis narzędzia z serwera Tomka. Kliknij wszystkie fragmenty, na których Claude się potknie."
prompt: "get: Gets data. Param user: the user. Returns everything about the user in JSON. Use for CRM tasks."
segments:
  - text: "get: "
    weak: true
    why: "Nazwa get nic nie mówi, a narzędzie o tej samej nazwie może być na innym serwerze. Lepiej: crm_get_contact."
  - text: "Gets data. "
    weak: true
    why: "Jakie dane? Opis powinien mówić konkretnie: „Zwraca kartę kontaktu z CRM po jego ID”."
  - text: "Param user: the user. "
    weak: true
    why: "Nie wiadomo, co przekazać: imię, e-mail czy ID. Stąd błąd z historii Tomka. Potrzebne są user_id i format z przykładem."
  - text: "Returns everything about the user in JSON. "
    weak: true
    why: "„Wszystko” oznacza dużo tokenów i mało pożytku. Lepiej zwrócić to, co najważniejsze: imię i nazwisko, firmę, telefon, ostatnią transakcję, a szczegóły podawać na żądanie."
  - text: "Use for CRM tasks."
    weak: true
    why: "Zbyt ogólnie: do „zadań CRM” pasuje wszystkie 30 narzędzi. Napisz, kiedy dokładnie wywołać to, np. „gdy ID kontaktu jest już znane; do wyszukiwania po nazwisku użyj crm_search_contacts”."
hint: "Przeczytaj opis oczami nowego pracownika: co robi narzędzie, co przekazać, co dostaniesz i kiedy po nie sięgnąć?"
:::

::: step explain
Odpowiedź narzędzia też czyta model, a każdy token zajmuje jego kontekst. Dlatego:

- zwracaj to, co najważniejsze, a nie wszystko, i czytelne nazwy zamiast UUID;
- daj wybór szczegółowości, np. parametr `response_format` z wartościami `concise` i `detailed`;
- stosuj paginację, filtry i rozsądne limity domyślne.

Claude Code ostrzega o wyniku większym niż {{data.limits.pfive_cc_output_warn}} i domyślnie przycina go do {{data.limits.pfive_cc_output_max}}. W claude.ai i Desktop limit wyniku to {{data.limits.pfive_web_result_max}}.
:::

::: step explain
Błąd to też wskazówka dla agenta. Błąd wykonania serwer zwraca w wyniku z `isError: true` i zrozumiałym tekstem. Wtedy Claude może poprawić się sam.

Źle: `Error 400`.

Dobrze, jak w specyfikacji: `Invalid departure date: must be in the future. Current date is 08/08/2025.`

Dobry komunikat mówi, co jest nie tak i jak to poprawić.
:::

:::

::: step summary
**Dobre narzędzie wykonuje działanie dopasowane do zadania agenta, a nie powtarza endpointu API.**

Nazwa z prefiksem usługi, jednoznaczne parametry, opis jak dla nowego pracownika, krótka odpowiedź z czytelnymi nazwami i błąd, który podpowiada poprawkę.

Moduł MCP ukończony: znasz architekturę, prymitywy i transporty, zbudowałeś własny serwer i umiesz podłączyć go do Claude.
:::
