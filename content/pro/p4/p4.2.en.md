::: step hook
Emma from Leeds sorts an online shop's reviews into “delivery”, “quality” and “price”. There are 30,000 of them a day.

She picked the most powerful model “just in case”. The sorting is perfect, but the monthly bill is bigger than the salary of the person who used to do it by hand.

Where did she go wrong?
:::

::: step explain
The stronger the model, the slower and pricier it is:

- {{data.models.pfour_fable_name}}: the hardest reasoning;
- {{data.models.pfour_opus_name}}: long-running work with code and knowledge; the recommended starting point if you're unsure;
- {{data.models.pfour_sonnet_name}}: a balance of speed and intelligence;
- {{data.models.pfour_haiku_name}}: the fastest, for classification, extraction and routing.
:::

::: step explain
Pricing is per *million tokens* (MTok), separately for input and output. Output tokens cost more than input tokens.

The formula: `tokens × price per MTok / 1,000,000`, separately for input and output, then add them up.
:::

::: exercise single_choice

question: "A hypothetical model costs $1 per million input tokens and $5 per million output tokens. A request has 2,000 input tokens and 400 output tokens. How much does it cost?"
options:
  - text: "$0.004"
    correct: true
    why: "Input: 2,000 × 1 / 1,000,000 = $0.002. Output: 400 × 5 / 1,000,000 = $0.002. Total: $0.004. A million requests like this come to $4,000."
  - text: "$0.012"
    correct: false
    why: "That's what you get if you charge all 2,400 tokens at the output price. Input and output each have their own price."
  - text: "$0.0024"
    correct: false
    why: "That's what you get if you charge every token at the input price. But output tokens here cost 5 times more."
  - text: "$4"
    correct: false
    why: "The price is per million tokens, and the request has 2,400. Don't forget to divide by 1,000,000."
hint: "Work out input and output separately: tokens × price / 1,000,000. Then add them up."
:::

::: step explain
Every model in the API is called by its *ID*, for example `{{data.models.pfour_haiku_id}}`. It's a *pinned snapshot*: the model's behaviour under that ID won't change behind your back. A new version comes with a new ID.

Older models (before generation 4.6) had a short *alias* that pointed to a dated ID. Every model has a retirement date.
:::

::: step summary
**Start with the model that fits the task, test it on your own data and only then scale up.**

Cost = tokens × price per million, input and output separately. A model ID is a pinned snapshot; keep it in your config.
