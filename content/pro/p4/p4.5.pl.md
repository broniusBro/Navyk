::: step hook
Natalia z Poznania wyciąga dane z maili od klientów: imię, miasto, numer zamówienia. Kod oczekuje czystego JSON-a, ale czasem Claude pisze:

```claude
Oto dane w formacie JSON:
{"name": "Andrzej", "city": "Poznań", …
```

Parser wywraca się na pierwszym słowie. Kiedyś leczyło się to *prefillem*: dopisywało się za Claude początek odpowiedzi `{`. W nowych modelach takie zapytanie zwraca błąd 400.
:::

::: step explain
Właściwe narzędzie to *Structured Outputs*. Przekazujesz schemat JSON, a Claude zwraca poprawny JSON ściśle według niego. Bez wstępów i bez zbędnych pól.

Schemat podaje się w `output_config.format`, nagłówek beta nie jest potrzebny. Tak samo działa oceniający w Navyk: ocena twoich promptów przychodzi jako JSON zgodny ze schematem.
:::

::: step explain
```python
schema = {
    "type": "object",
    "properties": {
        "name": {"type": "string"},
        "city": {"type": "string"},
        "order_id": {"type": "string"},
    },
    "required": ["name", "city", "order_id"],
    "additionalProperties": False,
}
response = client.messages.create(
    model="{{data.models.pfour_haiku_id}}",
    max_tokens=1024,
    messages=[{"role": "user", "content": letter_text}],
    output_config={"format": {"type": "json_schema", "schema": schema}},
)
text = next(b.text for b in response.content if b.type == "text")
data = json.loads(text)
```
:::

::: step explain
Schematy mają ograniczenia:

- każdy obiekt ma `"additionalProperties": false`;
- obsługiwane są typy, `enum`, `required`, `anyOf`;
- *nie* są obsługiwane `minimum`/`maximum`, `minLength`/`maxLength` ani schematy rekurencyjne.

Nieobsługiwane elementy dają błąd 400. Granice liczbowe sprawdzaj we własnym kodzie po parsowaniu.
:::

::: step explain
JSON zgodny ze schematem jest gwarantowany tylko wtedy, gdy Claude zakończył normalnie. Sprawdzaj `stop_reason`:

- `refusal` — Claude odmówił, odpowiedź może nie pasować do schematu;
- `max_tokens` — odpowiedź jest ucięta; powtórz zapytanie z większym `max_tokens`.

W Pythonie wygodniej użyć `client.messages.parse()` z modelem Pydantic: SDK samo przekaże schemat i sprawdzi odpowiedź.
:::

::: step explain
Schemat określa *formę* odpowiedzi, ale nie *znaczenie* pól. Co uznać za miasto? Co zrobić, jeśli w mailu nie ma numeru zamówienia?

To wciąż zadanie promptu: wyjaśnij, co znaczy każde pole i co wpisać, gdy brakuje danych.
:::
