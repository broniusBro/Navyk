::: step hook
Наталья из Запорожья достаёт данные из писем клиентов: имя, город, номер заказа. Код ждёт чистый JSON, но иногда Claude пишет:

```claude
Вот данные в формате JSON:
{"name": "Андрей", "city": "Запорожье", …
```

Парсер падает на первом же слове. Раньше это лечили *prefill*: дописывали за Claude начало ответа `{`. На новых моделях такой запрос возвращает ошибку 400.
:::

::: step explain
Правильный инструмент — *Structured Outputs*. Ты передаёшь JSON-схему, и Claude возвращает валидный JSON строго по ней. Без вступлений и без лишних полей.

Схема задаётся в `output_config.format`, beta-заголовок не нужен. Так же устроен проверяющий Navyk: разбор твоих промптов приходит JSON-ом по схеме.
:::

::: step explain
```python
schema = {
    "type": "object",
    "properties": {
        "name": {"type": "string"},
        "city": {"type": "string"},
        "order_id": {"type": "string"},
    },
    "required": ["name", "city", "order_id"],
    "additionalProperties": False,
}
response = client.messages.create(
    model="{{data.models.pfour_haiku_id}}",
    max_tokens=1024,
    messages=[{"role": "user", "content": letter_text}],
    output_config={"format": {"type": "json_schema", "schema": schema}},
)
text = next(b.text for b in response.content if b.type == "text")
data = json.loads(text)
```
:::

::: step explain
У схем есть ограничения:

- у каждого объекта `"additionalProperties": false`;
- поддерживаются типы, `enum`, `required`, `anyOf`;
- *не* поддерживаются `minimum`/`maximum`, `minLength`/`maxLength` и рекурсивные схемы.

Неподдерживаемое даёт ошибку 400. Числовые границы проверяй в своём коде после разбора.
:::

  - text: '"score": {"type": "integer", "minimum": 1, "maximum": 5}}, '
    weak: true

  - text: '"required": ["topic", "score"], '
    weak: false
    why: "required поддерживается: оба поля обязательны."
  - text: '"additionalProperties": true}'
    weak: true
    why: "Для объектов нужно additionalProperties: false. Иначе ошибка 400."
hint: "Сверь схему со списком ограничений: что с числовыми границами и что с additionalProperties?"

::: step explain
JSON по схеме гарантирован, только когда Claude закончил нормально. Проверяй `stop_reason`:

- `refusal` — Claude отказался, ответ может не совпасть со схемой;
- `max_tokens` — ответ обрезан; повтори запрос с бо́льшим `max_tokens`.

В Python удобнее `client.messages.parse()` с моделью Pydantic: SDK сам передаст схему и проверит ответ.
:::

::: step explain
Схема задаёт *форму* ответа, но не *смысл* полей. Что считать городом? Что делать, если номера заказа в письме нет?

Это всё ещё задача промпта: объясни, что значит каждое поле и что писать, когда данных нет.
:::

::: step summary
**Нужен JSON — передай схему в output_config.format, а не дописывай «{» за Claude.**

`additionalProperties: false`, числовые границы проверяй в коде, `stop_reason` проверяй всегда. Схема задаёт форму, промпт — смысл.
