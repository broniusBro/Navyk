::: step hook
A customer messages a Limerick bookshop's bot: “Where's my order 1042?” The bot confidently replies: “Your order is on its way!”

The order hasn't even been packed. The bot has no access to the database and simply guessed.
:::

::: step explain
*Tool use* is how you give Claude tools: functions in your app that it can ask you to call. For example, “find an order by its number”.

Important: Claude doesn't run code itself. It says: “call get_order with the number 1042”. Your server makes the call, and you return the result to Claude.
:::

::: step explain
A tool is described with three fields:

```python
tools = [{
    "name": "get_order_status",
    "description": "Returns the status of a bookshop order by its number: being packed, out for delivery, delivered. Use it when a customer asks where their order is. Doesn't return the address or the order's contents.",
    "input_schema": {
        "type": "object",
        "properties": {
            "order_id": {"type": "string", "description": "Order number, digits only, e.g. 1042"}
        },
        "required": ["order_id"],
    },
}]
```
:::

::: step explain
Then comes the loop:

1. You send a request with `tools`.
2. Claude replies with `stop_reason: "tool_use"` and a `tool_use` block with `id`, `name` and `input`.
3. Your code calls the function.
4. You send a new `user` message with a `tool_result` block and the same `tool_use_id`.
5. Claude writes the reply to the customer.
:::

::: step explain
The most important part of a tool is its *description*. The docs call it the single biggest factor in quality. The description covers:

- what the tool does;
- when to use it and when *not* to;
- what each parameter means;
- what it can't do.

At least 3–4 sentences. If the function fails, return a `tool_result` with `"is_error": true` and a clear message: what happened and what to do.
:::

  - text: "description: Gets data. "

  - text: "Parameter id: identifier. "
    weak: true
    why: "Identifier of what, and in what format? A phone number, a booking number, a car registration? It needs a format example."
  - text: "Use for questions about booking a repair; don't use for questions about prices, the prices are in the system prompt."
    weak: false
    why: "Excellent: it says when to use it, when not to and why. That way Claude won't call the tool unnecessarily."

:::

::: step summary
**Claude doesn't run tools; it asks for them to be called. Your code runs them and returns the result.**

A tool = a name, a detailed description and an input schema. A `tool_use` reply → your call → a `tool_result` with the same `tool_use_id`.
