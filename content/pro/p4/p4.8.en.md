::: step hook
Every night Emma sorts the day's reviews by topic: 20,000 of them. Right now her script sends them one at a time, as if someone were waiting for each reply.

But nobody looks at the report until the morning. Why pay for speed nobody needs?
:::

::: step explain
That's what the *Message Batches API* is for: batch processing. You send lots of requests at once and collect the results later.

You pay {{data.prices.pfour_batch_discount}} of the standard price, for both input and output tokens. In exchange, you wait: {{data.limits.pfour_batch_typical}}, {{data.limits.pfour_batch_expire}} at most.
:::

  - text: "An agent where each next step depends on the reply to the previous one"
    correct: false
    why: "Requests in a batch are independent and processed together. You can't build a chain where each step waits for the previous result."
hint: "A good fit is lots of requests that are independent and don't need an answer right now."
:::

::: step explain
Each request in a batch is a `custom_id` plus regular Messages API parameters:

```python
batch = client.messages.batches.create(
    requests=[
        {
            "custom_id": f"review-{r.id}",
            "params": {
                "model": "{{data.models.pfour_haiku_id}}",
                "max_tokens": 50,
                "messages": [{"role": "user", "content": r.text}],
            },
        }
        for r in reviews
    ]
)
```

A `custom_id` is 1 to 64 characters: Latin letters, digits, `-` and `_`.
:::

::: step explain
While the batch is running, `processing_status` is `in_progress`. Once it's `ended`, you collect the results:

```python
for item in client.messages.batches.results(batch.id):
    if item.result.type == "succeeded":
        save(item.custom_id, item.result.message)
```

Results come back *in any order*. Match them only by `custom_id`. They're kept for {{data.limits.pfour_batch_results_days}}.
:::

::: step explain
Not every request in a batch succeeds. There are four result types:

- `succeeded`: done, with a regular reply inside;
- `errored`: an error in the request or on the server;
- `canceled`: you canceled the batch before it finished;
- `expired`: the batch ran out of time (limit: {{data.limits.pfour_batch_expire}}).

You don't pay for `errored`, `canceled` or `expired`.
:::

::: step summary
**If you don't need the answer right now, send it as a batch and pay half.**

Give every request a unique `custom_id` and match results only by it. Caching and batches together give you the biggest savings.
