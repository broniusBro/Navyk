::: step hook
Наталя із Запоріжжя дістає дані з листів клієнтів: ім'я, місто, номер замовлення. Код чекає чистий JSON, але іноді Claude пише:

```claude
Ось дані у форматі JSON:
{"name": "Андрій", "city": "Запоріжжя", …
```

Парсер падає на першому ж слові. Раніше це лікували *prefill*: дописували за Claude початок відповіді `{`. На нових моделях такий запит повертає помилку 400.
:::

::: step explain
Правильний інструмент — *Structured Outputs*. Ти передаєш JSON-схему, і Claude повертає валідний JSON суворо за нею. Без вступів і без зайвих полів.

Схема задається в `output_config.format`, beta-заголовок не потрібен. Так само влаштований перевіряльник Navyk: розбір твоїх промптів приходить JSON-ом за схемою.
:::

::: step explain
```python
schema = {
    "type": "object",
    "properties": {
        "name": {"type": "string"},
        "city": {"type": "string"},
        "order_id": {"type": "string"},
    },
    "required": ["name", "city", "order_id"],
    "additionalProperties": False,
}
response = client.messages.create(
    model="{{data.models.pfour_haiku_id}}",
    max_tokens=1024,
    messages=[{"role": "user", "content": letter_text}],
    output_config={"format": {"type": "json_schema", "schema": schema}},
)
text = next(b.text for b in response.content if b.type == "text")
data = json.loads(text)
```
:::

::: step explain
Схеми мають обмеження:

- у кожного об'єкта `"additionalProperties": false`;
- підтримуються типи, `enum`, `required`, `anyOf`;
- *не* підтримуються `minimum`/`maximum`, `minLength`/`maxLength` і рекурсивні схеми.

Непідтримуване дає помилку 400. Числові межі перевіряй у своєму коді після розбору.
:::

::: step explain
JSON за схемою гарантовано, лише коли Claude завершив нормально. Перевіряй `stop_reason`:

- `refusal` — Claude відмовився, відповідь може не збігтися зі схемою;
- `max_tokens` — відповідь обрізано; повтори запит із більшим `max_tokens`.

У Python зручніше `client.messages.parse()` з моделлю Pydantic: SDK сам передасть схему й перевірить відповідь.
:::

::: step explain
Схема задає *форму* відповіді, але не *зміст* полів. Що вважати містом? Що робити, якщо номера замовлення в листі немає?

Це все ще завдання промпту: поясни, що означає кожне поле і що писати, коли даних немає.
:::

::: step summary
**Потрібен JSON — передай схему в output_config.format, а не дописуй «{» за Claude.**

`additionalProperties: false`, числові межі перевіряй у коді, `stop_reason` перевіряй завжди. Схема задає форму, промпт — зміст.
