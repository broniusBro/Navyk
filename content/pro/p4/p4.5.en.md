::: step hook
Natalie from Manchester pulls data out of customer emails: name, city, order number. Her code expects clean JSON, but sometimes Claude writes:

```claude
Here's the data in JSON format:
{"name": "Andrew", "city": "Manchester", …
```

The parser falls over on the very first word. The old fix was *prefill*: writing the start of Claude's reply for it, `{`. On new models, a request like that returns a 400 error.
:::

::: step explain
The right tool is *Structured Outputs*. You pass a JSON schema, and Claude returns valid JSON that strictly follows it. No preamble, no extra fields.

The schema goes in `output_config.format`, with no beta header needed. Navyk's reviewer works the same way: the feedback on your prompts comes back as JSON that follows a schema.
:::

::: step explain
```python
schema = {
    "type": "object",
    "properties": {
        "name": {"type": "string"},
        "city": {"type": "string"},
        "order_id": {"type": "string"},
    },
    "required": ["name", "city", "order_id"],
    "additionalProperties": False,
}
response = client.messages.create(
    model="{{data.models.pfour_haiku_id}}",
    max_tokens=1024,
    messages=[{"role": "user", "content": letter_text}],
    output_config={"format": {"type": "json_schema", "schema": schema}},
)
text = next(b.text for b in response.content if b.type == "text")
data = json.loads(text)
```
:::

::: step explain
Schemas have limitations:

- every object needs `"additionalProperties": false`;
- types, `enum`, `required` and `anyOf` are supported;
- `minimum`/`maximum`, `minLength`/`maxLength` and recursive schemas are *not* supported.

Anything unsupported returns a 400 error. Check numeric bounds in your own code after parsing.
:::

  - text: '"topic": {"type": "string", "enum": ["delivery", "quality", "price"]}, '
    weak: false
    why: "enum is supported and works great for classification: Claude will pick one of the three values."
  - text: '"score": {"type": "integer", "minimum": 1, "maximum": 5}}, '
    weak: true
    why: "minimum and maximum aren't supported. Keep integer, describe the range in description and check it in code."
  - text: '"required": ["topic", "score"], '
    weak: false
    why: "required is supported: both fields are mandatory."
  - text: '"additionalProperties": true}'
    weak: true
    why: "Objects need additionalProperties: false. Otherwise you get a 400 error."
hint: "Check the schema against the list of limitations: what about numeric bounds, and what about additionalProperties?"

::: step explain
JSON matching the schema is guaranteed only when Claude finishes normally. Always check `stop_reason`:

- `refusal`: Claude declined, so the reply may not match the schema;
- `max_tokens`: the reply was cut off; retry with a higher `max_tokens`.

In Python, `client.messages.parse()` with a Pydantic model is more convenient: the SDK passes the schema and validates the reply for you.
:::

::: step explain
The schema sets the *shape* of the reply, but not the *meaning* of the fields. What counts as the city? What if there's no order number in the email?

That's still the prompt's job: explain what each field means and what to write when the data is missing.
:::

::: step summary
**Need JSON? Pass a schema in output_config.format instead of writing “{” for Claude.**

Use `additionalProperties: false`, check numeric bounds in code and always check `stop_reason`. The schema sets the shape; the prompt sets the meaning.
