::: step hook
Айгерим из Алматы в пятницу вечером меняет в конфиге сервиса модель: была {{data.models.pseven_old_name}}, стала {{data.models.pseven_new_name}}. «Это же просто строчка», — думает она.

Через пять минут в логах:

```text
400 invalid_request_error: This model does not support assistant message prefill.
The conversation must end with a user message.
```

А там, где ошибок нет, ответы стали другими по длине. Что пошло не так?
:::

::: step explain
Новая модель — это не только новый ID. Меняются параметры API, поведение и расход токенов.

Поэтому у Anthropic есть страница *Migration guides*: для каждой новой модели — свой гайд. Внутри *чек-лист*, сгруппированный по твоей исходной модели: «для всех», «с 4.6 и старше», «с 4.5 и старше». Читаешь только свои разделы.
:::

::: step example
Что Айгерим нашла бы в гайде для своей модели:

- *prefill* (начало ответа за Claude) заменить: иначе ошибка 400;
- убрать нестандартные `temperature`, `top_p`, `top_k`: иначе тоже 400;
- вместо бюджета thinking задать уровень `effort`;
- пересчитать токены: тот же текст даёт {{data.limits.pseven_token_growth}}.

Детали меняются с каждой моделью: сверяйся с актуальным гайдом.
:::

::: step explain
Исправить ошибки 400 мало. Модель могла начать отвечать по-другому, а это видно только на твоих тестах.

Гайд советует: после перехода перепроверить модельно-специфичные инструкции промпта по гайду промптинга для новой модели. А сравнить версии поможет твой eval из прошлых уроков.
:::

::: step summary
**Смена модели — это миграция, а не правка одной строки.**

Открой гайд новой модели, читай разделы для своей исходной модели, почини несовместимые параметры и сравни старую и новую модель на одном и том же eval. Переключай продакшен только после разбора провалов.
:::
