::: step hook
Андрій виправив у промпті одну фразу про тон. Перевірив на трьох запитаннях — бот став теплішим. Викотив.

Через тиждень прийшли скарги: бот почав називати ціну тарифу «Домашній 100» 150 грн замість 250. Цієї помилки ніхто не впіймав, бо ніхто не перевіряв ціни після правки.

Як дізнатися про таку поломку раніше за клієнтів?
:::

::: step explain
Потрібен *eval* — набір тестів для промпту, який проганяють після кожної правки.

Кілька термінів зі статті інженерів Anthropic:

- *завдання* (task) — один тест: вхідні дані й критерії успіху;
- *оцінювач* (grader) — логіка, яка ставить бал;
- *транскрипт* — повний запис спроби.

Починати радять із 20–50 простих завдань із реальних збоїв.
:::

::: step example
Найпростіший eval — файл із завданнями й перевірка кодом:

```json
[
  { "id": "tariff-1", "input": "Скільки коштує «Домашній 100»?", "expect": { "contains": "250 грн" } },
  { "id": "empty-1", "input": "", "expect": { "handoff": true } }
]
```

```python
def grade(output: str, case: dict) -> bool:
    return case["expect"]["contains"].lower() in output.lower()
```

У Navyk так перевіряють самого перевіряльника твоїх промптів: еталонний набір проганяється після кожної правки його інструкції.
:::

::: step explain
Оцінювачі бувають трьох видів:

- *код*: точний збіг, пошук рядка. Швидко, дешево й відтворювано, але без нюансів;
- *модель*: оцінює за рубрикою, вловлює тон і зміст. Її треба звіряти з людьми;
- *людина*: еталон, але повільно й дорого.

Документація радить автоматизувати, де можна: багато тестів з автооцінюванням краще, ніж мало з ручним.
:::

::: step explain
Модель-оцінювач — теж промпт. За документацією, хорошому оцінювачеві потрібні:

- детальна чітка рубрика;
- конкретний вивід: «correct» або «incorrect», чи шкала 1–5;
- міркування перед оцінкою.

І оцінювати краще іншою моделлю, ніж та, що відповідала. Напиши такий промпт сам.
:::

::: step summary
**Кожна правка промпту — через той самий набір тестів.**

Почни з 20–50 завдань із реальних збоїв і крайніх випадків. Код — для однозначного, модель із рубрикою — для змісту й тону, людина — для спірного. І читай транскрипти провалів.
:::
