::: step hook
Tim asked Claude Code to work out how authentication is set up in the project. Claude read thirty files, explained everything, and Tim said: “Great, now add sign-in with Google.”

From then on, Claude started getting confused about details they'd discussed ten minutes earlier. The context is clogged with the contents of those thirty files.
:::

::: step explain
An investigation like that is better handed to a *subagent*: a separate helper with its own context. It's like sending an intern to the archive: they go through the folders themselves and bring you back one page of conclusions.

A subagent has its own system prompt, its own set of tools and its own context window. Only the summary comes back to the main conversation.
:::

::: step example
A subagent is a Markdown file with frontmatter. The file `.claude/agents/code-researcher.md`:

```markdown
---
name: code-researcher
description: Investigates the codebase and explains where and how things are implemented. Use before making changes in unfamiliar modules.
tools: Read, Grep, Glob
---

You are a code researcher. You'll be given a question about the project.
Find the answer by reading files. Don't change anything.
Return: the answer in 3–5 sentences, a list of files with line numbers, and open questions.
```

Only `name` and `description` are required. The `tools` line leaves it with nothing but reading and searching.
:::

::: exercise single_choice
id: "p2.3.e1"
type: "single_choice"
question: "Tim removed the `tools` line from the frontmatter. What changes?"
options:
  - text: "The subagent gets every tool available to subagents, including file editing and the terminal"
    correct: true
    why: "Without `tools`, the full set is inherited. A researcher doesn't need that: restricting it to `Read, Grep, Glob` guarantees it only reads."
  - text: "The subagent gets no tools at all and can only reply with text"
    correct: false
    why: "The opposite: without `tools` it inherits everything. To deny something, you list tools explicitly or put them in `disallowedTools`."
  - text: "The file stops working because `tools` is a required field"
    correct: false
    why: "Only `name` and `description` are required. The other fields, including `tools`, are optional."
  - text: "The subagent starts working in the main context"
    correct: false
    why: "Every subagent has its own context. The `tools` field only affects which actions it can take."
hint: "Think about the default for a tool Claude Code uses on its own: give it everything or nothing? The docs went with one of the two."
:::

::: step explain
How Claude hands a task to a subagent:

- **On its own**, based on `description`. The more precisely you describe when to call it, the more often Claude does. The docs recommend adding phrases like “use proactively”.
- **When you ask**: “Use the code-researcher subagent to…”
- **With @**: type `@` and pick it from the list.

If the `.claude/agents/` folder didn't exist before, restart the session after adding the first file.
:::

    correct: false

  - text: "Read the summary and make the change in the main conversation"

::: step explain
Now build your own subagent. For example, a reviewer that looks for problems in your changes before a commit, or a researcher for your project.

Write the whole file: frontmatter and system prompt. Think about which tools it really needs. Navyk will send the file to Claude for feedback.
:::

    name: diff-reviewer

::: step summary
**A subagent is a file in `.claude/agents/` with `name`, `description` and, where it matters, `tools`. It works in its own context and returns a summary.**

Without `tools`, a subagent gets every tool, so give a researcher read-only access. Be specific about the task: it can't see your conversation.
