::: step hook
Денис из Кракова неделю работает в Claude Code, и у него накопились жалобы:

- Claude дважды запустил `npm` вместо `pnpm`.
- Каждую пятницу он вставляет в чат один и тот же чек-лист релиза.
- Задачи из трекера копирует в чат руками.
- После правок Claude иногда забывает запустить линтер.

Четыре проблемы — и у каждой свой инструмент. Какой куда?
:::

::: step explain
У Claude Code шесть основных способов расширения:

- **CLAUDE.md** — правила, которые Claude видит в каждой сессии.
- **Навык** (*skill*) — инструкция или процесс по требованию, вызов через `/имя`.
- **Субагент** — помощник с отдельным контекстом, возвращает только сводку.
- **Хук** — твой скрипт, который запускается на событие.
- **MCP** — подключение внешних сервисов.
- **Плагин** — упаковка всего этого для других проектов и людей.
:::

::: exercise match_pairs
id: "p2.1.e1"
type: "match_pairs"
question: "Соедини ситуацию Дениса с расширением, которое её решает."
pairs:
  - left: "Claude второй раз путает `npm` и `pnpm`"
    right: "Строка в CLAUDE.md"
    why: "Это правило «всегда делай так» для каждой сессии. Документация так и советует: если Claude дважды ошибся в соглашении проекта, допиши его в CLAUDE.md."
  - left: "Каждую пятницу один и тот же чек-лист релиза"
    right: "Навык с вызовом `/release`"
    why: "Повторяемый процесс, который нужен не всегда, а по команде. Навык загружается только при вызове и не занимает контекст в остальное время."
  - left: "Задачи из трекера копируются в чат руками"
    right: "MCP-сервер трекера"
    why: "Claude не видит вкладку браузера. MCP даёт ему инструменты, чтобы читать задачи из трекера самому."
  - left: "Линтер должен запускаться после каждой правки, без исключений"
    right: "Хук на событие после правки файла"
    why: "«Каждый раз, без просьбы» — это работа для хука. Хук запускается всегда, а не тогда, когда Claude вспомнит."
hint: "Спроси себя про каждую ситуацию: это правило на всю сессию, процесс по команде, внешний сервис или действие, которое должно случаться всегда?"
:::

::: step explain
Главное отличие — *совет* или *гарантия*.

CLAUDE.md и навыки — это инструкции. Claude их читает и обычно выполняет, но это просьба. Хук — это код: Claude Code запускает его на событии каждый раз.

Документация формулирует прямо: правило «никогда не правь `.env`» в CLAUDE.md — просьба, а хук, который блокирует правку, — принуждение.
:::

options:
  - text: "Хук, который перед правкой файла проверяет путь и блокирует изменение `.env`"
    correct: true
    why: "Если правило должно соблюдаться каждый раз, нужен хук: он срабатывает на событие и не зависит от того, как Claude понял инструкцию."
  - text: "Строку в CLAUDE.md: «Никогда не трогай .env»"
    correct: false
    why: "Полезно, но это просьба. В длинной сессии или при неудачной формулировке задачи Claude может её нарушить. Для гарантии нужен хук."
  - text: "Навык `/no-env`, который напоминает Claude о правиле"
    correct: false
    why: "Навык — тоже инструкция, и он работает, только когда загружен. Гарантии он не даёт."
  - text: "Субагента, который следит за остальными"
    correct: false
    why: "Субагент — отдельный исполнитель задач, а не охранник. Он не перехватывает правки в главном разговоре."
hint: "Здесь нужно не «обычно соблюдается», а «соблюдается всегда». Что из списка запускает Claude Code, а не сам Claude?"
:::

::: step explain
Второй вопрос — *цена в контексте*. Всё, что ты добавляешь, занимает место в рабочей памяти Claude.

- CLAUDE.md загружается целиком в каждый запрос.
- От навыков в начале сессии видны только описания, полный текст — при вызове.
- Субагент работает в своём контексте и возвращает сводку.
- Хук ничего не добавляет, если сам не вернёт вывод.
:::

::: step summary
**Правило «на всегда» — в CLAUDE.md. Процесс по команде — в навык. Много чтения — субагенту. «Каждый раз без исключений» — в хук. Внешний сервис — через MCP. Поделиться всем этим — плагином.**

Начинай с CLAUDE.md и добавляй остальное, когда появится повод. Дальше разберём каждое расширение на практике, начиная с навыков.
:::
