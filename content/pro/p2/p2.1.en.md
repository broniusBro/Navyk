::: step hook
Dan in Dublin has been working in Claude Code for a week, and the complaints are piling up:

- Claude has run `npm` instead of `pnpm` twice.
- Every Friday he pastes the same release checklist into the chat.
- He copies tickets from the tracker into the chat by hand.
- After making edits, Claude sometimes forgets to run the linter.

Four problems, and each one has its own tool. Which goes where?
:::

::: step explain
Claude Code has six main ways to extend it:

- **CLAUDE.md** — rules Claude sees in every session.
- **Skill** — an instruction or workflow on demand, invoked with `/name`.
- **Subagent** — a helper with its own context that returns only a summary.
- **Hook** — your script that runs on an event.
- **MCP** — connections to external services.
- **Plugin** — a bundle of all of the above for other projects and people.
:::

::: exercise match_pairs
id: "p2.1.e1"
type: "match_pairs"
question: "Match each of Dan's situations with the extension that solves it."
pairs:
  - left: "Claude mixes up `npm` and `pnpm` for the second time"
    right: "A line in CLAUDE.md"
    why: "This is an “always do it this way” rule for every session. The docs say exactly this: if Claude gets a project convention wrong twice, add it to CLAUDE.md."
  - left: "The same release checklist every Friday"
    right: "A skill invoked with `/release`"
    why: "A repeatable workflow you need on command, not all the time. A skill only loads when invoked and takes up no context the rest of the time."
  - left: "Tickets get copied from the tracker into the chat by hand"
    right: "An MCP server for the tracker"
    why: "Claude can't see your browser tab. MCP gives it tools to read tickets from the tracker itself."
  - left: "The linter must run after every edit, no exceptions"
    right: "A hook on the after-file-edit event"
    why: "“Every time, without asking” is a job for a hook. A hook always runs, not just when Claude remembers."
hint: "For each situation, ask yourself: is it a rule for the whole session, a workflow on command, an external service, or an action that must always happen?"
:::

::: step explain
The key difference is *advice* versus *guarantee*.

CLAUDE.md and skills are instructions. Claude reads them and usually follows them, but they're requests. A hook is code: Claude Code runs it on the event every single time.

The docs put it plainly: a “never edit `.env`” rule in CLAUDE.md is a request, while a hook that blocks the edit enforces it.
:::

::: exercise single_choice
id: "p2.1.e2"
type: "single_choice"
question: "The project has a secrets file, `.env`. Claude must never change it under any circumstances. What do you choose?"
options:
  - text: "A hook that checks the path before a file edit and blocks changes to `.env`"
    correct: true
    why: "If a rule must hold every time, you need a hook: it fires on the event and doesn't depend on how Claude understood an instruction."
  - text: "A line in CLAUDE.md: “Never touch .env”"
    correct: false
    why: "Useful, but it's a request. In a long session, or with a badly worded task, Claude may break it. For a guarantee you need a hook."
  - text: "A `/no-env` skill that reminds Claude of the rule"
    correct: false
    why: "A skill is also an instruction, and it only works when loaded. It gives no guarantee."
  - text: "A subagent that keeps an eye on everything else"
    correct: false
    why: "A subagent is a separate worker for tasks, not a guard. It doesn't intercept edits in the main conversation."
hint: "You need “always holds”, not “usually holds”. Which option is run by Claude Code rather than by Claude itself?"
:::

::: step explain
The second question is *context cost*. Everything you add takes up space in Claude's working memory.

- CLAUDE.md is loaded in full into every request.
- For skills, only the descriptions are visible at the start of a session; the full text loads when invoked.
- A subagent works in its own context and returns a summary.
- A hook adds nothing unless it returns output itself.
:::

::: exercise multi_choice
id: "p2.1.e3"
type: "multi_choice"
question: "Dan moved 300 lines of internal API reference into CLAUDE.md. Which of these are true? Select all that apply."
options:
  - text: "Those 300 lines go into every request, even when the API isn't needed"
    correct: true
    why: "CLAUDE.md is loaded in full at the start of a session and stays in every request. That's why big reference docs are expensive there."
  - text: "It's better to move the reference into a skill: only its description will be visible at the start of a session"
    correct: true
    why: "That's what the docs recommend: keep CLAUDE.md short and move reference material into skills that load on demand."
  - text: "A hook that runs the linter also takes up space in the context of every request"
    correct: false
    why: "A hook runs outside. Only what it returns itself ends up in context, such as linter errors."
  - text: "The more you load, the more precisely Claude follows the rules"
    correct: false
    why: "The opposite. Extra context is noise: skills may fire at the wrong moment, and project conventions get lost."
hint: "Remember which extensions load in full straight away and which load only when needed."
:::

::: exercise single_choice
id: "p2.1.e4"
type: "single_choice"
question: "Dan needs to understand how payments work in a monorepo. That means reading about forty files, but afterwards he only needs a short summary. What fits best?"
options:
  - text: "A subagent: it reads the files in its own context and returns a summary"
    correct: true
    why: "A classic subagent task. The intermediate work stays with it, and only the result comes back to the main conversation."
  - text: "A skill describing the payments module"
    correct: false
    why: "A skill adds text to your main context. And to write it, you'd still have to do the research."
  - text: "A hook that reads all forty files at session start"
    correct: false
    why: "A hook runs a script; it doesn't reason. Plus, output into context at every start is exactly the load Dan wants to avoid."
  - text: "Ask Claude in the main chat, since context is unlimited"
    correct: false
    why: "Context isn't unlimited. Forty files in the main conversation will push out what matters for the next task."
hint: "The key phrases are “read a lot” and “only need the result”. Which extension works in a separate context?"
:::

::: step summary
**A rule for always goes in CLAUDE.md. A workflow on command goes in a skill. Lots of reading goes to a subagent. “Every time, no exceptions” goes in a hook. An external service goes through MCP. To share all of it, use a plugin.**

Start with CLAUDE.md and add the rest when there's a reason. Next, we'll try each extension in practice, starting with skills.
:::
