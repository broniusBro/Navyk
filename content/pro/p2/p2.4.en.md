::: step hook
Megan's CLAUDE.md says: “Run `npx eslint` after every edit.” Usually Claude does.

But in a long session it forgot a couple of times, and the linter errors only surfaced in CI. Megan doesn't need “usually”, she needs “every time”.
:::

::: step explain
That's what a *hook* is for: your command that Claude Code runs by itself at a specific moment. Think of a smoke detector: it goes off not because someone remembered, but because there's smoke.

CLAUDE.md is a request to Claude. A hook is run by Claude Code, not by the model, so it fires on every matching event.
:::

::: step explain
Hooks are defined in the `hooks` block of a settings file. `.claude/settings.json` is for the project, and you can commit it. `~/.claude/settings.json` is for all your projects.

The main parts:

- the *event*: `PostToolUse` — after a successful tool call, `PreToolUse` — before it;
- the *matcher*: `Edit|Write` — only file-editing tools;
- the *command*, which receives the event data as JSON on its input (stdin).
:::

::: step example
Megan adds this to `.claude/settings.json`:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/lint.sh"
          }
        ]
      }
    ]
  }
}
```

And the script `.claude/hooks/lint.sh`:

```bash
#!/bin/bash
FILE_PATH=$(jq -r '.tool_input.file_path // empty')
case "$FILE_PATH" in
  *.js|*.ts) npx eslint "$FILE_PATH" >&2 || exit 2 ;;
esac
exit 0
```

Don't forget `chmod +x .claude/hooks/lint.sh`: the script has to be executable.
:::

::: step explain
What does `exit 2` mean? A hook responds with an exit code:

- `0` — no objection;
- `2` — a signal to Claude Code, with the stderr text passed on as the reason;
- any other code — a non-blocking error, work carries on.

For `PostToolUse`, code 2 shows stderr to Claude: the edit has already been made, but Claude sees the linter errors and fixes them. That's why the ESLint output is redirected to stderr (`>&2`).
:::

::: step summary
**A hook is a command Claude Code runs on an event. A rule in CLAUDE.md is advice; a hook is a guarantee.**

Linter after edits: `PostToolUse` + `Edit|Write` + `exit 2` with errors on stderr. Blocking edits: `PreToolUse` + `exit 2`.
