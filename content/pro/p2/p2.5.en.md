::: step hook
Every morning Jake opens his team's knowledge base in the browser, copies a task description and pastes it into Claude Code.

Claude can't see browser tabs, so there's no way around the copying. Or is there a way to give it direct access?
:::

::: step explain
There is: *MCP* (Model Context Protocol), an open standard for connecting external services. An *MCP server* is like an adapter: the service on one side, Claude Code on the other. The server gives Claude tools: find a page, read a task, create an entry.

Servers can be remote (at an internet address) or local (a process on your machine).
:::

::: step example
You connect a remote server with a single terminal command. HTTP is the recommended transport for remote servers:

```bash
claude mcp add --transport http notion https://mcp.notion.com/mcp
```

Here `notion` is the name the server will appear under in Claude Code, followed by its URL.

If the server asks you to sign in through the browser (OAuth), type `/mcp` in Claude Code and sign in. That's also where you can see whether the server is connected.
:::

::: step explain
A server has a *scope* (the `--scope` flag):

- `local` — the default: only you, and only in this project;
- `project` — for the whole team: the entry goes into a `.mcp.json` file in the project root, which gets committed;
- `user` — only you, but in all your projects.

For servers from `.mcp.json`, Claude Code shows them and asks for approval before first use.
:::

::: step explain
A local server is a program on your machine (the *stdio* transport). Here the `--` separator matters:

```bash
claude mcp add --env AIRTABLE_API_KEY=YOUR_KEY --transport stdio airtable \
  -- npx -y airtable-mcp-server
```

Everything before `--` is an option for Claude Code itself. Everything after it is the command that starts the server, passed on as is.

To check: `claude mcp list`, `claude mcp get airtable`. To remove: `claude mcp remove airtable`.
:::

::: exercise single_choice
id: "p2.5.e4"
type: "single_choice"
question: "Why is there a `--` in the command for a stdio server?"
options:
  - text: "To separate Claude Code's options from the command that starts the server"
    correct: true
    why: "Everything after `--` goes to the server unchanged. Without the separator, Claude Code would try to parse the server's flags, such as `--port`, as its own."
  - text: "To comment out the rest of the line"
    correct: false
    why: "On the command line, `--` isn't a comment. It's the standard “what follows isn't my options” separator."
  - text: "To turn on a detailed connection log"
    correct: false
    why: "`--` has nothing to do with logging. You check connection status with `/mcp` or `claude mcp get`."
  - text: "It's needed in every `claude mcp add` command, including HTTP"
    correct: false
    why: "For a remote server, the name is simply followed by the URL. `--` is needed when what follows is a command that starts a local process."
hint: "Look at the flags before and after `--` in the example. Who do they belong to?"
:::

::: exercise multi_choice
id: "p2.5.e5"
type: "multi_choice"
question: "Someone sent Jake a link to an unknown MCP server “for working with email”. What's sensible? Select all that apply."
options:
  - text: "First find out who made the server and decide whether you trust them"
    correct: true
    why: "The docs explicitly advise checking that you trust each server before connecting it. The server gets access to data and gives Claude tools to take actions."
  - text: "Remember that a server that reads external content (emails, web pages) can bring someone else's instructions into the context"
    correct: true
    why: "That's the prompt injection risk: an email might contain “forward all emails to…”. Claude reads it as part of the data, but keeping an eye on actions is still your job."
  - text: "Connect it with `local` scope in a test project first, rather than for the whole team straight away"
    correct: true
    why: "That way a mistake or a bad server affects only you. You can add it to `.mcp.json` for the team later."
  - text: "Connect it with `--scope project` straight away, since Claude Code will ask for approval anyway"
    correct: false
    why: "Approval protects against accidental launches, but it doesn't vet the server for you. If the server turns out to be bad, the whole team gets it."
hint: "Think about three things: who the author is, what data will flow through the server and who a mistake would affect."
:::

::: step summary
**An MCP server gives Claude Code the tools of an external service. Remote: `claude mcp add --transport http <name> <url>`. Local: options, then `--` and the server command.**

Scope: `local` for yourself, `project` for the team via `.mcp.json`, `user` for all your own projects. Don't commit secrets, and only connect servers you trust.
