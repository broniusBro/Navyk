::: step hook
Каждую пятницу Олена из Львова пишет в Claude Code один и тот же длинный запрос: «Возьми коммиты с последнего тега, сгруппируй, убери хеши, пиши для пользователей…»

Двенадцать строк, и каждый раз она что-нибудь забывает. Хочется набрать `/release-notes 2.4.0` и получить готовый текст.
:::

::: step explain
Для этого есть *навык* (*skill*) — папка с файлом `SKILL.md`. Как памятка для коллеги: открыл и сделал по шагам.

Где лежит:

- `.claude/skills/<имя>/SKILL.md` — навык проекта. Закоммить, и он будет у всей команды.
- `~/.claude/skills/<имя>/SKILL.md` — личный навык, во всех твоих проектах.

Имя папки становится командой: `/release-notes`.
:::

::: step example
Файл `.claude/skills/release-notes/SKILL.md`:

```markdown
---
description: Пишет заметки о релизе по коммитам с последнего git-тега. Используй, когда просят release notes или список изменений к релизу.
argument-hint: "[версия]"
---

Собери заметки о релизе версии $ARGUMENTS.

1. Посмотри коммиты с последнего тега: `git log $(git describe --tags --abbrev=0)..HEAD --oneline`.
2. Сгруппируй их: «Новое», «Исправления», «Прочее».
3. Пиши для пользователей: без хешей коммитов и имён файлов.
4. Непонятные коммиты вынеси в конец с пометкой «уточнить».
```

Вызов: `/release-notes 2.4.0`. Вместо `$ARGUMENTS` подставится `2.4.0`.
:::

::: step explain
Claude может и сам загрузить навык, без команды. В начале сессии он видит только *описание* (`description`) каждого навыка и по нему решает, подходит ли тот к задаче. Расплывчатое описание — и навык не сработает или сработает не там.

Два поля управляют вызовом:

- `disable-model-invocation: true` — только ты, через `/имя`. Для навыков с побочными эффектами, например деплоя.
- `user-invocable: false` — только Claude, в меню `/` навыка нет.
:::

::: exercise match_pairs
id: "p2.2.e2"
type: "match_pairs"
question: "Соедини поле или приём в SKILL.md с тем, что он делает."
pairs:
  - left: "`description`"
    right: "Объясняет Claude, что делает навык и когда его применять"
    why: "Это главное поле. По нему Claude сопоставляет твою задачу с навыками и решает, какой загрузить."
  - left: "`disable-model-invocation: true`"
    right: "Навык запускается только командой `/имя`"
    why: "Claude сам его не загрузит. Так делают для навыков с последствиями, например `/deploy`: ты сам решаешь, когда их запускать."
  - left: "`user-invocable: false`"
    right: "Навык пропадает из меню `/`, но Claude может применить его сам"
    why: "Подходит для справочных навыков, например стиля API: вызывать их руками незачем, а Claude пригодятся."
  - left: "`$ARGUMENTS` в тексте навыка"
    right: "Сюда подставляется то, что ты написал после команды"
    why: "В `/release-notes 2.4.0` это `2.4.0`. Один навык работает для любой версии."
hint: "Одно поле — для Claude, два — про то, кто может вызвать навык, и ещё один приём — про текст после команды."
:::

::: step explain
Теперь напиши свой навык. Возьми задачу, которую ты повторяешь в Claude Code: описание pull request, проверку кода по чек-листу команды, разбор упавших тестов.

Нужны шапка с `description` и инструкция по шагам. Navyk отправит навык на разбор Claude. Секреты и токены в навык не пиши.
:::

::: step summary
**Навык — папка с `SKILL.md`: шапка с описанием и инструкция. Проектный навык лежит в `.claude/skills/<имя>/`, вызывается `/имя`.**

Описание решает, сработает ли навык сам. Навыки с последствиями запускай только руками: `disable-model-invocation: true`.

Дальше: субагенты — помощники со своим контекстом.
:::
