::: step hook
Tom found an old blog post that installs Claude Code with npm, and another that uses some script. Which should he pick? And how can he tell it worked?

The official docs recommend the *native installer*: one command for your system. Let's go through it step by step.
:::

::: step explain
It all starts in the *terminal*, a window where you type text commands. On macOS it's the Terminal app; on Windows it's PowerShell.

The command for macOS, Linux and WSL (Linux inside Windows):

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

For Windows PowerShell:

```powershell
irm https://claude.ai/install.ps1 | iex
```

The installer doesn't show progress, so just wait.
:::

  - left: "Windows PowerShell"
    right: "irm https://claude.ai/install.ps1 | iex"
    why: "irm downloads the script and iex runs it. This pair only works in PowerShell."
  - left: "Windows CMD"
    right: "curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd"
    why: "In the classic CMD command prompt, the script is downloaded to a file, run and then deleted."
  - left: "macOS with the Homebrew package manager"
    right: "brew install --cask claude-code"
    why: "Also an official option, but this install doesn't update itself: every so often you need to run brew upgrade claude-code."
hint: "Look for clues in the commands themselves: .sh is for macOS and Linux, .ps1 for PowerShell, .cmd for CMD."
:::

::: step explain
Installed? Now check it. Open a **new** terminal window (the old one doesn't know about the new program) and run:

```bash
claude --version
```

If all is well, you'll see a version number and `(Claude Code)`.

If the terminal says `claude` can't be found, the install folder isn't on your *PATH* yet: the list of places where your system looks for programs. The fix is in the Troubleshoot installation section of the docs.
:::

::: step explain
One more thing for Windows: the docs recommend installing Git for Windows. That lets Claude Code use the familiar Bash shell. Without it, Claude Code works through PowerShell. You don't need it in WSL.

The native install updates itself in the background. Homebrew and WinGet installs don't; you update those by hand.
:::

::: step explain
All that's left is to sign in. Go to your project folder with `cd` and start Claude Code:

```bash
cd ~/projects/bakery-site
claude
```

On the first launch, a browser window opens so you can sign in. You'll need one of these: {{data.plans.p1_cli_accounts}}.

Your sign-in is saved, so you won't need to do it again. To switch accounts, use `/login` inside the session.
:::

::: step explain
A few everyday commands. You type them straight into the Claude Code input field:

- `/help` — list the available commands;
- `/login` — sign in or switch accounts;
- `/exit` — quit.

This one, though, goes in your regular terminal and continues the last conversation in that folder:

```bash
claude -c
```
:::

::: step summary
**Install: one native installer command → a new terminal window → `claude --version`.**

Then `cd` into your project folder, run `claude` and sign in through the browser. The native version updates itself.
