::: step hook
Tomek znalazł na starym blogu polecenie instalacji Claude Code przez npm, a na innym — przez jakiś skrypt. Które wybrać? I jak sprawdzić, że wszystko się udało?

Oficjalna dokumentacja zaleca *natywny instalator*: jedno polecenie dla twojego systemu. Przejdźmy przez to krok po kroku.
:::

::: step explain
Wszystko zaczyna się w *terminalu* — oknie, w którym wpisuje się polecenia tekstowe. Na macOS to aplikacja Terminal, na Windowsie — PowerShell.

Polecenie dla macOS, Linuksa i WSL (Linux wewnątrz Windowsa):

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

Dla Windows PowerShell:

```powershell
irm https://claude.ai/install.ps1 | iex
```

Instalator nie pokazuje postępu, po prostu poczekaj.
:::

    right: "curl -fsSL https://claude.ai/install.sh | bash"
    why: "To natywny instalator dla systemów uniksowych. Zalecany sposób: taka instalacja sama aktualizuje się w tle."
  - left: "Windows PowerShell"
    right: "irm https://claude.ai/install.ps1 | iex"
    why: "irm pobiera skrypt, iex go wykonuje. Ta para działa tylko w PowerShellu."
  - left: "Windows CMD"
    right: "curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd"
    why: "W zwykłym wierszu poleceń CMD skrypt jest pobierany do pliku, uruchamiany i usuwany."
  - left: "macOS z menedżerem pakietów Homebrew"
    right: "brew install --cask claude-code"
    why: "To też oficjalny sposób, ale taka instalacja sama się nie aktualizuje: co jakiś czas trzeba uruchomić brew upgrade claude-code."
hint: "Szukaj wskazówek w samych poleceniach: .sh — dla macOS i Linuksa, .ps1 — dla PowerShella, .cmd — dla CMD."
:::

::: step explain
Zainstalowane? Teraz sprawdź. Otwórz **nowe** okno terminala (stare nie wie o nowym programie) i wykonaj:

```bash
claude --version
```

Jeśli wszystko jest w porządku, pojawi się numer wersji i napis `(Claude Code)`.

Jeśli terminal pisze, że nie znaleziono `claude`, folderu instalacji nie ma jeszcze w *PATH* — liście miejsc, w których system szuka programów. Rozwiązanie znajdziesz w sekcji Troubleshoot installation w dokumentacji.
:::

::: step explain
Jeszcze o Windowsie: dokumentacja zaleca zainstalowanie Git for Windows. Wtedy Claude Code może korzystać ze znanej powłoki Bash. Bez niego będzie pracować przez PowerShell. W WSL nie jest to potrzebne.

Instalacja natywna aktualizuje się sama w tle. Instalacje przez Homebrew i WinGet — nie, te aktualizujesz ręcznie.
:::

::: step explain
Zostało zalogować się. Przejdź do folderu projektu poleceniem `cd` i uruchom Claude Code:

```bash
cd ~/projects/bakery-site
claude
```

Przy pierwszym uruchomieniu otworzy się przeglądarka do logowania. Wystarczy jedno z poniższych: {{data.plans.p1_cli_accounts}}.

Dane logowania są zapamiętywane, drugi raz nie trzeba się logować. Konto zmienisz poleceniem `/login` wewnątrz sesji.
:::

::: step explain
Kilka poleceń na co dzień. Wpisuje się je bezpośrednio w pole wiadomości Claude Code:

- `/help` — lista dostępnych poleceń;
- `/login` — zalogować się lub zmienić konto;
- `/exit` — wyjść.

A to polecenie wpisuje się w zwykłym terminalu i kontynuuje ostatnią rozmowę w tym folderze:

```bash
claude -c
```
:::

::: step summary
**Instalacja: jedno polecenie natywnego instalatora → nowe okno terminala → `claude --version`.**

Potem `cd` do folderu projektu, `claude` i logowanie przez przeglądarkę. Wersja natywna aktualizuje się sama.

Dalej: co robi Claude, gdy dajesz mu zadanie.
:::
