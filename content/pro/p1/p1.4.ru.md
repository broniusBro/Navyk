::: step hook
Ирина в каждой новой сессии пишет Claude одно и то же:

```prompt
Тесты запускай через npm run test:unit, не через npm test — тот идёт 20 минут. И ветки называй feature/номер-задачи.
```

Каждая сессия Claude Code начинается с чистого листа. Как сделать, чтобы он помнил правила проекта?
:::

::: step explain
Для этого есть *CLAUDE.md* — обычный текстовый файл в формате Markdown, который Claude читает в начале каждой сессии. Как памятка новому сотруднику на первый день.

Самый простой старт — команда в Claude Code:

```prompt
/init
```

Claude изучит проект и создаст файл с командами сборки, тестов и найденными правилами. Если файл уже есть, `/init` предложит улучшения, а не перезапишет его.
:::

::: step explain
Где может лежать CLAUDE.md:

- `./CLAUDE.md` или `./.claude/CLAUDE.md` в папке проекта — общие правила, хранятся в git вместе с кодом;
- `~/.claude/CLAUDE.md` в домашней папке — твои личные правила для всех проектов;
- `./CLAUDE.local.md` — твои личные правила для одного проекта. Добавь его в `.gitignore`, чтобы он не ушёл коллегам.
:::

  - left: "«Объясняй мне изменения по-русски» — во всех твоих проектах"
    right: "~/.claude/CLAUDE.md"
    why: "Личное предпочтение, общее для всех проектов. Коллегам оно не нужно."
  - left: "«Мой тестовый сервер — localhost:8081» — только в этом проекте и только у тебя"
    right: "./CLAUDE.local.md"
    why: "Личная деталь одного проекта. Файл не должен попасть в git, поэтому его добавляют в .gitignore."
hint: "Задай два вопроса: правило для всех или только для тебя? Для одного проекта или для всех?"
:::

::: step explain
Главная ошибка — раздутый CLAUDE.md. Когда в нём сотни строк, важные правила теряются, и Claude начинает их пропускать.

Для каждой строки спроси себя: **«Если убрать эту строку, Claude начнёт ошибаться?»** Если нет — удаляй.

Ориентир документации — меньше {{data.limits.p1_claude_md_lines}} на файл.
:::

    correct: false

  - text: "Описание каждого файла проекта по очереди"
    correct: false
    why: "Удалить. Claude сам прочитает нужные файлы. Пофайловое описание раздувает CLAUDE.md и быстро устаревает."
  - text: "Полная документация API на 300 строк"
    correct: false
    why: "Удалить. Лучше дать ссылку на документацию. CLAUDE.md загружается в каждую сессию целиком, длинные тексты съедают место."
hint: "Оставляй то, что Claude не узнает сам из кода. Удаляй очевидное и длинное."

::: step explain
Пиши правила так, чтобы их можно было проверить:

- «Отступ — 2 пробела» вместо «Форматируй код правильно»;
- «Перед коммитом запускай npm test» вместо «Проверяй изменения»;
- «Обработчики API лежат в src/api/handlers/» вместо «Держи файлы в порядке».

Пример короткого CLAUDE.md:

```markdown
# Команды
- Тесты: npm run test:unit (npm test запускает e2e, это 20 минут)

# Правила
- Ветки: feature/<номер-задачи>
```
:::

::: step explain
Важно знать две вещи.

CLAUDE.md — это совет, а не замок. Claude старается следовать ему, но для жёсткого запрета есть другие механизмы, о них — в следующих модулях.

Кроме CLAUDE.md, Claude ведёт *автопамять*: сам записывает заметки о твоих поправках и предпочтениях. Посмотреть и выключить её можно командой `/memory`.
:::

::: step explain
Теперь сам. Придумай небольшой проект: бот для записи, сайт кафе, скрипт для отчётов. Напиши для него короткий CLAUDE.md.

Оставь только то, без чего Claude будет ошибаться: команды, необычные правила, особенности окружения. Navyk отправит твой файл на разбор Claude.
