::: step hook
Ірина в кожній новій сесії пише Claude одне й те саме:

```prompt
Тести запускай через npm run test:unit, не через npm test — той триває 20 хвилин. І гілки називай feature/номер-завдання.
```

Кожна сесія Claude Code починається з чистого аркуша. Як зробити, щоб він пам'ятав правила проєкту?
:::

::: step explain
Для цього є *CLAUDE.md* — звичайний текстовий файл у форматі Markdown, який Claude читає на початку кожної сесії. Як пам'ятка новому співробітникові на перший день.

Найпростіший старт — команда в Claude Code:

```prompt
/init
```

Claude вивчить проєкт і створить файл із командами збирання, тестів і знайденими правилами. Якщо файл уже є, `/init` запропонує покращення, а не перезапише його.
:::

::: step explain
Де може лежати CLAUDE.md:

- `./CLAUDE.md` або `./.claude/CLAUDE.md` у теці проєкту — спільні правила, зберігаються в git разом із кодом;
- `~/.claude/CLAUDE.md` у домашній теці — твої особисті правила для всіх проєктів;
- `./CLAUDE.local.md` — твої особисті правила для одного проєкту. Додай його в `.gitignore`, щоб він не потрапив до колег.
:::

::: step explain
Головна помилка — роздутий CLAUDE.md. Коли в ньому сотні рядків, важливі правила губляться, і Claude починає їх пропускати.

Для кожного рядка запитай себе: **«Якщо прибрати цей рядок, Claude почне помилятися?»** Якщо ні — видаляй.

Орієнтир документації — менше ніж {{data.limits.p1_claude_md_lines}} на файл.
:::

::: step explain
Пиши правила так, щоб їх можна було перевірити:

- «Відступ — 2 пробіли» замість «Форматуй код правильно»;
- «Перед комітом запускай npm test» замість «Перевіряй зміни»;
- «Обробники API лежать у src/api/handlers/» замість «Тримай файли в порядку».

Приклад короткого CLAUDE.md:

```markdown
# Команди
- Тести: npm run test:unit (npm test запускає e2e, це 20 хвилин)

# Правила
- Гілки: feature/<номер-завдання>
```
:::

::: step explain
Важливо знати дві речі.

CLAUDE.md — це порада, а не замок. Claude намагається йому слідувати, але для жорсткої заборони є інші механізми, про них — у наступних модулях.

Крім CLAUDE.md, Claude веде *автопам'ять*: сам записує нотатки про твої поправки й уподобання. Переглянути й вимкнути її можна командою `/memory`.
:::

::: step explain
Тепер сам. Вигадай невеликий проєкт: бот для запису, сайт кав'ярні, скрипт для звітів. Напиши для нього короткий CLAUDE.md.

Залиш лише те, без чого Claude помилятиметься: команди, незвичні правила, особливості середовища. Navyk надішле твій файл на розбір Claude.
:::
