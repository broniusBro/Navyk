::: step hook
Piszesz do Claude Code jedno zdanie:

```prompt
fix the failing tests
```

I widzisz, jak sam uruchamia testy, czyta błędy, szuka plików, poprawia kod i znowu uruchamia testy. Nie mówiłeś mu, które pliki otworzyć ani jakie polecenia wykonać. Skąd wie, co robić?
:::

::: step explain
Claude pracuje w *pętli agenta*, która ma trzy fazy:

1. **Zbierz kontekst**: przeczytaj pliki, znajdź to, co potrzebne.
2. **Działaj**: poprawiaj kod, uruchamiaj polecenia.
3. **Sprawdź wynik**: uruchom testy, obejrzyj wynik.

Jeśli sprawdzenie nie przejdzie, pętla się powtarza. Każdy kolejny krok Claude wybiera na podstawie tego, czego dowiedział się w poprzednim.
:::

::: exercise order_steps
id: "p1.3.e1"
type: "order_steps"
question: "Jak Claude może wykonać „fix the failing tests”? Ułóż kroki we właściwej kolejności."
shuffle: true
items:
  - text: "Uruchomić testy, żeby zobaczyć, które nie przechodzą"
    why: "Najpierw fakty: co dokładnie jest zepsute. To faza „zbierz kontekst”."
  - text: "Przeczytać komunikaty o błędach"
    why: "Komunikat o błędzie podpowiada, gdzie szukać przyczyny."
  - text: "Znaleźć pliki związane z błędem"
    why: "Wyszukiwanie w projekcie: Claude sam znajduje potrzebne pliki, ty ich nie wskazywałeś."
  - text: "Przeczytać te pliki i zrozumieć kod"
    why: "Bez zrozumienia kodu poprawka będzie na ślepo."
  - text: "Poprawić pliki"
    why: "Faza „działaj”: dopiero teraz Claude zmienia kod."
  - text: "Ponownie uruchomić testy"
    why: "Faza „sprawdź”. Jeśli testy dalej nie przechodzą, pętla zrobi kolejne okrążenie."
hint: "Przykład pochodzi z dokumentacji: zaczyna się i kończy tym samym poleceniem."
:::

::: step explain
Co sprawia, że pętla jest możliwa? *Narzędzia*. Bez nich Claude może tylko pisać tekst. Z nimi działa.

Model Claude rozumuje i decyduje, co robić. Claude Code wokół niego daje mu narzędzia i pilnuje, co model widzi. Tę otoczkę nazywa się *obudową agenta* (ang. agentic harness).

Pięć grup narzędzi: praca z plikami, wyszukiwanie, wykonywanie poleceń, sieć i analiza kodu.
:::

:::

  - text: "Głównie samo zbieranie kontekstu: znaleźć i przeczytać odpowiedni kod"
    correct: true

  - text: "Wszystkie trzy fazy obowiązkowo, inaczej Claude nie odpowie"
    correct: false
    why: "Nie, fazy nie są obowiązkowe. Naprawa błędu przechodzi przez wszystkie trzy kilka razy, a pytanie — nie."
  - text: "Tylko działanie: Claude od razu przepisze liczenie dostawy"
    correct: false
    why: "Nie prosiłeś o żadne zmiany. Poprawka w odpowiedzi na pytanie byłaby błędem."
  - text: "Tylko sprawdzenie: Claude uruchomi testy"
    correct: false
    why: "Testy nie powiedzą, gdzie jest liczenie dostawy. Trzeba wyszukać i przeczytać kod."
hint: "Potrzebujesz odpowiedzi czy zmiany w kodzie?"
:::

::: step explain
Ty też jesteś częścią pętli. Jeśli widzisz, że Claude poszedł w złą stronę:

- naciśnij {{data.ui_paths.p1_esc}} i napisz, co jest nie tak;
- albo po prostu wpisz poprawkę i naciśnij Enter, nie zatrzymując go. Wiadomość trafi do kolejki, a Claude przeczyta ją po bieżącym kroku.

Nie trzeba zaczynać od nowa.
:::

  - text: "Nie zatrzymując Claude, wpisać tę samą poprawkę i nacisnąć Enter"
    correct: true

  - text: "Zamknąć terminal i zacząć nową sesję od zera"
    correct: false

  - text: "Poczekać do końca i po cichu poprawić wszystko ręcznie"
    correct: false

::: step explain
Ostatnia zasada z dokumentacji: *deleguj, a nie dyktuj*. Wyjaśnij zadanie jak rozgarniętemu koledze: co jest nie tak, gdzie szukać i po czym poznać, że jest gotowe. Które pliki czytać i jakie polecenia uruchamiać, Claude zdecyduje sam.

```prompt
Płatność nie działa u użytkowników z kartą po terminie ważności. Kod płatności jest w src/payments/. Znajdź przyczynę i napraw.
```
:::

question: "Popraw zadanie dla Claude Code: deleguj, a nie dyktuj. Podaj objaw, gdzie szukać i po czym poznać, że wszystko naprawione."

review:

Mocne zadanie: jasne, który formularz i jaki jest objaw (R1); jest kontekst — kiedy pojawia się błąd, gdzie leży kod (R2); wiadomo, co znaczy „naprawione”, np. test albo scenariusz sprawdzenia (R4); są granice: czego nie ruszać, bez zbędnych zmian (R9). Nie wymagaj wymieniania konkretnych poleceń i plików do przeczytania — lekcja uczy, że Claude wybierze je sam. Odbiorcy niekoniecznie są programistami."
  criteria: ["R1", "R2", "R4", "R9"]
  reference_prompt: |
    Formularz zapisów na stronie salonu nie wysyła się, jeśli w polu telefonu są spacje lub myślniki, np. „+48 601-234-567”: przycisk „Zapisz się” nic nie robi, a na ekranie nie ma błędu. Kod formularza jest w src/booking/. Znajdź przyczynę i napraw tak, żeby telefon był przyjmowany w każdym typowym zapisie. Napisz test na te warianty numeru i uruchom testy. Nie zmieniaj wyglądu formularza ani pozostałych pól.
  show_reference: true
  fallback_feedback:
    - "Czy wiadomo, który to formularz i co dokładnie z nim nie tak?"
    - "Czy napisałeś, kiedy pojawia się problem: przy jakich danych lub działaniach?"
    - "Czy wskazałeś, gdzie mniej więcej leży kod?"
    - "Czy jest sposób na sprawdzenie, że naprawione: test albo kroki?"
    - "Czy jest granica: czego nie ruszać?"

::: step summary
**Pętla agenta: zbierz kontekst → działaj → sprawdź, i tak w kółko.**

Model decyduje, narzędzia działają. Możesz się wtrącić w każdej chwili: {{data.ui_paths.p1_esc}} albo poprawka do kolejki. Dawaj zadanie jak koledze: objaw, gdzie szukać, po czym poznać, że gotowe.

Dalej: plik CLAUDE.md, żeby nie tłumaczyć w kółko tego samego.
:::
