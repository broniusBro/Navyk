::: step hook
You type one line into Claude Code:

```prompt
fix the failing tests
```

And you watch it run the tests, read the errors, search for files, edit the code and run the tests again, all by itself. You never told it which files to open or which commands to run. How does it know what to do?
:::

::: step explain
Claude works in an *agentic loop* with three phases:

1. **Gather context**: read files, find what's relevant.
2. **Take action**: edit code, run commands.
3. **Verify the result**: run the tests, look at the output.

If the check fails, the loop goes round again. Claude picks each next step based on what it learned in the previous one.
:::

::: exercise order_steps

shuffle: true
items:
  - text: "Run the tests to see which ones fail"
    why: "Facts first: what exactly is broken. This is the “gather context” phase."
  - text: "Read the error output"
    why: "The error message hints at where to look for the cause."
  - text: "Find the files related to the error"
    why: "A project-wide search: Claude finds the right files itself; you didn't point to them."
  - text: "Read those files and understand the code"
    why: "Without understanding the code, any fix is a guess."
  - text: "Fix the files"
    why: "The “take action” phase: only now does Claude change the code."
  - text: "Run the tests again"
    why: "The “verify” phase. If the tests still fail, the loop goes round again."
hint: "This example comes from the docs: it starts and ends with the same command."
:::

::: step explain
What makes the loop possible? *Tools*. Without them, Claude can only write text. With them, it can act.

The Claude model reasons and decides what to do. Claude Code wraps around it, providing the tools and managing what the model sees. This wrapper is called the *agentic harness*.

There are five groups of tools: file operations, search, running commands, web and code intelligence.
:::

::: step explain
You're part of the loop too. If you see Claude heading the wrong way:

- press {{data.ui_paths.p1_esc}} and say what's wrong;
- or just type your correction and press Enter without stopping it. The message is queued, and Claude reads it after the current step.

There's no need to start over.
:::

::: step explain
One last principle from the docs: *delegate, don't dictate*. Explain the task as you would to a capable colleague: what's wrong, where to look and how to tell when it's done. Claude will decide for itself which files to read and which commands to run.

```prompt
Checkout fails for users with expired cards. The payment code is in src/payments/. Investigate and fix it.
```
:::
