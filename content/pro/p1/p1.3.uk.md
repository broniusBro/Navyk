::: step hook
Ти пишеш Claude Code одну фразу:

```prompt
fix the failing tests
```

І бачиш, як він сам запускає тести, читає помилки, шукає файли, редагує код і знову запускає тести. Ти не казав йому, які файли відкрити й які команди виконати. Звідки він знає, що робити?
:::

::: step explain
Claude працює за *агентним циклом* із трьох фаз:

1. **Зібрати контекст**: прочитати файли, знайти потрібне.
2. **Діяти**: редагувати код, запускати команди.
3. **Перевірити результат**: запустити тести, подивитися вивід.

Якщо перевірка не пройшла, цикл повторюється. Кожен наступний крок Claude вибирає залежно від того, що дізнався на попередньому.
:::

::: step explain
Що робить цикл можливим? *Інструменти*. Без них Claude може лише писати текст. З ними він діє.

Модель Claude міркує і вирішує, що робити. Claude Code довкола неї дає інструменти й стежить, що бачить модель. Цю оболонку називають *агентною обв'язкою*.

П'ять груп інструментів: робота з файлами, пошук, виконання команд, веб і аналіз коду.
:::

::: step explain
Ти теж частина циклу. Якщо бачиш, що Claude пішов не туди:

- натисни {{data.ui_paths.p1_esc}} і напиши, що не так;
- або просто надрукуй поправку й натисни Enter, не зупиняючи його. Повідомлення стане в чергу, і Claude прочитає його після поточного кроку.

Починати заново не треба.
:::

::: step explain
Останній принцип із документації: *делегуй, а не диктуй*. Поясни завдання, як тямущому колезі: що не так, де шукати, як зрозуміти, що готово. Які файли читати й які команди запускати, Claude вирішить сам.

```prompt
Оплата ламається в користувачів із простроченою карткою. Код оплати в src/payments/. Розберися і виправ.
```
:::

::: step summary
**Агентний цикл: зібрати контекст → діяти → перевірити, і так по колу.**

Модель вирішує, інструменти діють. Ти можеш утрутитися будь-коли: {{data.ui_paths.p1_esc}} або поправка в чергу. Давай завдання, як колезі: симптом, де шукати, як зрозуміти, що готово.

Далі: файл CLAUDE.md, щоб не пояснювати одне й те саме щоразу.
:::
