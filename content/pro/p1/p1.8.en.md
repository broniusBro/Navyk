::: step hook
Two hours in one session. First Anna was fixing sign-in, then she asked about the README, then went back to sign-in and also discussed button colours.

Now Claude is getting confused: it's forgotten a rule she gave right at the start, and it keeps suggesting things that already didn't work. What went wrong?
:::

::: step explain
Claude has a *context window*: its working memory for the session. It holds the whole conversation, every file it has read and the output of every command.

The window fills up fast, and the fuller it gets, the more often Claude forgets early instructions and makes mistakes. You can see what's taking up space with `/context`.

Context is your most important resource, and it needs managing.
:::

::: step explain
Four tools:

- {{data.ui_paths.p1_esc}} — stop and redirect;
- `/clear` — a new conversation with an empty context, for a new task;
- `/compact` — condense the conversation into a summary, optionally with a focus;
- `/rewind` or {{data.ui_paths.p1_esc_twice}} — go back to an earlier point.

```prompt
/compact keep the list of changed files and the test command
```
:::

    right: "/compact"

  - left: "The last edit broke everything and you want the files back the way they were"
    right: "/rewind"
    why: "The rewind menu restores the code and, if needed, the conversation to the checkpoint you choose."
hint: "Stop, start fresh, condense or go back?"
:::

::: step explain
A *checkpoint* is a snapshot of your files taken before each of your prompts. Claude keeps {{data.limits.p1_checkpoints_kept}}.

In the `/rewind` menu, pick a prompt and an action:

- {{data.ui_paths.p1_rewind_both}};
- {{data.ui_paths.p1_rewind_conversation}};
- {{data.ui_paths.p1_rewind_code}};
- {{data.ui_paths.p1_rewind_summarize}}.

So you can try risky things with confidence: if it doesn't work out, rewind.
:::

::: step explain
But checkpoints have blind spots. They do **not** track:

- files changed by terminal commands: `rm`, `mv`, `cp`;
- edits you made yourself outside Claude Code;
- edits by most *subagents*, the helpers Claude launches;
- actions in external systems: databases, APIs, deployments.

For a real history of changes, you need git.
:::

::: step explain
Back to Anna. The docs call her situation “the kitchen sink session”: unrelated tasks got mixed up in one conversation.

And a second rule: **if you've corrected Claude more than twice on the same issue, the context is clogged with failed attempts.** Run `/clear` and write a new prompt that includes everything you've learned.
:::

::: step explain
One last bit of practice. You've corrected Claude three times and decided to start over with `/clear`.

Write a new opening prompt. Include everything you learned from the failed attempts so Claude doesn't make the same mistakes again. Navyk will send it to Claude for feedback.
:::

::: step summary
**Context is your most important resource. New task: `/clear`. Long session: `/compact`. Mistake happening right now: {{data.ui_paths.p1_esc}}.**

`/rewind` rolls back Claude's edits, but not terminal commands or external systems. Checkpoints don't replace git: commit anything important.
