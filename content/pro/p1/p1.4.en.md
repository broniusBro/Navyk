::: step hook
In every new session, Emma writes the same thing to Claude:

```prompt
Run tests with npm run test:unit, not npm test — that one takes 20 minutes. And name branches feature/ticket-number.
```

Every Claude Code session starts with a blank slate. How can she get it to remember the project's rules?
:::

::: step explain
That's what *CLAUDE.md* is for: a plain Markdown text file that Claude reads at the start of every session. Like a briefing sheet for a new colleague on their first day.

The easiest way to start is this command in Claude Code:

```prompt
/init
```

Claude explores the project and creates a file with the build and test commands and any rules it finds. If the file already exists, `/init` suggests improvements instead of overwriting it.
:::

::: step explain
Where CLAUDE.md can live:

- `./CLAUDE.md` or `./.claude/CLAUDE.md` in the project folder — shared rules, stored in git alongside the code;
- `~/.claude/CLAUDE.md` in your home folder — your personal rules for every project;
- `./CLAUDE.local.md` — your personal rules for one project. Add it to `.gitignore` so it doesn't end up with your colleagues.
:::

  - left: "“Explain your changes to me in plain English, no jargon” — in all your projects"
    right: "~/.claude/CLAUDE.md"
    why: "A personal preference that applies across all your projects. Your colleagues don't need it."
  - left: "“My test server is localhost:8081” — only in this project and only for you"
    right: "./CLAUDE.local.md"
    why: "A personal detail for one project. The file mustn't go into git, so it's added to .gitignore."
hint: "Ask two questions: is the rule for everyone or just you? For one project or all of them?"
:::

::: step explain
The biggest mistake is a bloated CLAUDE.md. When it runs to hundreds of lines, the important rules get lost and Claude starts skipping them.

For each line, ask yourself: **“If I remove this line, will Claude start making mistakes?”** If not, cut it.

The docs suggest keeping it under {{data.limits.p1_claude_md_lines}} per file.
:::

::: exercise multi_choice
id: "p1.4.e2"
type: "multi_choice"
question: "Which lines are worth keeping in CLAUDE.md? Select all."
options:
  - text: "“Build: make build-prod. Plain make only builds for development”"
    correct: true
    why: "Keep. Claude can't guess this command from the code, and getting it wrong wastes time."
  - text: "“Indent with 4 spaces, even though 2 is usual for this language”"
    correct: true
    why: "Keep. The rule differs from the default; without it, Claude will write out of habit."
  - text: "“The API_BASE_URL environment variable must be set before running”"
    correct: true
    why: "Keep. This environment quirk isn't visible in the code; without it, Claude will be left guessing why nothing works."
  - text: "“Write clean, readable code”"
    correct: false
    why: "Cut. It's obvious practice, and Claude aims for it anyway. The line changes nothing but takes up space."
  - text: "A description of every file in the project, one by one"
    correct: false
    why: "Cut. Claude will read the files it needs. File-by-file descriptions bloat CLAUDE.md and go out of date fast."
  - text: "300 lines of full API documentation"
    correct: false
    why: "Cut. Better to link to the docs. CLAUDE.md is loaded in full into every session, so long texts eat up space."
hint: "Keep what Claude can't work out from the code. Cut anything obvious or long."
:::

::: step explain
Write rules that can be checked:

- “Indent with 2 spaces” rather than “Format code properly”;
- “Run npm test before committing” rather than “Check your changes”;
- “API handlers live in src/api/handlers/” rather than “Keep files organised”.

An example of a short CLAUDE.md:

```markdown
# Commands
- Tests: npm run test:unit (npm test runs e2e, which takes 20 minutes)

# Rules
- Branches: feature/<ticket-number>
```
:::

:::

::: step explain
Two important things to know.

CLAUDE.md is advice, not a lock. Claude tries to follow it, but there are other mechanisms for hard blocks; we'll cover them in later modules.

Besides CLAUDE.md, Claude keeps an *auto memory*: it writes notes about your corrections and preferences by itself. You can view it and turn it off with `/memory`.
:::

  - text: "Add another 50 lines of detailed explanations"
    correct: false
    why: "The file gets even longer, and the rules get even more lost."
  - text: "Write every rule IN CAPITAL LETTERS"
    correct: false
    why: "The docs suggest emphasising only the one rule Claude keeps skipping. If everything is emphasised, nothing is."
  - text: "Delete CLAUDE.md altogether"
    correct: false
    why: "Then the useful rules go too. What's needed is a short file, not no file."
hint: "Why does one rule get lost among 600 lines?"
:::

::: step explain
Your turn. Think up a small project: a booking bot, a café website, a reporting script. Write a short CLAUDE.md for it.

Keep only what Claude would get wrong without: commands, unusual rules, environment quirks. Navyk will send your file to Claude for feedback.
:::
