::: step hook
Irena w każdej nowej sesji pisze do Claude to samo:

```prompt
Testy uruchamiaj przez npm run test:unit, nie przez npm test — tamto trwa 20 minut. I gałęzie nazywaj feature/numer-zadania.
```

Każda sesja Claude Code zaczyna się od czystej karty. Jak sprawić, żeby pamiętał zasady projektu?
:::

::: step explain
Do tego służy *CLAUDE.md* — zwykły plik tekstowy w formacie Markdown, który Claude czyta na początku każdej sesji. Jak ściągawka dla nowego pracownika na pierwszy dzień.

Najprostszy start to polecenie w Claude Code:

```prompt
/init
```

Claude przejrzy projekt i utworzy plik z poleceniami budowania, testów i znalezionymi zasadami. Jeśli plik już istnieje, `/init` zaproponuje ulepszenia, a nie nadpisze go.
:::

::: step explain
Gdzie może leżeć CLAUDE.md:

- `./CLAUDE.md` lub `./.claude/CLAUDE.md` w folderze projektu — wspólne zasady, przechowywane w gicie razem z kodem;
- `~/.claude/CLAUDE.md` w folderze domowym — twoje osobiste zasady dla wszystkich projektów;
- `./CLAUDE.local.md` — twoje osobiste zasady dla jednego projektu. Dodaj go do `.gitignore`, żeby nie trafił do kolegów.
:::

::: step explain
Największy błąd to rozdęty CLAUDE.md. Gdy ma setki wierszy, ważne zasady giną, a Claude zaczyna je pomijać.

Przy każdym wierszu zapytaj siebie: **„Jeśli usunę ten wiersz, czy Claude zacznie się mylić?”** Jeśli nie — usuwaj.

Dokumentacja radzi, żeby plik miał poniżej {{data.limits.p1_claude_md_lines}}.
:::

::: step explain
Pisz zasady tak, żeby dało się je sprawdzić:

- „Wcięcie — 2 spacje” zamiast „Formatuj kod poprawnie”;
- „Przed commitem uruchamiaj npm test” zamiast „Sprawdzaj zmiany”;
- „Handlery API leżą w src/api/handlers/” zamiast „Utrzymuj porządek w plikach”.

Przykład krótkiego CLAUDE.md:

```markdown
# Polecenia
- Testy: npm run test:unit (npm test uruchamia e2e, to 20 minut)

# Zasady
- Gałęzie: feature/<numer-zadania>
```
:::

::: step explain
Warto wiedzieć dwie rzeczy.

CLAUDE.md to rada, a nie zamek. Claude stara się go przestrzegać, ale do twardych zakazów są inne mechanizmy — o nich w kolejnych modułach.

Oprócz CLAUDE.md Claude prowadzi *automatyczną pamięć* (auto memory): sam zapisuje notatki o twoich poprawkach i preferencjach. Podejrzysz ją i wyłączysz poleceniem `/memory`.
:::

::: step explain
Teraz ty. Wymyśl niewielki projekt: bota do zapisów, stronę kawiarni, skrypt do raportów. Napisz dla niego krótki CLAUDE.md.

Zostaw tylko to, bez czego Claude będzie się mylić: polecenia, nietypowe zasady, specyfikę środowiska. Navyk wyśle twój plik do Claude do oceny.
:::
